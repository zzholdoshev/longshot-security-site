Longshot 2.18.1 — руководство и справочник функций

Обновлено 10 ноября 2026 г. для Longshot 2.18.1 (версии Firefox и Chrome) и его собственный прокси-сервер HTTP/HTTPS. Это заменяет общее руководство 2.11.1. Инструкции ниже описывают поставляемую реализацию, включая ее ограничения; старые примеры мостов не являются взаимозаменяемыми с этой версией.

Longshot — это инструментальная среда браузерного сеанса для авторизованной оценки веб-приложений. Он сочетает в себе обнаружение, собственный активный сканер JavaScript, ручные инструменты HTTP, импортированные шаблоны, обзор результатов и отчеты. Дополнительный браузерный мост позволяет внешним инструментам использовать выбранные значения сеанса Firefox при отправке собственных HTTP-запросов.

Полезный первый проход: откройте приложение → войдите в систему → запустите Longshot на этой вкладке → Подключитесь → подтвердите сеанс → найдите входные данные → выполните выбранные проверки → просмотрите доказательства.

Если приложение работает с деньгами или конфиденциальными данными, в том числе если его помог создать ИИ, закажите профессиональный аудит у команды по кибербезопасности. Сканирование расширением не заменяет проверку прав доступа, бизнес-логики и независимую оценку безопасности. Пустой список находок не доказывает, что приложение безопасно.

В этом документе объясняются команды; его обновление не устанавливает программное обеспечение, не регистрирует хост, не изменяет настройки браузера и не запускает какое-либо сканирование. Запускайте примеры только в соответствии с утвержденной целью оценки. Образец http://localhost:8080 — это пример локальной цели, а не встроенной службы Longshot.

Код написал ИИ. А кто найдёт уязвимости?

Представьте себе это: ваше приложение запускается, злоумышленник находит ошибку, а пользователь открывает свою учетную запись с нулевым балансом. Все их деньги — пропали.

Код выглядел убедительно. ИИ сказал, что это выглядело безопасным. Этого было недостаточно.

Ответы ИИ могут различаться. Модель способна пропустить уязвимость и при этом уверенно назвать код безопасным. Нужна независимая проверка — здесь пригодится Longshot.

Longshot превращает Firefox в инструмент безопасности для создаваемых вами веб-приложений. Выполняйте повторяющиеся проверки действительно работающего приложения, проверяйте доказательства HTTP и исследуйте слабые места, прежде чем ваши пользователи заплатят за это.

Поддерживается покрытие чеков Внедрение SQL/NoSQL, внедрение кода и шаблонов на стороне сервера, отраженные кандидаты XSS, обход пути/включение файлов, открытые перенаправления и внедрение CRLF/заголовка., с дополнительной проверкой DOM XSS в реальном времени. Обзор слабые заголовки безопасности, политики cookie и CORS, раскрытая конфигурация и раскрытие ошибок, с дополнительными проверками на наличие дальнейших классов атак.

Начните с вкладки браузера, которую вы уже используете. Сохраняйте активные файлы cookie, настраивайте проверку сеанса, восстанавливайте его после потери сеанса и систематизируйте настройки, историю и результаты каждой цели.

Поручайте задачи ИИ — и проверяйте результат. Подключите агента через MCP для проведения авторизованных проверок и изучения результатов. Используйте встроенный браузерный мост, чтобы подключить ZAP, sqlmap, curl, ffuf или wget к подключенному сеансу браузера без копирования значений файлов cookie вручную. Инструменты отправляют свои собственные HTTP-запросы и полезные данные; Переопределение файлов cookie браузера включено по умолчанию и может быть отключено.

Опытные пользователи могут импортировать совместимые CVE-шаблоны и коррелировать Обратные вызовы OAST с зондами, которые их вызвали. Просмотрите и запишите свои вердикты, а затем экспортируйте богатые доказательства Отчеты HTML, JSON, CSV или SARIF, с выводом на печать/PDF. Объясните выводы с помощью кинозритель, включая живой контекст страницы CSS/JavaScript, анимированные 3D-элементы, элементы управления паузой и полноэкранным режимом. Выберите яркую тему и настройте движение и звук в соответствии с вашим рабочим пространством.

Быстрое сканирование — одно предложение

Откройте свое приложение в Firefox, при необходимости войдите в систему, запустите Longshot на этой вкладке, нажмите «Подключиться», подтвердите настроенную проверку сеанса, затем выберите Spider + активные проверки → Начать сканирование и просмотрите результаты.

Короткое объявление

Приложение, написанное с ИИ, уже работает. Что могло остаться незамеченным? Longshot помогает искать инъекции, XSS и другие распространённые уязвимости в работающем приложении. Используйте текущую сессию браузера, подключайте агента через MCP и проверяйте выводы по собранным доказательствам. Код заслуживает ещё одной проверки.

Компактное описание

Проверка приложений, созданных с ИИ: текущая сессия браузера, AI/MCP, внешние HTTP-инструменты с настраиваемой подстановкой cookies, CVE/OAST, наглядные объяснения и отчёты.

  2. Проверяйте приложение в своей сессии. Живые файлы cookie, проверка и целевые доказательства.
  3. Код написал ИИ. А кто его проверил? Внесите предложения ИИ в проверяемый рабочий процесс по обеспечению безопасности.
  4. Ваши инструменты. Ваша вкладка. Ваша сессия. Браузерный мост для поддерживаемых локальных утилит HTTP.
  5. Находите уязвимости. Проверяйте доказательства. Расширенные совместимые шаблоны CVE и корреляция OAST.
  6. Доказательства убедительнее обещаний. Просматривайте и экспортируйте отчеты в рабочей области, которую вы можете настроить.
  7. Уверенность ИИ — ещё не гарантия безопасности. MCP проверяет ваше работающее приложение; доказательства, которые вы можете просмотреть.
  8. Сессия истекла? Войдите снова и продолжайте. Подтвердите, приостановите, снова войдите в систему и возобновите.

Примечания к публикации

История потери аккаунта является гипотетической, а не заявлением о реальном клиенте или гарантией того, что Longshot предотвратит финансовые потери. Расширение выполняет оценку, а не постоянную блокировку атак. Результаты требуют рассмотрения; В таблице покрытия поясняется ограниченная поддержка и пробелы, требующиеся только для ручного управления. Анализ DOM включает в себя индикаторы и поддерживаемые канареечные программы выполнения, а не универсальный охват эксплойтов DOM. Кинематографический эпизод объясняет доказательства; это не добавляет доказательств эксплуатации.

MCP и Browser Bridge требуют локальной настройки. Собственный прокси-сервер инструмента использует отдельный процесс Node/Python/mitmproxy, а для перехвата HTTPS требуется настройка доверия инструмента для центра сертификации адаптера. Это анализируемый транспорт HTTP, а не прозрачный для байтов необработанный TCP. Переопределение файлов cookie можно отключить; файл cookie браузера или пользовательский агент не гарантируют идентичность сети браузера или принятие WAF. Внешний ZAP остается установленным отдельно. Выполнение шаблона зависит от совместимости/времени выполнения; Для OAST требуется настроенный поставщик. Для проверки подлинности требуется значимая защищенная конечная точка/маркер. Целевые профили отдельных данных оценки; вкладка/контейнер предоставляет сеанс cookie.

Для приложений, обрабатывающих конфиденциальные данные или деньги, наймите команду по кибербезопасности и используйте Longshot как часть оценки. Используйте его только в тех приложениях, которыми вы владеете или имеете право тестировать.

Если вы повторно используете ранее созданные изображения кампании, пометьте их как композиции и используйте реальные текущие скриншоты везде, где требуется пользовательский интерфейс с точностью до пикселя. В этом руководстве приведены ссылки на скриншоты проверки версии 2.18.1 в разделе внешнего вида; он не включает новый пакет кампании из восьми изображений и не требует одобрения третьих лиц.

Установите версию Chrome

  1. Загрузите Хром-почтовый индекс по ссылкам на выпуск выше/ниже и извлеките его в папку, которую вы сохраняете.
  2. Открыть chrome://extensions, включить Режим разработчика, выберите Загрузить в распакованном виде, затем выберите извлеченную папку, содержащую manifest.json.
  3. Откройте авторизованное приложение, войдите в систему, запустите Longshot с этой вкладки и подключитесь.
  4. Держите вкладку рабочей среды открытой во время сканирования и встроенного сопряжения. Закрытие его прекращает работу двигателя; сохраненные доказательства сохраняются и восстанавливаются без повторного воспроизведения неопределенных запросов.
  5. Для запуска прокси-сервера собственного инструмента используйте точное происхождение, указанное Chrome, например chrome-extension://YOUR_INSTALLED_ID, а не Firefox moz-extension:// происхождение. Прокси использует реальные целевые URL-адреса; запись в файле хостов не требуется.

Регистрация Chrome Agent API/MCP

Из сохраненного полного исходного кода после установки закрепленной вспомогательной зависимости:

npm --prefix native-bridge ci --omit=dev
node bridge/bin/longshot-bridge install --browser chrome \
  --extension-id YOUR_INSTALLED_32_LETTER_ID \
  --port 8775 --data-dir /absolute/private/longshot-chrome
node bridge/bin/longshot-bridge mcp \
  --port 8775 --data-dir /absolute/private/longshot-chrome

Для использования хрома --browser chromium. Используйте фактический идентификатор в chrome://extensions; зарегистрируйтесь еще раз, если установка версии магазина дает другой идентификатор. Отдельный каталог портов/данных позволяет избежать конфликта с хостом Firefox. Этот API агента отличается от прокси-сервера инструмента HTTP (порты по умолчанию 8900/8901). Linux — это проверенная платформа с собственным хостом; Здесь реализована регистрация macOS, но она не тестировалась, и установщик для собственного хоста Windows не поставляется.

Подробная конфигурация браузерного моста также доступна в разделе расширения. Браузерный мост → Информация диалог. Полный README и новые документы по платформе и конфиденциальности написаны на английском языке; встроенный выбор языка пользовательского интерфейса не переводит целевые данные, полезные данные или исполняемые примеры.

XPI включает собственный адаптер в виде загружаемого архива. Он не может запустить произвольный процесс Node/Python или установить собственный хост исключительно через надстройки Firefox. Запуск прокси-сервера и регистрация API агента — это отдельные необязательные этапы локальной настройки.

Начало работы и целевые сеансы

Подключите правую вкладку

  1. Откройте авторизованную цель, например, в Firefox. http://localhost:8080.
  2. Войдите в систему с помощью предполагаемой тестовой учетной записи и выполните любую задачу браузера.
  3. Запустить Лонгшот с этой целевой вкладки. Держите вкладку приложения открытой.
  4. Проверьте целевой адрес и выберите Подключиться.
  5. Использование Начало работы в заголовке выделенного пошагового руководства, состоящего из восьми шагов. Его можно переиграть; он не запускает сканирование и не меняет настройки самостоятельно.
  6. Просматривайте типичные страницы приложений, чтобы Longshot мог наблюдать полезные маршруты и входные данные.

Целевой источник состоит из схемы, имени хоста и порта. http://localhost:8080, http://127.0.0.1:8080 и https://localhost:8080 имеют различное происхождение, даже если в конечном итоге они достигают одной и той же услуги. Подключитесь и используйте точный адрес, предназначенный для оценки. IP-адрес, наблюдаемый за именем хоста, не становится автоматически дополнительной авторизованной целью.

Профили и аккаунты

Цели разделяет историю, выводы, журнал запросов, обнаруженные конечные точки, обзоры и конфигурацию сканирования. При возврате к профилю восстанавливаются данные оценки, а не старый сеанс браузера с аутентификацией. Явные профили могут иметь общее происхождение.

Две обычные вкладки Firefox обычно используют файлы cookie. Используйте независимые контейнеры или отдельное частное хранилище файлов cookie для действительно разных тестовых идентификаторов. Переключение профилей не создает второй сеанс учетной записи. Для сравнения сеанса B требуется тот же целевой источник и отдельное хранилище.

Обнаружение света и целенаправленное активное сканирование

Первый проход: обнаружение и пассивный обзор

  1. Установить Запросов в секунду до 0,5–1, глубину сканирования до 1 и максимальное количество обнаруженных URL-адресов до 25–50.
  2. Уйти Максимальные выводы, Агрессивный, автофазировка CVE, OAST и собственное выполнение отключены.
  3. Установить Авто-фазз → Выкл.. Оставьте клики/прокрутку страниц и живые тесты DOM/тайминга/обратного вызова отключенными.
  4. Выберите пассивные группы обзора: заголовки, файлы cookie, раскрытие, формы, проверка источника/приемника DOM и CORS.
  5. Выберите Только паук и начнем.
  6. Осмотреть Карта сайта, История HTTP, API-проводник, Серверный стек и Выводы.

Spider следует за обнаруженными ссылками/формами в области видимости, не отправляя записи в формы. Он не знает всех скрытых конечных точек. Запросы GET по-прежнему могут иметь побочные эффекты, специфичные для приложения; «метод чтения» не устанавливает цель, свободную от побочных эффектов.

Второй проход: ограниченная активная оценка

  1. Держите Авто-фазз → Выкл. чтобы облегчить просмотр встроенных активных правил по отдельности.
  2. Выберите соответствующие активные проверки обзора, такие как внедрение SQL и отраженный XSS.
  3. Используйте небольшие ограничения, например 150 активных запросов, 10 активных URL-адресов и пять активных параметров.
  4. Выберите Только активные проверки повторно использовать текущую страницу и сохраненный инвентарь, или Паук + активные проверки обнаружить первым.
  5. Запустите, просмотрите все необходимые утверждения и наблюдайте за количеством активности и запросов.
  6. Проверьте запрос каждого результата, исходный уровень, данные повторного исследования/контроля, вердикт и достоверность.
  7. Открыть Проверки WSTG → Фактическое покрытие ввода чтобы увидеть выполненную, частичную и пропущенную работу.

Auto-fuzz Off не отключает активные проверки. SQLi/XSS/SSTI и другие специальные правила генерируют свои собственные зонды. И наоборот, отметка активного правила не приводит к отсутствующим входным данным и не заставляет запуск только Spider выполнять общую активную фазу.

Агрессивные варианты и одобрение запуска

Агрессивный включает явно одобренные методы/возможности; он не требует проведения каждой проверки и не гарантирует более веских доказательств.

  1. Сначала найдите входные данные и подтвердите аутентификацию.
  2. Включите только необходимые дополнительные параметры и разрешения на запись/загрузку/удаление.
  3. Сохранить параметры сканирования.
  4. Выберите Рассмотреть/одобрить следующий агрессивный запуск.
  5. Просмотрите цель, функции, разрешения на методы и бюджеты.
  6. Нажмите Одобрить следующий запуск. Это действие пользователя запрашивает все недостающие комбинированные разрешения Firefox и создает разрешение при следующем запуске.
  7. Запустите запуск с проверенной конфигурацией.

Грант является одноразовым, истекает через 30 минут и аннулируется соответствующими изменениями цели/конфигурации/запроса. Новое сканирование обычно требует нового разрешения. Допускается сохранение незавершенных вариантов; запуск или утверждение проверяет обязательные поля.

Firefox требует permissions.request() возникать непосредственно в результате реального действия пользователя. Изменение параметра не является основанием для предоставления произвольных разрешений в фоновом режиме. Если в разрешении отказано, просмотрите конкретную функцию, повторите попытку, нажав кнопку утверждения, или отключите эту функцию. Обычные запросы разрешений ОС/браузера остаются за пределами автоматизации расширений DOM.

Максимальные результаты – это широкая предустановка.

Эта предустановка включает множество этапов, включая расширенную проверку, сравнение OAST и сеанса B, а также расширяет несколько бюджетов. Это не переключатель «найти все». Он не создает учетную запись OAST, не заполняет URL-адрес поставщика/домен обратного вызова, не выбирает действительный сеанс B, не устанавливает Nuclei и не аутентифицирует недостающие роли.

Если при утверждении сообщается о пустых полях OAST или отсутствии сеанса B, настройте их или отключите эти параметры. Это не зависит от того, действителен ли целевой URL-адрес.

Два элемента управления вводом команд

Обзор → Индикаторы команд ОС позволяет проводить прямые проверки командного вывода, ориентированные на Unix. По умолчанию он выключен. Параметры сканирования → Командные зонды управляет дополнительным слепым маршрутом обратного вызова, когда OAST прослушивает. Один флажок не настраивает автоматически другой путь. Ознакомьтесь с требованиями авторизации для фактического запуска.

Ручной фаззер запросов

  1. Подключите цель и выберите URL-адрес с ограниченной областью действия. Относительные URL-адреса, такие как /search?q=apple принимаются против связанного источника.
  2. Введите существующее имя параметра запроса или выберите Использование рядом с обнаруженным входом.
  3. Выберите класс полезной нагрузки и значение мутации.
  4. Для Загруженные пользователем пользовательские полезные нагрузки, сначала включите подходящий пользовательский пакет.
  5. Выберите Запустить фаззер, затем проверьте базовый уровень, запрос, статус, продолжительность/сроки и доказательства.

Отсутствующий URL-адрес, параметр или пустой пользовательский набор создают конкретное сообщение проверки. Изменение ответа само по себе не указывает на ошибку впрыска. Регулирование сервера может остановить параметр, даже если он возникает в базовой версии.

Автоматическая фаззинг обнаруженных входных данных

Использование Предварительный просмотр обнаруженных входных данных сначала. Он считывает сохраненные ресурсы и сообщает о подходящих/пропущенных запросах без отправки пробных запросов. Для автоматического фаззинга не требуются поля URL/параметров ручного фаззера. Сначала просмотрите или Паук, если инвентарь пуст.

Выберите классы полезной нагрузки и выберите отдельный Авто-фазз кнопка. Включить обнаруженные тела запросов начинается и требует агрессивного плюс одобрения при следующем запуске. Формы, связанные с токеном, неподдерживаемые методы, недоступные тела и XML пропускаются этим автоматическим селектором ввода. Существующие исключения, ограничения на запросы и регулирование по-прежнему применяются.

Доступные флажки классов: SQLI, NOSQLI, CODE, XSS, SSTI, TRVERSAL, COMMAND, SSRF, REDIRECT, CRLF и CUSTOM. Новые значения по умолчанию включают SQLI, SSTI, TRVERSAL, REDIRECT и CRLF. Общий цикл пропускает SSRF; использовать Канарейки SSRF/обратные вызовы для его осуществленной проверки. CUSTOM использует введенные/включенные пользовательские значения и сообщает о различиях в ответах с низкой степенью достоверности, если только специальный сопоставитель не установит больше.

Почему здесь должна быть библиотека Probe

Библиотечные принадлежности значения полезной нагрузки и проверенные шаблоны; элементы управления фаззером выбирают куда и как их отправить. Он не заменяет URL-адрес/параметр, указанный вручную. Параметры общей библиотеки также влияют на активное сканирование и автоматические этапы после сохранения.

Загрузить списки букв

Принятые формы списков:

  • .txt: одно буквальное непустое значение в строке; пробелы и регистр сохранены.
  • .json: массив строк или объект, содержащий name, category и payloads.

  "category": "sqli",

Пакеты ориентированы на конкретную цель и изначально отключен. Проверьте предварительный просмотр и явно включите нужный пакет. Включенные загруженные пакеты требуют агрессивности и одобрения; загрузка сама по себе ничего не дает.

Ограничения: 256 КБ на файл полезных данных, 200 строк на пакет, 2000 символов на значение и не более 10 пакетов/500 значений/512 КБ конфигурации пакета на цель. Дублирующиеся строки внутри пакета удаляются. Существующие методы, область применения, бюджет и средства защиты от деструктивного SQL по-прежнему применяются.

Пакеты с категоризацией дополняют встроенные значения классов. Пакеты WAF также нуждаются в разумных вариациях и подходящих доказательствах фильтрации. Буквальная пользовательская полезная нагрузка не является средством сопоставления ожидаемого результата или исполняемым кодом расширения. Загрузка только номера CVE не может подтвердить этот CVE.

Перед загрузкой YAML/YML/JSON выберите категорию шаблонов CVE/Nuclei; максимальный размер файла шаблона составляет 2 МБ.   • Выполнить выбранное выполняет выбранные шаблоны напрямую и не требует автофазировки CVE.
  • CVE автофаза рассматривает допустимый импорт с тегами/идентификаторами CVE во время настроенного сканирования.
  • Авто-фазз генерирует общие значения; он не перезаписывает авторские полезные нагрузки или средства сопоставления CVE.
  • JSON, предназначенный только для рекомендаций, сопоставляет данные о продукте/версии. Он не изобретает работающий запрос на эксплойт.
  • Необработанные, сложные, кодовые, безголовые, файловые или не-HTTP-шаблоны могут требовать отдельного официального механизма и дополнительных грантов или оставаться заблокированными.

Импортируйте проверенные относительные вспомогательные пакеты с шаблонами, которые в них нуждаются. Недоступная встроенная среда выполнения, запрос, выходящий за рамки области применения, отсутствие утверждения или неподдерживаемая функция — это повод для проверки, а не успешный отрицательный тест.

Серверный стек и смарт-анализатор

Использование Обнаружение программного обеспечения для сбора поддерживаемых масштабных наблюдений. Просматривайте репрезентативные страницы и сохраняйте подходящие ответы, когда вам нужны вещественные доказательства. Затем выберите Анализ записанных доказательств для локальной пассивной корреляции до 200 последних сохраненных ответов. Сам анализатор не добавляет целевых запросов.

В представлении разделяются компоненты браузера, WAF/CDN/edge, веб-сервер/обратный прокси-сервер и сигналы приложения/среды выполнения. Заголовки, относящиеся к конкретному продукту, имена файлов cookie, структуры активов/начальной загрузки и текст ошибок могут повысить доверие. Тела страниц запроса исключаются из снятия отпечатков пальцев приложений. Общий баннер 403, баннер nginx или граница CDN не определяют, включено ли конкретное правило WAF.

Карты возможных конфигураций объясняют их доказательства и предлагаемую проверку. Это гипотезы: ответы браузера не могут точно установить исходный IP-адрес, частные подсети, настройки внутренней базы данных, завершение TLS, правила брандмауэра или списки доверия прокси. Множественные восходящие потоки и переписанные баннеры могут скрыть или неправильно идентифицировать слои.

Рекомендации WAF и обработка ставок

Примените консервативные рекомендации по сканированию явно включает пробы SQL сообщества, интеллектуальные варианты и адаптивную скорость, а также снижает настроенную скорость максимум до 0,5 запросов в секунду. Он не запускает сканирование и не предоставляет расширенные возможности.

Приемлемые проверки рассматривают не более трех альтернативных представлений в рамках существующих бюджетов. Заблокированная базовая линия пропускается. Проблемы с браузером требуют нормального разрешения браузера; обычное отрицание ACL не оправдывает бесконечные попытки обхода. Изменение «блокировать-разрешить» является свидетельством достижимости, а не доказательством уязвимости.

Повторяющиеся явные запросы могут вдвое снизить скорость обработки данных в памяти и вызвать ожидание продолжительностью не менее десяти секунд. HTTP 429 или 503 с Retry-After останавливает дальнейшие запланированные проверки; соблюдаются более длинные интервалы повтора-после. Ставка не увеличивается автоматически снова. Новые прогоны начинаются с настроенной скорости.

CVE-поиск

Поиск CVE в Интернете после разрешения запрашивает у NVD/OSV координаты поддерживаемого продукта/пакета. Запрос отправляет координаты, а не целевые URL-адреса, файлы cookie или содержимое страницы. Неизвестные версии, бэкпорты поставщиков и выводы об ограничении присутствия непроверенных пакетов. Введенные вручную записи npm/PyPI не подтверждают установку.

Отсутствие совпадений не означает отсутствие CVE. Матч является консультативным кандидатом; проверить предварительные условия и использовать Найдите шаблоны подтверждения найти подходящие импортные чеки. Эта кнопка фильтрует шаблоны, а не выполняет их.

Настройка и интерпретация OAST

OAST наблюдает за взаимодействиями DNS/HTTP, вызванными зондом, когда нормальный ответ не обнаруживает такого поведения. Longshot владеет ключами регистрации/корреляции; случайный предварительно сгенерированный обратный вызов от другого клиента не является взаимозаменяемым.

  1. Выберите Interactsh-совместимую службу, которую вы контролируете или которую вам разрешено использовать.
  2. Войти URL-адрес поставщика: полный базовый адрес API провайдера, обычно HTTPS. HTTP разрешен только для провайдеров обратной связи.
  3. Введите соответствие Домен обратного вызова без http://, порт или путь.
  4. Войти Токен провайдера только если этого требует провайдер.
  5. Установите TTL и интервал опроса; включите OAST плюс соответствующие параметры SSRF/XXE/Log4Shell/команды.
  6. Использование Проверка соединения OAST для проверки регистрации/опроса.
  7. Использование Тест обратного вызова OAST для отправки отдельной коррелированной канарейки из этого браузера.
  8. Сохраните, просмотрите и подтвердите фактическое сканирование. Проверьте точную корреляцию и протокол взаимодействия OAST.

Например, если вы используете соответствующую государственную услугу по адресу https://oast.pro, его база обратного вызова oast.pro. Это пример, а не гарантия доступности или требование использования этого поставщика. Самостоятельно размещаемому провайдеру необходим собственный правильно делегированный доступный домен, DNS/прослушиватели и TLS; HTTP-прослушиватель ноутбука сам по себе не является общедоступной службой обратного вызова. Следовать официальная настройка Interactsh.

Браузерный мост: собственный прокси-инструмент

Что он отправляет

Внешний инструмент генерирует запрос, включая полезные данные атаки, метод, тело и запрос. Собственный адаптер пересылает его через mitmproxy, применяя только настроенные изменения cookie/заголовка. Это делает нет попросите Firefox выполнить выборку от имени ZAP или другого инструмента.

При этом сохраняется собственная семантика HTTP и генерация полезной нагрузки инструмента, но не произвольные исходные байты передачи: mitmproxy анализирует/сериализует HTTP и устанавливает собственное исходящее TLS-соединение. Строка User-Agent браузера не делает собственный отпечаток TLS/сети идентичным Firefox.

Установите скачанный адаптер

  1. Открыть Браузерный мост. Только Собственный инструментальный прокси доступен в версии 2.18.1.
  2. Выберите Скачать родной адаптер и извлеките его.
  3. Введите извлеченный native-bridge каталог. Он содержит cli.js, bootstrap.py, config.json и прилагаемый Node ws зависимость.
  4. Установите Node.js 20+ и Python 3.12+, если они еще не доступны.
  5. Запустите одноразовую настройку Python:

sh cd /absolute/path/to/native-bridge python3 bootstrap.py

Это создает локальный .venv и устанавливает закрепленный mitmproxy 12.2.3. Для установки необходим доступ в Интернет. При обычном запуске код сканера или списки полезной нагрузки не загружаются.

  1. Используйте команду, показанную твой страница расширения:

sh node cli.js --config config.json \ --extension-origin moz-extension://YOUR-LONGSHOT-UUID

Замените заполнитель полным источником текущего расширения. Это не целевой веб-сайт, идентификатор дополнения или источник, скопированный из другого профиля Firefox.

  1. Оставьте терминал включенным. После того, как прослушиватель прокси-сервера готов, он печатает адрес прокси-сервера, порт управления, новый токен сопряжения/прокси-сервера и путь сертификата CA.

При разработке из исходного ZIP-файла вместо использования прилагаемого архива адаптера сначала установите закрепленную зависимость Node, если она отсутствует:

cd /absolute/path/to/longshot-source
npm --prefix native-bridge ci --omit=dev
cd native-bridge
python3 bootstrap.py

--mitmdump /absolute/path/to/mitmdump или LONGSHOT_MITMDUMP выбирает существующую среду выполнения. --data-dir /absolute/private/run-directory выбирает каталог CA/audit; по умолчанию run внутри родного адаптера. Ctrl+C останавливает адаптер.

Собственный прокси-сервер вручную не связан с регистрацией узла API агента. Это не нужно node bridge/bin/longshot-bridge install просто для прокси-завивки/ZAP. Linux/Firefox был протестирован в тестах интеграции выпусков; не делайте вывод о поддержке установщика собственных сообщений на другой платформе из этого руководства по пути запуска Node/Python.

Привязать выбранную вкладку

  1. Выберите авторизованного Вкладка «Цель» в браузерном мосту.
  2. Проверьте его отображаемое происхождение и хранилище файлов cookie. Использование Обновить вкладки если необходимо.
  3. Войти Порт управления 8901, если это не изменено в конфигурации адаптера.
  4. Вставить текущий Сопряжение/прокси-токен от работающего адаптера.
  5. Выберите Парный родной мост и проверьте статус готовности.
  6. Проверьте переключатели файлов cookie/заголовков перед маршрутизацией трафика инструмента.

Поле очищает токен после успешного сопряжения. При перезапуске создается новый токен: снова выполните сопряжение и обновите учетные данные прокси-сервера в каждом внешнем инструменте. Прокси-порт 8900 предназначен для инструментов; порт управления 8901 это для Firefox. Ни один из них не использует токен носителя API агента из порта 8765.

Фактические целевые URL-адреса и Bridge.invalid

Используйте реальный адрес, например http://localhost:8080/search?q=apple, в вашем инструменте. При тестировании HTTPS используйте настоящий https://... адрес. Собственный адрес прокси остается http://127.0.0.1:8900 потому что это локальный прослушиватель HTTP-прокси, в том числе для HTTPS CONNECT.

Нет /etc/hosts вход нужен. Старый bridge.invalid Адрес был псевдонимом, специфичным для адаптера, для сопоставления URL-адреса HTTP утилиты с выбранной целью загрузки браузера. Текущий собственный прокси-сервер поддерживает фактические целевые URL-адреса и HTTPS CONNECT, поэтому сопоставление не требуется.

localhost не является взаимозаменяемым псевдонимом для каждой цели: он называет локальный компьютер из сетевого окружения соответствующего процесса. Это правильно только тогда, когда цель действительно локальна в этом источнике. Другое имя хоста может выбирать другой виртуальный хост, политику использования файлов cookie или источник, даже если оба имени соответствуют одному и тому же IP-адресу.

Существующая устаревшая запись хостов не имеет отношения к новому рабочему процессу; не используйте его в URL-адресах инструментов. При подготовке этого руководства не вносилось никаких изменений в файл hosts.

HTTPS-доверие

Адаптер генерирует свой собственный локальный центр сертификации в выбранном каталоге данных, обычно:

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

Настройте конфигурация доверия оценки внешнего инструмента с путем к общедоступному сертификату, напечатанным при запуске. Не передавайте закрытый ключ и не предполагайте, что хранилище доверенных сертификатов системы/Firefox было изменено. Адаптер не устанавливает свой центр сертификации ни в одно хранилище доверенных сертификатов.

Для завитка:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

Заменить CURRENT_TOKEN и целевой путь/путь сертификата. Для локальной цели только с HTTP: --cacert ненужно. --noproxy '' гарантирует, что Curl не будет молча обходить прокси-сервер для цели обратной связи.

Существует две отдельные проверки TLS:

  • Клиент проверяет сертификат, предоставленный адаптером. Настройте доверие клиента с помощью ЦС адаптера.
  • Адаптер проверяет реальный вышестоящий сервер. tls.verifyUpstream по умолчанию правда. Клиент --cacert не предоставляет адаптеру частный центр сертификации.

Не рассматривайте отключение проверки как обычное исправление ошибок сертификата. Для собственного самоподписанного прибора: tls.verifyUpstream:false — явное исключение оценки в конфигурации адаптера, за которым следует перезапуск; это ослабляет эту отдельную проверку восходящего потока. См. поведение сертификата mitmproxy.

Переопределение файлов cookie и заголовков без повреждения зондов

Поведение файлов cookie по умолчанию

Используйте файлы cookie браузера и Сохранить обновления ответа Set-Cookie включены по умолчанию. User-Agent, Accept-Language и Authorization по умолчанию остаются под контролем инструмента.

Для собственного запроса Firefox выбирает применимые файлы cookie для URL-адреса из хранилища файлов cookie парной вкладки и соответствующего раздела. Другие контейнеры/частные магазины не объединяются. Правила домена/пути/безопасности/срока действия и порядок одноимённых путей остаются актуальными. Значения передаются собственному прокси-серверу, чтобы он мог создать исходящий заголовок Cookie; В отличие от удаленного пути выборки браузера, встроенный помощник обрабатывает секреты сеанса в памяти.

С cookies.mode:"replace", jar браузера является авторитетным, даже если он пуст. Файл cookie браузера, удаленный из jar, удаляется из последующих управляемых запросов. Явно защищенные имена и обнаруженные изменения инструментов имеют приоритет. С mode:"merge"файлы cookie несвязанных инструментов могут оставаться, пока обновляются имена, управляемые браузером.

Поля Response Set-Cookie применяются индивидуально к одному и тому же выбранному хранилищу с помощью API файлов cookie Firefox, включая поддерживаемые атрибуты Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition. Недействительные файлы cookie могут быть отклонены; проверить обнаруженные ошибки. Дополнительные настроенные источники не получают файлы cookie браузера или заголовки, производные от браузера.

Предположим, тесты ZAP session=ATTACK_PAYLOAD. Слепая замена этого значения действительным сеансом браузера может привести к стиранию теста. И наоборот, сохранение устаревшего файла cookie в каждом запросе может сделать сканирование с проверкой подлинности бесполезным.

По умолчанию Сохранять изменения файлов cookie/заголовка инструмента после первого запроса. записывает базовые показатели для каждого клиентского соединения/источника и сохраняет последующие изменения. Сначала отправьте обычный запрос на начальное число. Прокси-сервер не может достоверно определить намерение по первому запросу, и новое соединение создает новый базовый уровень. Эта эвристика не является полной защитой.

Для предсказуемого тестирования выберите один из этих механизмов:

  1. Отключите конкретное тестируемое переопределение файла cookie/заголовка.
  2. Добавьте имена файлов cookie в cookies.protectedNames или заголовки для headers.protectedNames.
  3. Отправьте выборочную аннотацию для каждого запроса:

http X-Longshot-Preserve: cookie:session, User-Agent, Authorization

При этом сохраняются именованные поля cookie/заголовка инструмента. cookie без имени сохраняет полный заголовок файла cookie инструмента.

  1. Обход всех переопределений на стороне запроса для этого запроса:

http X-Longshot-Override: off

Адаптер удаляет эти заголовки аннотаций перед пересылкой. Аутентификация прокси, область действия и ограничения по-прежнему применяются. Настройте аннотации в исходном инструменте; размещение их на целевой веб-странице не является механизмом настройки моста.

Например, сохранение session protected позволяет ZAP изменять его, в то время как помощник может продолжать обновлять несвязанный preferences печенье. Для исчерпывающего тестирования файлов cookie/авторизации/пользовательского агента отключение этих переопределений позволяет избежать зависимости от эвристики обнаружения изменений.

Авторизация браузера и другие заголовки

Авторизация в браузере включается через конфигурацию JSON. Он фиксируется из фактического запроса парной целевой вкладки только после включения поиска в браузере. Это не автоматическое считывание каждого токена в localStorage или памяти приложения. Прежде чем появится наблюдаемое значение, может потребоваться более поздний запрос браузера. Отключение авторизации браузера прекращает предоставление захваченного значения помощником.

Выбор User-Agent браузера или Accept-Language изменяет только эти поля HTTP. Он не запускает целевой JavaScript, не обновляет основной CSRF-токен, не воспроизводит TLS браузера и не гарантирует принятие WAF. Аутентификация с привязкой к IP/устройству и обновление OAuth по-прежнему требуют рабочего процесса приложения.

VHOST/Обработка хоста

Собственный помощник не заменяет внутренний псевдоним моста в поле Хост инструмента. Позвольте инструменту отправить значение хоста, необходимое для авторизованного теста виртуального хоста. Для HTTPS пункт назначения CONNECT остается авторизованным целевым объектом, в то время как заголовок Host инструмента может быть сохранен.

Изменение заголовка узла не предоставляет доступ к другому сетевому назначению. Обратный прокси-сервер может направить его в другое приложение; включите это поведение виртуального хоста в авторизацию оценки. Точные неверные байты заголовка и конфликтующие кадры находятся за пределами анализируемого прокси.

Аудит и конфиденциальность

Нативный трафик показывает метаданные запроса и измененные/защищенные имена полей. При аудите не учитываются секретные значения файлов cookie/заголовков, значения и тела запросов. Это не означает, что прокси-сервер никогда не обрабатывает секреты: он должен обрабатывать их для отправки аутентифицированного трафика. Внешние инструменты ведут свою собственную историю/результаты, которые могут содержать эти значения.

Храните частные токены конфигурации, ключи CA и каталоги данных в отчетах/исходных архивах. Загрузка конфигурации с пользовательскими значениями авторизации может создать файл, содержащий эти значения.

Внешние инструменты и фактическое сканирование ZAP

Начните с одного запроса

Подключите мост, затем проверьте реальную локальную цель:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  'http://localhost:8080/'

Используйте известный проверенный путь чтения для проверки поведения сеанса. 200 с общедоступной домашней страницы недостаточно. Убедитесь, что запрос появился в собственном трафике, выбранное хранилище файлов cookie правильно и инструмент получил ожидаемый контент. Не делайте вывод, что все последующие запросы используют прокси только потому, что этот.

ZAP исходящий прокси

  1. Установите/запустите ZAP отдельно и используйте сеанс ZAP для конкретного оценивания.
  2. В ЗАПах Параметры → Сеть → Подключение, включите исходящий HTTP-прокси.
  3. Установить хост 127.0.0.1, порт 8900 (или текущий настроенный порт прокси).
  4. Включить аутентификацию прокси: имя пользователя bridge, задайте пароль для текущего токена адаптера.
  5. Отключите собственный SOCKS-прокси ZAP для этой цепочки. Настройка SOCKS ZAP имеет приоритет над HTTP-прокси.
  6. Проверьте исключения HTTP-прокси, чтобы намеченная цель не была обойдена, особенно для локальной службы.
  7. При необходимости настройте ЦС адаптера в соответствующих настройках доверия/проверки TLS инструмента. Его местоположение печатается при запуске адаптера.
  8. Доступ к фактический целевой URL из ZAP и проверьте его историю и метаданные моста.
  9. Определите собственную цель/контекст ZAP, политику сканирования, исключения, проверки подлинности и умеренную частоту запросов. Запустите фактическое спайдерное/активное сканирование, как разрешено.
  10. Просмотрите выводы и освещение в ZAP. При намеренном фаззинге полей аутентификации cookie/заголовка используйте механизмы защиты/обхода, описанные выше.

Эта настройка принадлежит ZAP. исходящее соединение, а не его локальный прослушиватель входящего прокси-сервера браузера. Firefox не нужно перенастраивать для использования ZAP просто для передачи файлов cookie выбранной вкладки в эту цепочку.

ZAP генерирует свои реальные полезные данные активных правил; mitmproxy отправляет результирующие собственные запросы. Longshot меняет только поля запроса, в которых указано согласие. Это увеличивает полезный контекст сеанса внешнего инструмента, но не делает сканирование ни одним из инструментов комплексным. См. Настройки ZAP-соединения.

Пример стандартной библиотеки Linux Python для локальной цели, доступной только для чтения; он запрашивает токен вместо его жесткого кодирования и очищает обход прокси-сервера среды для этого процесса:

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

Проверьте запрос в Native трафике; другие платформы могут иметь дополнительные правила обхода системных прокси. Пример скручивания с явным --noproxy '' — это более простая проверка проверки маршрута с обратной связью. Клиентам HTTPS Python дополнительно требуется пакет контекста SSL/CA, который доверяет сертификату адаптера.

Пауза и ошибки

Приостановить собственные запросы блокирует новый исходный выход. Статусы аутентификации 401/419/440, HTTP 429, закрытие вкладок/изменение исходного кода или ограничения бюджета также могут приостановить работу. Возобновить после проверки вкладки возобновляется только после проверки состояния сопряжения.

Остановиться и отключиться завершает сопряжение браузера; он не завершает отдельно запущенный процесс Node. Используйте Ctrl+C в терминале, чтобы остановить этот процесс.

Запросы в полете могут быть завершены. Прокси-клиенты получают ошибки о заблокированной работе; адаптер не приостанавливает произвольные процессы инструментов и не воспроизводит их запросы. Проверьте, какие запросы были успешными, и используйте собственные элементы управления повтором/возобновлением инструмента. Перезапуск/повторное сопряжение изменяет токен и требует обновления средства аутентификации.

401/419/440 можно ожидать в преднамеренно отрицательных тестах аутентификации. При необходимости отрегулируйте session.pauseStatuses для этого просмотрено запуск и перезагрузка; адаптер не делает вывод о том, является ли каждая ошибка аутентификации намеренной проверкой.

Tor и луковая маршрутизация

Запросы Longshot на основе браузера следуют сети выбранного браузера. Собственный адаптер представляет собой другой процесс и не наследует настройки прокси-сервера Firefox/Tor Browser.

SOCKS/Tor — это выключено по умолчанию в родной конфигурации. Для авторизованной луковой оценки используйте явно настроенную существующую службу SOCKS с разрешением имени удаленного хоста, например, это переопределение, если это действительно ваш локальный прослушиватель Tor:

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

В этом примере Tor не запускается и не устанавливается наличие порта 9050. Выберите фактическую настроенную услугу; экземпляр Tor Browser может использовать другой прослушиватель. Перезапустите адаптер и выполните повторное сопряжение. HTTP(S) upstream.url и routing.socks5 являются взаимоисключающими.

Собственная оболочка разрешает имена хостов через SOCKS и не имеет прямого резервного копирования. Без явно настроенного маршрута восходящего потока/SOCKS прямые луковые адресаты отклоняются перед целевым DNS. URL-адрес SOCKS также может ссылаться на авторизованный туннель SSH или другую службу SOCKS5; по своей сути это не является доказательством маршрутизации Tor.

Совместное использование файлов cookie не делает выходной IP-адрес собственного маршрута или отпечаток TLS/браузера идентичным Firefox. Вызовы или привязка сеанса могут отклонить его. Проверьте маршрут и ожидаемую сессию самостоятельно.

Изолированные собственные ядра, запускаемые API-интерфейсом агента, отличаются: его встроенный ретранслятор не имеет маршрута Tor/SOCKS и блокирует луковые цели перед системным DNS. Используйте подходящие проверки на стороне браузера в предполагаемом браузере или отдельно настроенный внешний инструмент через собственный прокси-сервер. Не предполагайте, что флажок Nuclei наследует routing.socks5 из браузерного моста.

Зарегистрируйтесь и подключите родной хост

Из сохранившегося источник каталог, содержащий manifest.json и bridge/:

cd /absolute/path/to/longshot-source
node bridge/bin/longshot-bridge install

Это регистрирует longshot.bridge и средство запуска, ссылающееся на исходную папку и исполняемый файл Node. Держите оба на месте. Если кто-то из них переедет, зарегистрируйтесь еще раз.

Открыть Настройки → Подключение и настройка → Подключить родной мост и предоставьте Firefox разрешение на обмен собственными сообщениями. Хост может запустить свой демон автоматически. Если демон намеренно запускается вручную:

node bridge/bin/longshot-bridge serve

Избегайте размещения второго демона в том же каталоге порт/данные. Disconnect закрывает собственное соединение расширения; это не обязательно останавливает независимо запущенный демон.

Требуется Node.js 20+. Собственный MCP для обмена сообщениями не требует установки прокси-сервера Python/mitmproxy. Linux — это проверенная установка. Здесь предоставляется поддержка регистрации macOS, но не проверяется во время выполнения; в этом выпуске нет встроенного установщика Windows Firefox. Регистрация в WSL не регистрирует хост для Windows Firefox. Нативная изоляция Nuclei доступна только в Linux.

Служба по умолчанию: http://127.0.0.1:8765. Этот адрес локального хоста является API управления, не сканируемая цель. Токен/сокет по умолчанию имеет значение $XDG_DATA_HOME/longshot или ~/.local/share/longshot. Пользовательский --port и --data-dir должен совпадать при установке, обслуживании и mcp. Используйте короткий путь к данным Unix, поскольку его путь к сокету имеет ограничение в 100 байт.

REST-пример

Из той же исходной папки:

longshot_token_file="$(node bridge/bin/longshot-bridge token-path)"
longshot_api_token="$(cat "$longshot_token_file")"

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/health

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/targets

token-path команда печатает имя файла, а не токен. API использует аутентификацию носителя, в отличие от аутентификации по имени пользователя и паролю прокси. Он отклоняет клиенты без обратной связи и запросы Origin браузера и не предоставляет общий API CORS. Не публикуйте его через общедоступный обратный прокси-сервер.

Запускайте небольшое сканирование только после подключения/активации намеченной цели и проверки ее сохраненных параметров:

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  -H 'Content-Type: application/json' \
  --data '{"target_id":"PROFILE_ID","mode":"safe","budget":150}' \
  http://127.0.0.1:8765/v1/scans

Замените PROFILE_ID выбранным идентификатором профиля. safe карты только для Паука; он не сбрасывает все сохраненные дополнительные параметры и не действует как универсальное переопределение. Запуск асинхронный. Считайте возвращенный идентификатор запуска, затем проследите /v1/scans/RUN_ID, /eta, /findings или /report?format=html. POST /pause, /resume и /stop контролировать бег. Проконсультируйтесь с аутентифицированным /openapi.json для точных схем.

REST/JSON-RPC поддерживает профили, сканирования, выводы/отчеты, шаблоны, OAST и операции сеанса. /rpc содержит JSON-RPC; /mcp предлагает MCP HTTP с опциями stdio и SSE. Строки версии протокола/API службы могут сохранять более старые версии схемы; используйте манифест расширения для установленной версии пользовательского интерфейса.

API-проводник

Сначала подключитесь и просмотрите, затем выберите Проверить текущую страницу. Импортируйте предоставленный разработчиком OpenAPI JSON описание при наличии, до 2 МБ. Он читает локальный JSON, а не произвольную удаленную страницу или файл YAML. Ссылки на местные спецификации и доступные примеры запросов/значения по умолчанию могут предоставить конкретные поддерживаемые входные данные; отсутствующие значения/тела и неподдерживаемые конструкции оставляют пробелы.

Конечная точка — это адрес; операция — это адрес плюс метод. Входные данные запроса появляются после ?, входные данные пути в пути адреса и входные данные тела в отправленном контенте. Перечисленная операция является инвентаризацией, а не доказательством того, что текущая учетная запись может получить доступ к каждому объекту, к которому она обращается.

Использование Репитер рядом с поддерживаемой операцией GET/HEAD, чтобы подготовить запрос, не отправляя его. Просмотрите URL/метод/входные данные, а затем отправьте обдуманно. Операции записи только для инвентаризации по-прежнему требуют подготовки соответствующего запроса и получения разрешения на запись.

Повторитель и сравнение

Повторитель выполняет новый запрос с определенной областью, используя привязанный сеанс браузера. GET/HEAD/OPTIONS использует обычный маршрут. Методы записи, изменения тела и возможности разрушения/загрузки остаются предметом политики и одобрения. Управляемые значения Cookie/Authorization/Host не могут быть свободно заменены через редактор заголовков; используйте собственный маршрут внешнего инструмента для явно настроенных тестов заголовков и файлов cookie.

Следуйте перенаправлениям того же происхождения контролирует, проверяете ли вы само перенаправление или разрешенный окончательный ответ. Перенаправления за пределами области действия не являются полным разрешением. Сохраняйте тексты ответов, когда это необходимо для проверки, а затем выберите два сохраненных ответа в Сравнить. Функция сравнения не отправляет запросы; Динамический контент, состояние входа в систему, регулирование или страницы WAF могут объяснить разницу.

Интерпретация фактического покрытия пробега

Полная справочная карта WSTG включает автоматизированные подмножества, вспомогательную работу и ручную оценку. В Фактическое входное покрытие:

  • Завершено означает, что реализованное правило завершилось на этом вводе, а не то, что ввод защищен.
  • Частичный означает, что какая-то работа выполнялась, но ограничение, перерыв или другое условие не позволили завершить ее.
  • Пропущено означает, что правило/ввод не выполнен; проверить причину.

WAF, отсутствующая роль, недопустимый сеанс, скрытый/непосещаемый рабочий процесс, недоступное тело запроса, CSP или исчерпанный бюджет могут оставить уязвимые входные данные непроверенными. Сопряжение с собственным прокси-сервером не снимает эти ограничения со встроенного сканера. Обнаруженная версия CVE, отсутствующий заголовок или другой ответ не являются автоматически эксплойтом.

Версия 2.18.1 прошла 192 автоматических модульных/регрессионных теста, восемь реальных проверок Chrome и восемь реальных проверок Firefox, включая проверку CSP ZIP/YAML и собственный трафик ZAP по собственному устройству SQLite. Его официальные библиотеки браузера проверяются побайтно, а чистая перестройка исходного кода точно воспроизводит Firefox XPI. Эти тесты проверяют поведение именованной реализации; они не показывают обнаружение каждого вызова Juice Shop, WebGoat, bWAPP или NodeGoat. Внешний результат ZAP SQLi проверяет путь прокси, а не отзыв Longshot для всех уязвимостей.

Хранилище браузера и дополнительные файлы сеансов

Хранилище браузера остается активным независимо от любого локального моста. Он хранит историю каждого профиля, выводы, обзоры, инвентарь и варианты. Органы реагирования можно сохранить, приложив все усилия к редактированию; наблюдаемый в браузере трафик часто имеет метаданные без захваченного тела.

Для автоматической проверки файлов:

  1. Зарегистрироваться/подключиться API агента, а не только Browser Bridge.
  2. Открыть Настройки → Сеансы оценки → Инструкция.
  3. Введите абсолютный Папка сеанса на компьютере API агента.
  4. Включить Автоматически сохранять файлы сеанса и выбери Сохранить настройки сеанса.
  5. Использование Сохранить сеанс сейчас для немедленного КПП; обычные изменения также вызывают сохранение.
  6. Использование Экспортировать текущий сеанс / Импортировать файл сеанса для ручного перевода; Импорт вручную не требует наличия собственного хоста.

Файлы используют стабильные идентификаторы профилей с .longshot.json, что позволяет создавать явные профили для одного источника. Они представляют собой читаемые незашифрованные архивы оценок и могут содержать данные приложений, авторские шаблоны и сохраненные тела. Файлы cookie, управляемые браузером, токены поставщиков и гранты на выполнение исключаются.

Запись — это атомарные контрольные точки частного файла. Резкое завершение может восстановить только последнее завершенное сохранение. Восстановленные запущенные сканирования становятся прерванными. Если мост отключается, сохранение браузера продолжается, а сохранение файлов ожидает ожидания; неразрешенные включенные контрольные точки могут потребовать повторного подключения или отключения сохранения файлов перед переключением целей. Максимальный размер файла сессии — 256 МБ с явной ошибкой.

Экспорт архива оценок отличается от Скачать конфигурацию в браузерном мосту. Первый сохраняет доказательства/варианты оценки; последний сохраняет собственные настройки прокси.
