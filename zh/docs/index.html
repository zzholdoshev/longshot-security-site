Longshot 2.18.1 — 一般教程和控件参考

Longshot 更新于 2026 年 11 月 10 日 2.18.1 （Firefox 和 Chrome 版本）及其 原生 HTTP/HTTPS 工具代理。这取代了一般的 2.11.1 教程。下面的说明描述了已交付的实现，包括其限制；旧的桥示例不能与此版本互换。

Longshot 是一个用于授权 Web 应用程序评估的浏览器会话工作台。它结合了发现、自己的 JavaScript 主动扫描器、手动 HTTP 工具、导入的模板、结果审查和报告。可选的浏览器桥允许外部工具在发送自己的本机 HTTP 请求时使用选定的 Firefox 会话值。

有用的第一遍是： 打开应用程序 → 登录 → 从该选项卡启动 Longshot → 连接 → 验证会话 → 发现输入 → 运行选定的检查 → 审查证据.

对于处理敏感用户数据或资金的应用程序（包括人工智能构建或振动编码的应用程序），请聘请网络安全团队进行专业评估。扩展扫描不会取代授权测试、业务逻辑审查或独立的安全评估。空的结果列表不是安全证书。

本文档解释了命令；更新不会安装软件、注册主机、更改浏览器设置或运行任何扫描。仅针对您授权的评估目标运行示例。样品 http://localhost:8080 是本地目标示例，而不是内置的 Longshot 服务。

  1. 下载 铬邮政编码 从上面/下面的发布链接并将其解压到您保留的文件夹中。
  2. 打开 chrome://extensions, 启用 开发者模式，选择 装载已拆封的货物，然后选择解压后的文件夹，其中包含 manifest.json.

光发现和聚焦主动扫描

第一关：发现和被动审查

  1. 套装 每秒请求数 为 0.5–1，抓取深度为 1，最大发现 URL 为 25–50。
  2. 离开 最大发现, 好斗的、CVE 自动阶段、OAST 和本机执行关闭。
  3. 套装 自动模糊 → 关闭。关闭页面点击/滚动和实时 DOM/计时/回调测试。
  4. 选择被动概述组：标头、cookie、披露、表单、DOM 源/接收器审查和 CORS。
  5. 选择 仅蜘蛛 并开始。
  6. 检查 站点地图, HTTP 历史记录, API浏览器, 服务器堆栈 和 研究结果.

Spider 跟踪发现的范围内链接/表单，而不提交表单写入。它不知道每个隐藏端点。 GET 请求仍然会产生特定于应用程序的副作用； “阅读方法”并没有建立一个无副作用的目标。

第二遍：有界主动评估

  1. 保留 自动模糊 → 关闭 使内置的活动规则更易于单独查看。
  2. 选择相关的Overview主动检查，例如SQL注入和Reflected XSS。
  3. 使用较小的限制，例如 150 个活动请求、10 个活动 URL 和 5 个活动参数。
  4. 选择 仅主动检查 重用当前页面和保存的库存，或者 蜘蛛+主动检查 首先去发现。
  5. 开始，查看任何所需的批准，并观察活动和请求计数。
  6. 检查每个发现的要求、基线、重复探测/控制证据、结论和置信度。
  7. 打开 WSTG 检查 → 实际输入覆盖率 查看已完成、部分和跳过的工作。

自动模糊关闭不会关闭活动检查。 SQLi/XSS/SSTI 和其他专用规则生成自己的探针。相反，勾选活动规则不会提供缺失的输入或使仅蜘蛛运行执行通用活动阶段。

积极的选择和运行批准

积极主动启用明确批准的方法/功能；它并不执行每一次检查或保证更有力的证据。

  1. 首先发现输入并验证身份验证。
  2. 仅启用所需的高级选项和写入/上传/删除权限。
  3. 保存扫描选项。
  4. 选择 审查/批准下一次积极运行.
  5. 查看目标、功能、方法权限和预算。
  6. 点击 批准下次运行。此用户操作请求任何缺失的组合 Firefox 权限并创建下次运行授权。
  7. 使用审核后的配置开始运行。

该授权是一次性的，30 分钟后过期，并因相关目标/配置/请求设置更改而失效。新的扫描通常需要新的资助。允许保存未完成的选项；启动或批准验证必填字段。

火狐浏览器需要 permissions.request() 直接源自真实的用户操作。更改设置并不是在后台授予任意权限的理由。如果权限被拒绝，请查看确切的功能，通过批准按钮重试或禁用该功能。正常的操作系统/浏览器权限提示保留在扩展 DOM 自动化之外。

最大发现是一个广泛的预设

此预设开启了许多阶段，包括高级验证、OAST 和会话 B 比较，并扩大了多个预算。它不是一个“查找所有内容”的开关。它不会创建 OAST 帐户、填写提供程序 URL/回调域、选择有效的会话 B、安装 Nuclei 或验证缺失的角色。

如果批准报告为空 OAST 字段或缺少会话 B，请配置它们或关闭这些选项。这与目标 URL 是否有效无关。

使用 预览发现的输入 首先。它读取保存的库存并报告符合条件/跳过的请求，而无需发送探测。自动模糊测试不需要手动模糊器的 URL/参数字段。如果库存为空，请先浏览或蜘蛛。

WAF 建议和费率处理

应用保守的扫描建议 显式启用社区 SQL 探针、智能变体和自适应速率，并将配置的速率降低至最多 0.5 个请求/秒。它不会启动扫描或授予高级功能。

符合条件的调查最多考虑现有预算内的三种替代表示方式。跳过阻塞的基线。浏览器挑战需要正常的浏览器分辨率；普通的 ACL 拒绝并不能证明无休止的绕过尝试是合理的。从阻止到允许的更改是可达性证据，而不是漏洞证明。

重复的显式挑战可能会使内存速率减半并导致至少等待十秒。带 Retry-After 的 HTTP 429 或 503 会停止进一步计划的探测；考虑更长的重试间隔。该比率不会再次自动增加。新的运行以配置的速率开始。

OAST 设置和解释

OAST 当正常响应未揭示行为时，观察由探测引起的 DNS/HTTP 交互。 Longshot 拥有其注册/关联密钥；来自另一个客户端的随机预生成回调不可互换。

  1. 选择您控制或被允许使用的 Interactsh 兼容服务。
  2. 输入 提供商网址：提供者完整的API基地址，通常是HTTPS。仅允许环回提供程序使用 HTTP。
  3. 输入匹配的 回调域 没有 http://、端口或路径。
  4. 输入 提供商代币 仅当该提供商需要时。
  5. 设置TTL和轮询间隔；启用 OAST 以及相关的 SSRF/XXE/Log4Shell/命令选项。
  6. 使用 测试 OAST 连接 检查注册/投票。
  7. 使用 测试 OAST 回调 从此浏览器发送单独的相关金丝雀。
  8. 保存、审查并批准实际扫描。检查 OAST 交互中的精确相关性和协议。

例如，如果使用匹配的公共服务 https://oast.pro，其回调基数为 oast.pro。这是一个示例，不是可用性保证或使用该提供商的要求。自托管提供商需要自己正确委派的可访问域、DNS/侦听器和 TLS；单独的笔记本电脑 HTTP 侦听器并不是公共回调服务。关注 官方 Interactsh 设置.

观察 它建立了什么
连接测试通过 通过浏览器的路由进行注册和轮询
浏览器回调测试通过 该浏览器可以触发并检索其自己的相关交互
目标探针产生匹配相互作用 发生了相关的相互作用；注明来源并评估其含义
无回调 不确定：目标出口、提供者可达性、过期、过滤或不受支持的上下文可以解释它

DNS 解析可以来自中介/安全服务。单独的回调并不能证明任意内部访问、数据盗窃或代码执行。单独的隔离 Nuclei 引擎拥有自己的本机 Interactsh 注册；这些事件不是浏览器客户端的注册。

浏览器端 OAST 客户端不需要 Go、Node 或 Agent API。发布测试执行了官方服务器注册、加密 HTTP 回调检索和环回关联；他们没有建立公共提供商的可用性或目标服务器的出口。没有主机文件编辑是正常正确委派的 OAST 设置的一部分。

Browser Bridge：原生工具代理

它发送什么

外部工具生成请求，包括其攻击负载、方法、正文和查询。本机适配器通过 mitmproxy 转发它，仅应用配置的 cookie/标头更改。确实如此 不 要求 Firefox 代表 ZAP 或其他工具执行获取。

这保留了本机 HTTP 语义和工具的有效负载生成，但不保留任意原始线路字节：mitmproxy 解析/序列化 HTTP 并建立自己的出站 TLS 连接。浏览器用户代理字符串不会使本机 TLS/网络指纹与 Firefox 相同。

安装下载的适配器

  1. 打开 浏览器桥。仅 原生工具代理 在 2.18.1 中可用。
  2. 选择 下载本机适配器 并提取它。
  3. 输入提取的 native-bridge 目录。它包含 cli.js, bootstrap.py, config.json 和捆绑的节点 ws 依赖性。
  4. 如果 Node.js 20+ 和 Python 3.12+ 尚不可用，请安装它们。
  5. 运行一次性 Python 设置：

sh cd /absolute/path/to/native-bridge python3 bootstrap.py

这会创建一个本地 .venv 并安装固定的 mitmproxy 12.2.3。安装需要访问互联网。正常启动不会下载扫描器代码或有效负载列表。

  1. 使用显示的命令 你的 扩展页面：

sh node cli.js --config config.json \ --extension-origin moz-extension://YOUR-LONGSHOT-UUID

将占位符替换为完整的当前扩展原点。它不是目标网站、附加组件 ID 或从其他 Firefox 配置文件复制的源。

  1. 保持终端运行。代理侦听器准备就绪后，它会打印代理地址、控制端口、新配对/代理令牌和 CA 证书路径。

当从源 ZIP 开发而不是使用捆绑的适配器存档时，请首先安装其固定的 Node 依赖项（如果不存在）：

cd /absolute/path/to/longshot-source
npm --prefix native-bridge ci --omit=dev
cd native-bridge
python3 bootstrap.py

--mitmdump /absolute/path/to/mitmdump 或 LONGSHOT_MITMDUMP 选择现有的运行时。 --data-dir /absolute/private/run-directory 选择 CA/audit 目录；默认是 run 在本机适配器内。 Ctrl+C 停止适配器。

手动本机代理与代理 API 主机注册是分开的。它不需要 node bridge/bin/longshot-bridge install 仅代理curl/ZAP。 Linux/Firefox 进行了发布集成测试；不要从此手动 Node/Python 启动路径推断另一个平台上的本机消息安装程序支持。

配对选定的选项卡

  1. 选择授权的 目标选项卡 在浏览器桥中。
  2. 验证其显示的来源和 cookie 存储。使用 刷新选项卡 如果需要的话。
  3. 输入 控制端口 8901，除非在适配器配置中进行了更改。
  4. 粘贴当前的 配对/代理令牌 来自正在运行的适配器。
  5. 选择 配对本机桥 并验证就绪状态。
  6. 在路由工具流量之前检查 cookie/标头开关。

实际目标 URL 和bridge.invalid

使用真实地址，例如 http://localhost:8080/search?q=apple，在你的工具中。如果测试 HTTPS，请使用真实的 https://... 地址。代理自己的地址仍然存在 http://127.0.0.1:8900 因为这是本地 HTTP 代理侦听器，包括 HTTPS CONNECT。

否 /etc/hosts 需要输入。 旧的 bridge.invalid 地址是特定于适配器的别名，用于将实用程序的 HTTP URL 映射到选定的浏览器获取目标。当前的本机代理支持实际目标 URL 和 HTTPS CONNECT，因此不需要映射。

localhost 不是每个目标的可互换别名：它从相关进程的网络环境中命名本地计算机。仅当目标实际上位于该原点的本地时，它才是正确的。即使两个名称解析为相同的 IP，不同的主机名也可以选择不同的虚拟主机、cookie 策略或来源。

现有的过时主机条目与新工作流程无关；不要在工具 URL 中使用它。准备本教程时未对主机文件进行任何修改。

HTTPS 信任

适配器在选定的数据目录下生成自己的本地 CA，通常：

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

配置 外部工具的评估信任配置 启动时打印公共证书路径。不要共享私钥或假设系统/Firefox 信任存储已更改。适配器不会将其 CA 安装到任一信任存储中。

对于卷曲：

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

更换 CURRENT_TOKEN 和目标/证书路径。对于仅 HTTP 本地目标， --cacert 是不必要的。 --noproxy '' 确保curl不会默默地绕过环回目标的代理。

有两种不同的 TLS 检查：

  • 客户端验证适配器提供的证书。配置客户端对适配器 CA 的信任。
  • 适配器验证真实的上游服务器。 tls.verifyUpstream 默认为真。客户 --cacert 不向适配器提供私有原始 CA。

不要将禁用验证视为证书错误的正常修复。对于自有的自签名装置， tls.verifyUpstream:false 是适配器配置中的显式评估异常，然后重新启动；它削弱了单独的上游检查。参见 mitmproxy 证书行为.

标头名称不区分大小写。 Cookie 名称区分大小写。使用 JSON 布尔值 true/false，不是字符串。通用 headers.set 不能替换主机、Cookie、授权、框架或代理控制字段。使用专用的 cookie/授权选项和工具自己的主机值。

  "limits": {

}

没有通用的本机配置密钥可以刷新表单主体令牌或发明浏览器登录工作流程。

覆盖 Cookie 和标头而不损坏探针

默认 cookie 行为

使用浏览器cookie 和 保存响应 Set-Cookie 更新 默认情况下处于打开状态。默认情况下，用户代理、接受语言和授权仍然由工具控制。

对于本机请求，Firefox 从配对选项卡的 cookie 存储和匹配分区中为 URL 选择适用的 cookie。其他容器/私人商店不合并。域/路径/安全/过期规则和同名路径排序仍然相关。值被提供给本机代理，以便它可以构造传出的 Cookie 标头；与删除的浏览器获取路径不同，本机帮助程序因此在内存中处理会话机密。

与 cookies.mode:"replace"，浏览器 jar 是权威的，包括空时。从 jar 中删除的浏览器 cookie 将从以后的托管请求中删除。显式保护的名称和检测到的工具更改优先。与 mode:"merge"，在更新浏览器管理的名称时，可以保留不相关的工具 cookie。

响应 Set-Cookie 字段使用 Firefox 的 cookie API 单独应用于同一选定存储，包括支持的 Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition 属性。无效的cookie可以被拒绝；检查报告的错误。其他配置的源不会接收浏览器 cookie 或浏览器派生的标头。

请求和响应开关是独立的

请求 cookie 覆盖 响应同步 结果
开 开 使用 Firefox cookie 并通过响应 Set-Cookie 更新 jar
关闭 开 保留工具的请求cookie；目标响应仍然可以改变 Firefox 的 jar
开 关闭 使用火狐cookies；不要通过此助手写回响应 cookie
关闭 关闭 保持请求 cookie 由工具控制并且不同步响应

对于必须保持浏览器 jar 不变的 cookie 模糊测试或会话实验，请考虑这两个开关。每个请求的覆盖绕过会影响请求端的覆盖；它不会禁用独立的全局响应 cookie 同步设置。

保护包含攻击负载的字段

假设 ZAP 测试 session=ATTACK_PAYLOAD。盲目地用浏览器的有效会话替换该值可能会删除测试。相反，在每个请求中保留陈旧的 cookie 可能会使经过身份验证的扫描变得毫无用处。

默认 在第一次请求后保留工具 cookie/标头的更改 记录每个客户端连接/源的基线并保留后续更改。首先发送普通种子请求。代理无法可靠地推断第一个请求的意图，并且新连接会创建新基线。这种启发式方法并不是完全保护。

对于可预测的测试，请选择以下机制之一：

  1. 禁用正在测试的特定 cookie/标头覆盖。
  2. 将 cookie 名称添加到 cookies.protectedNames 或标题 headers.protectedNames.
  3. 发送选择性的每个请求注释：

http X-Longshot-Preserve: cookie:session, User-Agent, Authorization

这会保留该工具的命名 cookie/标头字段。 cookie 没有名称会保留完整的工具 Cookie 标头。

  1. 绕过该请求的所有请求端覆盖：

http X-Longshot-Override: off

适配器在转发之前剥离这些注释标头。代理身份验证、范围和限制仍然适用。在原始工具中配置注释；将它们放入目标网页不是桥接配置机制。

例如，保留 session protected 让 ZAP 改变它，而助手可以继续更新不相关的 preferences 饼干。对于详尽的 Cookie/授权/用户代理测试，禁用这些覆盖可以避免依赖于更改检测启发式方法。

浏览器授权和其他标头

浏览器授权是通过 JSON 配置选择加入的。仅在启用浏览器源之后，配对的目标选项卡才会从实际请求中捕获它。它不是本地存储或应用程序内存中每个令牌的自动读取器。在观察到的值存在之前，可能需要稍后的浏览器请求。关闭浏览器授权会停止帮助程序提供捕获的值。

选择浏览器用户代理或接受语言仅更改这些 HTTP 字段。它不运行目标 JavaScript、刷新正文 CSRF 令牌、重现浏览器 TLS 或保证 WAF 接受。 IP/设备绑定身份验证和 OAuth 刷新仍然需要其应用程序工作流程。

VHOST/主机处理

本机帮助程序不会将内部桥别名替换到工具的主机字段中。让工具发送授权虚拟主机测试所需的主机值。对于 HTTPS，CONNECT 目标仍然是授权目标，同时可以保留工具的主机标头。

更改主机标头不会授予对另一个网络目标的访问权限。反向代理可以将其路由到另一个应用程序；将该虚拟主机行为包含在评估的授权中。确切的格式错误的标头字节和冲突的帧位于此解析的代理之外。

审计和隐私

原生流量 显示请求元数据和已更改/受保护的字段名称。审核忽略 cookie/标头秘密值、查询值和主体。这并不意味着代理永远不会处理秘密：它必须处理它们才能发送经过身份验证的流量。外部工具维护自己的历史记录/结果，其中可以包含这些值。

将私有配置令牌、CA 密钥和数据目录保留在报告/源档案之外。下载具有自定义授权值的配置可以创建包含这些值的文件。

  1. 单独安装/启动 ZAP 并使用特定于评估的 ZAP 会话。
  2. 在ZAP的 选项 → 网络 → 连接，启用 传出 HTTP 代理.
  3. 设置主机 127.0.0.1, 端口 8900 （或当前配置的代理端口）。
  4. 启用代理身份验证：用户名 bridge，输入当前适配器令牌的密码。
  5. 为此链禁用 ZAP 自己的 SOCKS 代理。 ZAP 的 SOCKS 设置优先于其 HTTP 代理。
  6. 检查 HTTP 代理排除，以便不会绕过预期目标，尤其是对于本地服务。
  7. 需要时，在工具的适用 TLS 信任/验证设置中配置适配器 CA。它的位置在适配器启动时打印。
  8. 访问 实际目标网址 来自 ZAP 并验证其历史记录和桥接元数据。
  9. 定义 ZAP 自己的目标/上下文、扫描策略、排除、身份验证检查和适度的请求率。根据授权运行其实际的蜘蛛/主动扫描。

这个设置是ZAP的 传出连接，而不是其本地传入浏览器代理侦听器。 Firefox 无需重新配置即可仅使用 ZAP 向该链提供所选选项卡的 cookie。

ZAP 生成其真正的主动规则有效负载； mitmproxy 发送生成的本机请求。 Longshot 仅更改选择加入的请求字段。这增加了外部工具的可用会话上下文，但并不使任一工具的扫描变得全面。参见 ZAP 连接设置.

用于只读本地目标的 Linux Python 标准库示例；它会提示输入令牌而不是对其进行硬编码，并清除此过程的环境代理绕过：

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

验证Native流量中的请求；其他平台可以有额外的系统代理绕过规则。显式的卷曲示例 --noproxy '' 是更简单的环回路由验证检查。 HTTPS Python 客户端还需要信任适配器证书的 SSL 上下文/CA 捆绑包。

暂停和错误

暂停本机请求 阻止新的本机出口。身份验证状态 401/419/440、HTTP 429、选项卡关闭/离源更改或预算限制也可能暂停工作。 检查选项卡后恢复 仅在检查配对状态后才恢复。

停止并断开连接 结束浏览器配对；它不会终止单独启动的 Node 进程。在终端中使用 Ctrl+C 来停止该进程。

飞行中的请求可能会完成。代理客户端收到阻塞工作的错误；适配器不会暂停任意工具进程或重放其请求。检查哪些请求成功并使用该工具自己的重试/恢复控件。重新启动/重新配对会更改令牌并需要更新工具身份验证。

在故意的否定身份验证测试中可能会出现 401/419/440。如果需要，调整 session.pauseStatuses 对于经过审查的运行并重新启动；适配器不会推断每次身份验证失败是否都是有意探测。

Tor 和洋葱路由

基于浏览器的 Longshot 请求遵循所选浏览器的网络。本机适配器是一个不同的进程，不会继承 Firefox/Tor 浏览器代理设置。

袜子/托尔是 默认关闭 在本机配置中。对于授权洋葱评估，请使用具有远程主机名解析的显式配置的现有 SOCKS 服务，例如，如果这确实是您的本地 Tor 侦听器，则此覆盖：

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

此示例不会启动 Tor 或确定端口 9050 是否存在。选择实际配置的服务； Tor 浏览器实例可以使用不同的侦听器。重新启动适配器并重新配对。 HTTP(S) upstream.url 和 routing.socks5 是互斥的。

本机 shim 通过 SOCKS 解析主机名，并且没有静默直接回退。如果没有显式配置的上游/SOCKS 路由，直接洋葱目标将在目标 DNS 之前被拒绝。 SOCKS URL 还可以指授权的 SSH 隧道或其他 SOCKS5 服务；它并不是 Tor 路由的本质证明。

Cookie 共享不会使本机路由的退出 IP 或 TLS/浏览器指纹与 Firefox 相同。挑战或会话绑定可能会拒绝它。独立检查路线和预期会话。

Agent API 启动的隔离原生 Nuclei 则不同： 它的内置中继没有 Tor/SOCKS 路由，并且会在系统 DNS 之前阻止洋葱目标。在目标浏览器中使用符合条件的浏览器端检查，或通过本机代理单独配置的外部工具。不要假设 Nuclei 复选框继承 routing.socks5 来自浏览器桥。

中继器和比较

Repeater 使用绑定的浏览器会话发出新的范围请求。 GET/HEAD/OPTIONS 使用普通路由。写入方法、主体更改和破坏性/上传功能仍需遵守政策和批准。托管 Cookie/授权/主机值无法通过其标头编辑器自由替换；使用本机外部工具路由进行显式配置的标头/cookie 测试。

遵循同源重定向 controls whether you inspect the redirect itself or the allowed final response.范围外重定向不是一揽子授权。 Retain response bodies when needed for review, then choose two saved responses in 比较。比较不发送请求；动态内容、登录状态、限制或 WAF 页面可以解释差异。

A02 重复查询参数处理 仅指标 启用重复查询参数处理以进行重复的第一/最后顺序响应比较。 解析差异并不能证明 WAF 绕过、访问控制失败或代理/后端不一致。
A02 云权限、隐藏管理服务和后端配置 未涵盖 堆栈指纹和拓扑视图提供浏览器可见的假设。 无需云帐户访问、基础设施审计、服务器配置检查或详尽的内部网络发现。
A03 已知易受攻击的浏览器 JavaScript 依赖项 可选验证 使客户端库 SCA 能够将观察到的资产版本与小型捆绑咨询数据库进行比较。 仅版本/签名相关性；向后移植、可访问的易受攻击的代码、完整的依赖树和看不见的资产都未经过验证。
A03 服务器依赖项 CVE 和产品漏洞 依赖模板 CVE自动阶段需要符合条件的导入模板；仅运行他们编写的请求和匹配器。 Native Nuclei 需要其单独的引擎和批准。 仅指纹/咨询匹配就是候选。两个捆绑的社区启动器不提供通用的 CVE 覆盖。
A03 受损的软件包、CI/CD 和恶意供应链更新 未涵盖 依赖项名称或版本可以帮助单独的代码和构建审查。 没有 SBOM 完整性、存储库/构建审核、包真实性或签名链验证。
A04 HTTP 密码表单、HSTS 和不安全的资源引用 仅指标 被动检查使用 HTTP/GET 识别密码形式，不存在 HSTS 以及 HTTPS 标记引用的选定 HTTP 资源。 不全面的敏感数据发现；不证明静态数据暴露或评估所有传输行为。
A04 TLS 协议/密码、密钥管理和静态加密较弱 未涵盖 浏览器提供其正常的 TLS 连接。 没有密码/协议枚举、证书清单、加密设计审查、密码哈希审核或服务器端密钥访问。
A06 业务逻辑、支付/价格操纵和工作流程滥用 未涵盖 观察到的请求和中继器协助手动测试。 没有正确的价格、账户余额、业务规则、交易顺序或预期应用程序行为的模型。
A06 竞争条件和资源耗尽设计缺陷 未涵盖 请求限制和速率控制绑定扫描；速率限制响应是操作信号。 没有同步的竞赛安全带或故意的拒绝服务验证。
A07 弱 cookie/会话属性 仅指标 Cookie 审查报告缺少 Secure、HttpOnly 或显式 SameSite，并且在没有 Secure 的情况下 SameSite=None。 Cookie 的目的和浏览器默认设置很重要。不建立会话劫持、固定、注销失效或令牌熵。
A07 登录绕过、MFA、密码重置、暴力破解和帐户接管 未涵盖 注入检查可能会暴露登录缺陷的原因之一。会话验证器检查配置的登录是否仍然有效。 没有一般凭证攻击、MFA/重置工作流程测试、锁定审核或帐户接管验证。
A07 JWT、OAuth、OIDC 和 SAML 验证缺陷 未涵盖 实用程序可以在本地解码 JWT 以进行手动检查。 解码不是签名验证。没有一般的算法混淆、令牌伪造、重定向流或联合测试。

A08 不安全的反序列化 依赖模板 反序列化选项选择标记为反序列化的合格导入模板。检查他们的执行者和先决条件。 没有通用的对象格式发现、小工具链生成器或通用反序列化验证器。
A08 未签名的更新、伪造的应用程序数据和完整性控制 未涵盖 捕获的响应和解码的数据可以帮助手动分析。 没有应用程序信任模型、更新签名验证、数据签名审核或一般批量分配验证。
A09 缺少安全日志、警报、日志完整性和事件检测 未涵盖 Longshot 记录自己的扫描证据和本地请求日志。 扫描仪日志不会显示应用程序日志或警报是否正确；检查服务器/SIEM 证据并运行受监控的场景。
A10 异常响应导致信息泄露 仅指标 被动错误披露和主动注入控制可以注意到选定的堆栈跟踪和新引入的数据库错误。 只退回证据。一般错误或 HTTP 500 本身并不是经过验证的漏洞。
A10 故障开放行为、回滚故障和不安全异常恢复 未涵盖 状态/身体差异可以指导手动调查。 没有一般的故障注入、事务回滚断言、崩溃恢复或异常路径访问控制模型。
其他 HTTP 请求走私、格式错误的帧、缓存中毒和主机攻击 未涵盖 内置扫描仪使用浏览器网络并保护托管标头。 通过本机代理的外部工具是独立的。其解析的 HTTP 传输也不是字节透明的走私或自定义 TLS 引擎。
其他 WebSocket / SSE应用程序漏洞 仅指标 可选的有界通道测试捕获交换并报告选定的错误文本。 没有协议感知授权、消息模式模糊测试、跨站点 WebSocket 劫持或业务逻辑验证器。
其他 文件上传、GraphQL/SOAP 逻辑和不支持的二进制协议 未涵盖 发现的 HTTP 请求可以公开支持的标量输入以进行一般检查。 没有专用的上传执行、GraphQL 授权/复杂性、全面的 SOAP 或二进制协议扫描器。

解释实际运行覆盖率

完整的 WSTG 参考图包括自动化子集、辅助工作和手动评估。在 实际输入覆盖范围:

  • 已完成 意味着实施的规则在该输入上完成，而不是输入是安全的。
  • 部分 意味着某些工作已运行，但由于限制、中断或其他情况而无法完成。
  • 跳过 表示规则/输入未运行；检查原因。

WAF、缺少角色、无效会话、隐藏/未访问的工作流程、不可用的请求正文、CSP 或耗尽的预算可能会使易受攻击的输入未经测试。本机代理配对不会消除内置扫描程序的这些限制。观察到的 CVE 版本、缺少标头或不同的响应并不自动构成漏洞。

2.18.1 版通过了 192 项自动单元/回归测试、8 项真正的 Chrome 检查和 8 项真正的 Firefox 检查，包括针对自有 SQLite 固定装置的 ZIP/YAML CSP 验证和本机 ZAP 流量。其官方浏览器库经过逐字节验证，干净的源代码重建准确地再现了 Firefox XPI。这些测试验证命名的实现行为；它们没有显示对每个 Juice Shop、WebGoat、bWAPP 或 NodeGoat 挑战的检测。外部 ZAP SQLi 结果验证代理路径，而不是 Longshot 对所有漏洞的召回。

浏览器存储和可选会话文件

浏览器存储保持活动状态，独立于任一本地桥。它保留每个配置文件的历史记录、调查结果、评论、库存和选项。可以通过尽力编辑来保留响应主体；浏览器观察到的流量通常具有没有捕获主体的元数据。

对于自动文件检查点：

  1. 注册/连接 代理接口，不仅仅是浏览器桥。
  2. 打开 设置 → 评估课程 → 说明.
  3. 输入绝对值 会话文件夹 在代理 API 计算机上。
  4. 启用 自动保存会话文件 并选择 保存会话设置.
  5. 使用 立即保存会话 立即检查站；正常更改也会触发保存。
  6. 使用 导出当前会话 / 导入会话文件 用于手动传输；手动导入不需要本机主机。

文件使用稳定的配置文件 ID .longshot.json，允许一个来源的显式配置文件。它们是可读的、未加密的评估档案，可以包含应用程序数据、编写的模板和保留的正文。浏览器管理的 cookie、提供商令牌和执行授权不包括在内。

写入是原子私有文件检查点。突然终止只能恢复最后完成的保存。恢复的运行扫描被中断。如果网桥断开，浏览器存储继续，文件保存等待；未解析的启用检查点可能需要在切换目标之前重新连接或禁用文件保存。最大会话文件大小为 256 MB，有明确错误。

评估档案导出不同于 下载配置 在浏览器桥中。前者保存评估证据/选项；后者保存本机代理设置。
