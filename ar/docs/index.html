Longshot 2.18.1 — البرنامج التعليمي العام ومرجع التحكم

تم التحديث في 10 نوفمبر 2026 لـ Longshot 2.18.1 (إصدارات Firefox وChrome) و وكيل أداة HTTP/HTTPS الأصلي. يحل هذا محل البرنامج التعليمي العام 2.11.1. تصف الإرشادات أدناه التنفيذ الذي تم شحنه، بما في ذلك حدوده؛ أمثلة الجسر الأقدم غير قابلة للتبديل مع هذا الإصدار.

Longshot عبارة عن منصة عمل لجلسة المتصفح لتقييم تطبيقات الويب المعتمدة. فهو يجمع بين الاكتشاف وماسح جافا سكريبت النشط الخاص به وأدوات HTTP اليدوية والقوالب المستوردة ومراجعة النتائج والتقارير. يتيح جسر المتصفح الاختياري للأدوات الخارجية استخدام قيم جلسة Firefox المحددة أثناء إرسال طلبات HTTP الأصلية الخاصة بها.

التمريرة الأولى المفيدة هي: افتح التطبيق ← تسجيل الدخول ← تشغيل Longshot من علامة التبويب تلك ← الاتصال ← التحقق من صحة الجلسة ← اكتشاف المدخلات ← تشغيل عمليات التحقق المحددة ← مراجعة الأدلة.

بالنسبة إلى تطبيق يتعامل مع بيانات المستخدم الحساسة أو أمواله، بما في ذلك التطبيق المبني بالذكاء الاصطناعي أو المشفر، قم بتعيين فريق للأمن السيبراني لإجراء تقييم احترافي. لا يحل فحص الإضافات محل اختبار الترخيص أو مراجعة منطق الأعمال أو تقييم الأمان المستقل. قائمة النتائج الفارغة ليست شهادة أمان.

يشرح هذا المستند الأوامر؛ تحديثه لا يؤدي إلى تثبيت البرنامج أو تسجيل مضيف أو تغيير إعدادات المتصفح أو إجراء أي عمليات فحص. قم بتشغيل الأمثلة فقط مقابل هدف التقييم المعتمد الخاص بك. العينة http://localhost:8080 هو مثال على الهدف المحلي، وليس خدمة Longshot المضمنة.

يقوم Longshot بتحويل Firefox إلى منصة عمل أمنية لتطبيقات الويب التي تنشئها. قم بإجراء عمليات فحص متكررة على التطبيق الذي يتم تشغيله فعليًا، وافحص أدلة HTTP، وتحقق من نقاط الضعف قبل أن يدفع المستخدمون الثمن.

غطاء الشيكات مدعوم حقن SQL/NoSQL، وحقن التعليمات البرمجية والقالب من جانب الخادم، ومرشحات XSS المنعكسة، واجتياز المسار/تضمين الملف، وعمليات إعادة التوجيه المفتوحة، وحقن CRLF/الرأس، مع التحقق المباشر الاختياري من DOM XSS. مراجعة رؤوس الأمان الضعيفة وسياسات ملفات تعريف الارتباط وCORS والتكوين المكشوف والكشف عن الأخطاء، مع عمليات فحص اختيارية لمزيد من فئات الهجوم.

ابدأ من علامة تبويب المتصفح التي تستخدمها بالفعل. احتفظ بملفات تعريف الارتباط المباشرة، وقم بتكوين التحقق من صحة الجلسة، والتعافي بعد فقدان الجلسة، وحافظ على تنظيم إعدادات كل هدف وسجله ونتائجه.

قم بتشغيل الذكاء الاصطناعي الخاص بك، ثم تحقق من عمله. قم بتوصيل الوكيل من خلال MCP لإجراء الفحوصات المعتمدة وفحص النتائج. استخدم جسر المتصفح الأصلي لإحضار ZAP أو sqlmap أو curl أو ffuf أو wget إلى جلسة المتصفح المتصلة دون نسخ قيم ملفات تعريف الارتباط يدويًا. ترسل الأدوات طلبات HTTP وحمولاتها الخاصة؛ يتم تشغيل تجاوزات ملفات تعريف الارتباط للمتصفح افتراضيًا ويمكن إيقاف تشغيلها.

يمكن للمستخدمين المتقدمين استيراد متوافق قوالب مكافحة التطرف العنيف وترتبط عمليات الاسترجاعات OAST مع المجسات التي تسببت فيها. راجع أحكامك وسجلها، ثم قم بتصدير الأدلة الغنية بها تقارير HTML أو JSON أو CSV أو SARIF، مع إخراج الطباعة/PDF. شرح النتائج مع عارض سيماتيك، بما في ذلك سياق صفحة CSS/JavaScript المباشرة، والعناصر المتحركة ثلاثية الأبعاد، وعناصر التحكم في الإيقاف المؤقت وملء الشاشة. اختر سمة واضحة وقم بتخصيص الحركة والصوت لتناسب مساحة العمل الخاصة بك.

ملاحظات النشر

قصة خسارة الحساب هي قصة افتراضية، وليست ادعاء بشأن عميل حقيقي أو ضمان بأن Longshot يمنع الخسارة المالية. يقوم الملحق بإجراء التقييمات، وليس حظر الهجوم المستمر. النتائج تتطلب المراجعة. يشرح جدول التغطية الدعم المحدود والفجوات اليدوية فقط. يتضمن تحليل DOM المؤشرات وعناصر التنفيذ المدعومة، وليس تغطية استغلال DOM الشاملة. التسلسل السينمائي يوضح الأدلة؛ لا يضيف دليل الاستغلال.

يحتاج MCP وBrowser Bridge إلى الإعداد المحلي. يستخدم وكيل الأداة الأصلية عملية Node/Python/mitmproxy منفصلة، ​​ويتطلب اعتراض HTTPS تكوين ثقة الأداة للمحول CA. يتم تحليل نقل HTTP، وليس TCP الخام الشفاف للبايت. يمكن تعطيل تجاوزات ملفات تعريف الارتباط؛ لا يضمن ملف تعريف ارتباط المتصفح أو وكيل المستخدم شبكة متطابقة للمتصفح أو قبول WAF. يظل ZAP الخارجي مثبتًا بشكل منفصل. يعتمد تنفيذ القالب على التوافق/أوقات التشغيل؛ يتطلب OAST موفرًا تم تكوينه. يحتاج التحقق من صحة المصادقة إلى نقطة نهاية/علامة محمية ذات معنى. ملفات تعريف الهدف منفصلة عن بيانات التقييم؛ توفر علامة التبويب/الحاوية جلسة ملفات تعريف الارتباط.

بالنسبة للتطبيقات التي تتعامل مع البيانات الحساسة أو الأموال، قم بتعيين فريق للأمن السيبراني واستخدم Longshot كجزء من التقييم. استخدمه فقط على التطبيقات التي تمتلكها أو المرخص لها باختبارها.

في حالة إعادة استخدام صور الحملة التي تم إنشاؤها مسبقًا، قم بتسميتها على أنها تركيبات واستخدم لقطات الشاشة الحالية الحقيقية حيثما تكون واجهة المستخدم الدقيقة مطلوبة. يربط هذا البرنامج التعليمي لقطات الشاشة الفعلية للتحقق من صحة الإصدار 2.18.1 في قسم المظهر؛ ولا تتضمن حزمة حملة جديدة مكونة من ثماني صور أو تطالب بتأييد طرف ثالث.

قم بتثبيت إصدار Chrome

  1. قم بتنزيل كروم الرمز البريدي من روابط الإصدار أعلاه/أدناه واستخرجها إلى مجلد تحتفظ به.
  2. مفتوح chrome://extensions، تمكين وضع المطور، حدد تحميل تفكيكها، ثم اختر المجلد المستخرج الذي يحتوي على manifest.json.
  3. افتح تطبيقك المعتمد، وقم بتسجيل الدخول، ثم قم بتشغيل Longshot من علامة التبويب تلك، ثم قم بالاتصال.
  4. أبقِ علامة تبويب طاولة العمل مفتوحة أثناء المسح والاقتران الأصلي. إغلاقه ينهي عمل المحرك المباشر. تبقى الأدلة المحفوظة ويتم استعادتها دون إعادة تشغيل الطلبات غير المؤكدة.
  5. لبدء تشغيل وكيل الأداة الأصلية، استخدم الأصل الدقيق الذي يعرضه Chrome، مثل chrome-extension://YOUR_INSTALLED_ID، بدلاً من فايرفوكس moz-extension:// أصل. يستخدم الوكيل عناوين URL مستهدفة حقيقية؛ ليست هناك حاجة لإدخال ملف المضيفين.

تسجيل Chrome Agent API / MCP

من الخروج الكامل المصدر المحتفظ به، بعد تثبيت تبعية المساعد المثبتة:

npm --prefix native-bridge ci --omit=dev
node bridge/bin/longshot-bridge install --browser chrome \
  --extension-id YOUR_INSTALLED_32_LETTER_ID \
  --port 8775 --data-dir /absolute/private/longshot-chrome
node bridge/bin/longshot-bridge mcp \
  --port 8775 --data-dir /absolute/private/longshot-chrome

لاستخدام الكروم --browser chromium. استخدم المعرف الفعلي في chrome://extensions; قم بالتسجيل مرة أخرى إذا كان تثبيت إصدار المتجر يعطي معرفًا مختلفًا. يتجنب دليل المنفذ/البيانات المنفصل التصادم مع مضيف Firefox. تختلف واجهة برمجة تطبيقات الوكيل هذه عن وكيل أداة HTTP (المنافذ الافتراضية 8900/8901). Linux هو النظام الأساسي المضيف الأصلي الذي تم اختباره؛ تم تنفيذ تسجيل macOS ولكن لم يتم اختباره هنا، ولم يتم توفير مثبت Windows الأصلي.

يتوفر أيضًا التكوين التفصيلي لجسر المتصفح في الامتدادات جسر المتصفح → المعلومات الحوار. إن المستندات التمهيدية الطويلة ووثائق النظام الأساسي/الخصوصية الجديدة هي باللغة الإنجليزية؛ لا يؤدي تحديد لغة واجهة المستخدم المجمعة إلى ترجمة الأدلة المستهدفة أو الحمولات أو الأمثلة القابلة للتنفيذ.

التثبيت أو التحديث في Firefox Nightly

استخدم 2.18.1 XPI، وليس محول ZIP القديم الذي تمت إعادة تسميته كوظيفة إضافية. قم باستخراج أرشيف المصدر المطابق إلى مجلد تحتفظ به في مكانه، كما هو موضح /path/to/longshot في الأمثلة. لا تقم بنقل مضيف أصلي مسجل دون تسجيله مرة أخرى.

ملفات الإصدار هي:

  • فايرفوكس XPI
  • كروم الرمز البريدي
  • مطابقة مصدر الامتداد ZIP
  • ملاحظات الإصدار والمجاميع الاختبارية
  • المحول ZIP الأصلي: قم بتنزيله داخل Browser Bridge؛ يتم تضمينه في كل حزمة ملحقة.

هذه هي بنيات التطوير/التقديم. توقيع متجر Firefox وموافقات كلا السوقين معلقة. اتبع إجراء تحميل التطوير المطبق بدلاً من توقع تثبيت XPI غير الموقع بشكل طبيعي في إصدار Firefox.

يتطلب البيان Firefox 140 أو الأحدث. يتحقق تكامل الإصدار من سطح المكتب Firefox 159 على Linux. يعد دعم النظام الأساسي/وقت التشغيل للمساعدين الاختياريين منفصلاً عن دعم الامتداد الأساسي.

للتثبيت المؤقت غير الموقع:

  1. مفتوح about:debugging#/runtime/this-firefox.
  2. اختر تحميل الوظيفة الإضافية المؤقتة وحدد XPI.
  3. قم بتأكيد نسخة Longshot المعروضة، ثم افتح الهدف وقم بتشغيل زر شريط الأدوات الخاص به.
  4. أعد تحميل الامتداد بعد استبدال بنية التطوير غير المعبأة.

تختفي الوظيفة الإضافية المؤقتة بعد إعادة تشغيل Firefox. وهذا متوقع؛ ليس المحول هو الذي يحذف الامتداد. يحتاج التوزيع العام المستمر إلى توقيع Mozilla. يحتوي Nightly على خيارات تطوير إضافية غير موقعة موصوفة بواسطة دليل توقيع موزيلا; ولا يتطلب التحميل المؤقت تغيير تلك الإعدادات. انظر التثبيت المؤقت.

يقوم XPI بتجميع المحول الأصلي كأرشيف قابل للتنزيل. لا يمكن بدء عملية عقدة/Python عشوائية أو تثبيت المضيف الأصلي فقط من خلال الوظائف الإضافية لمتصفح Firefox. يعد بدء تشغيل الوكيل وتسجيل Agent API خطوات إعداد محلية اختيارية متميزة.

البدء والجلسات المستهدفة

قم بتوصيل علامة التبويب الصحيحة

  1. افتح الهدف المصرح به في Firefox، على سبيل المثال http://localhost:8080.
  2. قم بتسجيل الدخول باستخدام حساب الاختبار المقصود وأكمل أي تحدي للمتصفح.
  3. إطلاق Longshot من علامة التبويب الهدف تلك. أبقِ علامة تبويب التطبيق مفتوحة.
  4. تحقق من عنوان الهدف واختر الاتصال.
  5. استخدم البدء في رأس الإرشادات التفصيلية المميزة المكونة من ثماني خطوات. يمكن إعادتها. ولا يبدأ عمليات الفحص أو يغير الإعدادات بنفسه.
  6. تصفح صفحات التطبيق التمثيلية حتى يتمكن Longshot من ملاحظة المسارات والمدخلات المفيدة.

يتكون الأصل المستهدف من المخطط واسم المضيف والمنفذ. http://localhost:8080, http://127.0.0.1:8080 و https://localhost:8080 هي أصول مختلفة، حتى لو أنها تصل في نهاية المطاف إلى نفس الخدمة. قم بالاتصال واستخدام العنوان الدقيق المخصص للتقييم. لا يصبح عنوان IP الذي يتم ملاحظته خلف اسم المضيف تلقائيًا هدفًا معتمدًا إضافيًا.

الملفات الشخصية والحسابات

الأهداف يفصل التاريخ والنتائج ومجلة الطلب ونقاط النهاية المكتشفة والمراجعات وتكوين المسح. تؤدي العودة إلى ملف التعريف إلى استعادة بيانات التقييم، وليس جلسة متصفح قديمة تمت مصادقتها. يمكن للملفات الشخصية الصريحة مشاركة الأصل.

عادةً ما تشترك علامتا تبويب Firefox العاديتان في ملفات تعريف الارتباط. استخدم حاويات مستقلة أو مخزن ملفات تعريف ارتباط خاص منفصل لهويات اختبار مختلفة حقًا. لا يؤدي تبديل الملفات الشخصية إلى إنشاء جلسة حساب ثانية. تتطلب مقارنة الجلسة ب نفس الأصل المستهدف ومتجرًا منفصلاً.

اكتشاف الضوء والمسح النشط المركز

التمريرة الأولى: الاكتشاف والمراجعة السلبية

  1. تعيين طلبات في الثانية الواحدة إلى 0.5–1، وعمق الزحف إلى 1 والحد الأقصى لعناوين URL المكتشفة إلى 25–50.
  2. غادر الحد الأقصى للنتائج, عدوانية، إيقاف تشغيل الطور التلقائي لـ CVE وOAST والتنفيذ الأصلي.
  3. تعيين زغب تلقائي → إيقاف. اترك النقرات/التمرير على الصفحة وإيقاف اختبارات DOM/التوقيت/رد الاتصال المباشرة.
  4. حدد مجموعات النظرة العامة السلبية: الرؤوس وملفات تعريف الارتباط والإفصاح والنماذج ومراجعة مصدر/مصدر DOM وCORS.
  5. اختر العنكبوت فقط وابدأ.
  6. فحص خريطة الموقع, تاريخ HTTP, مستكشف واجهة برمجة التطبيقات, مكدس الخادم و النتائج.

يتبع العنكبوت الروابط/النماذج المكتشفة داخل النطاق دون إرسال نماذج مكتوبة. لا يعرف كل نقطة نهاية مخفية. لا يزال من الممكن أن يكون لطلبات GET آثار جانبية خاصة بالتطبيق؛ "طريقة القراءة" لا تنشئ هدفًا خاليًا من الآثار الجانبية.

التمريرة الثانية: تقييم نشط محدود

  1. احتفظ زغب تلقائي → إيقاف لتسهيل مراجعة القواعد النشطة المضمنة بشكل منفصل.
  2. حدد عمليات التحقق النشطة ذات الصلة "نظرة عامة"، مثل إدخال SQL وXSS المنعكس.
  3. استخدم حدودًا صغيرة، على سبيل المثال 150 طلبًا نشطًا و10 عناوين URL نشطة وخمس معلمات نشطة.
  4. اختر الشيكات النشطة فقط لإعادة استخدام الصفحة الحالية والمخزون المحفوظ، أو العنكبوت + الشيكات النشطة لاكتشاف أولا.
  5. ابدأ ومراجعة أي موافقة مطلوبة وشاهد أعداد الأنشطة والطلبات.
  6. قم بفحص طلب كل نتيجة، وخط الأساس، وأدلة التحقيق/التحكم المتكررة، والحكم والثقة.
  7. مفتوح يتحقق WSTG → تغطية الإدخال الفعلية لرؤية العمل المكتمل والجزئي والمتخطي.

لا يؤدي إيقاف الزغب التلقائي إلى إيقاف تشغيل عمليات التحقق النشطة. تقوم SQLi/XSS/SSTI والقواعد المخصصة الأخرى بإنشاء تحقيقات خاصة بها. وعلى العكس من ذلك، فإن تحديد قاعدة نشطة لا يوفر مدخلات مفقودة أو يجعل تشغيل العنكبوت فقط ينفذ المرحلة النشطة العامة.

الخيارات العدوانية وتشغيل الموافقة

العدوانية تمكن الأساليب/القدرات المعتمدة بشكل صريح؛ فهو لا يجعل كل فحص قيد التنفيذ أو يضمن أدلة أقوى.

  1. اكتشف المدخلات وتحقق من صحة المصادقة أولاً.
  2. قم بتمكين الخيارات المتقدمة المطلوبة فقط وأذونات الكتابة/التحميل/الحذف.
  3. حفظ خيارات المسح.
  4. اختر مراجعة/الموافقة على الجولة العدوانية التالية.
  5. قم بمراجعة الهدف والميزات وأذونات الطريقة والميزانيات.
  6. انقر الموافقة على هذا التشغيل التالي. يطلب إجراء المستخدم هذا أي أذونات مجمعة مفقودة لـ Firefox ويقوم بإنشاء المنحة التالية.
  7. ابدأ التشغيل بالتكوين الذي تمت مراجعته.

المنحة مخصصة للاستخدام مرة واحدة، وتنتهي صلاحيتها بعد 30 دقيقة، ويتم إبطالها من خلال تغييرات الهدف/التكوين/إعدادات الطلب ذات الصلة. يحتاج الفحص الجديد عادةً إلى منحة جديدة. يُسمح بحفظ الخيارات غير المكتملة؛ البدء أو الموافقة على التحقق من صحة الحقول المطلوبة.

يتطلب فايرفوكس permissions.request() لتنشأ مباشرة من إجراء المستخدم الحقيقي. لا يعد تغيير الإعداد سببًا لمنح أذونات عشوائية في الخلفية. إذا تم رفض الإذن، فراجع الميزة المحددة، وأعد المحاولة من زر الموافقة أو قم بتعطيل هذه الميزة. تظل مطالبات أذونات نظام التشغيل/المتصفح العادية خارج أتمتة DOM الملحقة.

الحد الأقصى للنتائج هو إعداد مسبق واسع النطاق

يقوم هذا الإعداد المسبق بتشغيل العديد من المراحل، بما في ذلك التحقق المتقدم، ومقارنة OAST والجلسة B، وتوسيع العديد من الميزانيات. إنه ليس مفتاح "العثور على كل شيء". ولا يقوم بإنشاء حساب OAST، أو ملء عنوان URL للموفر/مجال رد الاتصال، أو تحديد جلسة B صالحة، أو تثبيت Nuclei أو مصادقة الأدوار المفقودة.

إذا كانت تقارير الموافقة فارغة من حقول OAST أو كانت الجلسة B مفقودة، فقم بتكوينها أو قم بإيقاف تشغيل هذه الخيارات. وهذا منفصل عما إذا كان عنوان URL المستهدف صالحًا أم لا.

اثنان من أدوات التحكم في حقن الأوامر

نظرة عامة → مؤشرات أوامر نظام التشغيل يتيح تحقيقات إخراج الأوامر المباشرة الموجهة نحو Unix. يتم إيقاف تشغيله بشكل افتراضي. خيارات المسح → تحقيقات الأمر يتحكم في مسار رد الاتصال الأعمى الإضافي عندما يستمع OAST. لا يقوم أحد خانات الاختيار بتكوين المسار الآخر تلقائيًا. قم بمراجعة متطلبات الترخيص للتشغيل الفعلي.

ضباب الاستعلام اليدوي

  1. قم بتوصيل الهدف واختيار عنوان URL محدد النطاق. عناوين URL النسبية مثل /search?q=apple يتم قبولها مقابل الأصل المتصل.
  2. أدخل اسم معلمة الاستعلام الموجودة، أو اختر استخدم بجانب المدخلات المكتشفة.
  3. اختر فئة الحمولة وطفرة القيمة.
  4. ل الحمولات المخصصة التي تم تحميلها بواسطة المستخدم، قم بتمكين الحزمة المخصصة المناسبة أولاً.
  5. اختر تشغيل الزغب، ثم قم بفحص خط الأساس والطلب والحالة والمدة/التوقيت والأدلة.

يؤدي عنوان URL المفقود أو المعلمة أو المجموعة المخصصة الفارغة إلى ظهور رسالة تحقق محددة. تغيير الاستجابة وحده لا يثبت وجود عيب في الحقن. يمكن أن يؤدي تقييد الخادم إلى إيقاف المعلمة حتى في حالة حدوثها في الأساس.

اكتشف الزغب التلقائي المدخلات

استخدم معاينة المدخلات المكتشفة أولا. يقرأ المخزون المحفوظ ويبلغ عن الطلبات المؤهلة/التي تم تخطيها دون إرسال تحقيقات. لا يحتاج التشويش التلقائي إلى حقول عنوان URL/المعلمات الخاصة بالـ Fuzzer اليدوي. تصفح أو Spider أولاً إذا كان المخزون فارغًا.

حدد فئات الحمولة واختر المنفصلة زغب تلقائي زر. تضمين أجسام الطلبات المكتشفة يبدأ ويتطلب موافقة عدوانية بالإضافة إلى التشغيل التالي. يتم تخطي النماذج المرتبطة بالرمز المميز والأساليب غير المدعومة والنصوص غير المتوفرة وXML بواسطة محدد الإدخال التلقائي هذا. لا تزال الاستثناءات الحالية وحدود الطلب وسلوك التقييد سارية.

مربعات اختيار الفئات المتاحة هي SQLI، وNOSQLI، وCODE، وXSS، وSSTI، وTRAVERSAL، وCOMMAND، وSSRF، وREDIRECT، وCRLF، وCUSTOM. تعمل الإعدادات الافتراضية الجديدة على تمكين SQLI وSSTI وTRAVERSAL وREDIRECT وCRLF. تتخطى الحلقة العامة SSRF؛ استخدام جزر الكناري SSRF / عمليات الاسترجاعات للتحقق من تنفيذها. يستخدم CUSTOM القيم المخصصة التي تم إدخالها/تمكينها ويبلغ عن اختلافات الاستجابة منخفضة الثقة ما لم يقم المطابق المخصص بإنشاء المزيد.

تحديث قوائم جيثب يقوم بتحديث المصادر الثابتة، وليس الماسحات الضوئية القابلة للتنفيذ التعسفية:

أوقف الفحص قبل التحديث. لا يؤدي التحديث إلى بدء التحقيقات أو منح الموافقة أو تمكين OAST أو تحميل البيانات المستهدفة/الحزم المخصصة إلى GitHub. يتم رفض القالب الذي تم تنزيله والذي يتغير إلى نموذج غير مدعوم/خام/رمز/بدون رأس بدلاً من ترقيته بصمت إلى إمكانية تنفيذ جديدة.

الحمولات الخاصة بك والقوالب المستوردة

تحميل القوائم الحرفية

تحت خيارات المسح أو Fuzzer → مكتبة التحقيق → حمولاتك وقوالب CVE، ثم اختر الفئة تحميل ملف مخصص.

نماذج القائمة المقبولة:

  • .txt: قيمة حرفية واحدة غير فارغة لكل سطر؛ يتم الحفاظ على المساحات والحالة.
  • .json: مجموعة من السلاسل أو كائن يحتوي على name, category و payloads.
  • الفئات: custom, waf, sqli, nosqli, code, xss, ssti, traversal, crlf, redirect, command.
{
  "name": "My SQL review probes",
  "category": "sqli",
  "payloads": ["'", "\"", "' AND 1=1 -- "]
}

الحزم محددة الهدف ومبدئيًا معطل. افحص المعاينة وقم بتمكين الحزمة المقصودة بشكل صريح. تتطلب الحزم التي تم تحميلها تمكينًا حازمًا وموافقة؛ التحميل وحده لا يعمل شيئا.

الحدود: 256 كيلو بايت لكل ملف حمولة، و200 سلسلة لكل حزمة، و2000 حرف لكل قيمة، وعلى الأكثر 10 حزم / 500 قيمة / 512 كيلو بايت من تكوين الحزمة لكل هدف. تتم إزالة السلاسل المكررة داخل الحزمة. لا تزال الطريقة الحالية والنطاق والميزانية وحراس SQL التدميرية سارية.

تكمل الحزم المصنفة قيم الفئة المضمنة. تحتاج حزم WAF أيضًا إلى إصدارات ذكية وأدلة تصفية مؤهلة. الحمولة المخصصة الحرفية ليست مطابقة للمخرجات المتوقعة أو رمز ملحق قابل للتنفيذ. إن تحميل رقم CVE وحده لا يمكنه التحقق من ذلك.

استيراد قوالب الطلب/المطابقة

اختر فئة قالب CVE/Nuclei قبل تحميل YAML/YML/JSON؛ الحد الأقصى لملف القالب هو 2 ميجابايت. قم بمراجعتها في قوالب، بما في ذلك المنفذ والسبب الخرساني الجاهز/المحظور. تستخدم القوالب المستوردة المكتبة المشتركة؛ تبقى حزم الحمولة مع هدفها.

  • تشغيل المحدد ينفذ القوالب المحددة مباشرة ولا يتطلب مرحلة تلقائية لـ CVE.
  • المرحلة التلقائية لمكافحة التطرف العنيف يأخذ في الاعتبار عمليات الاستيراد المؤهلة التي تحمل علامة CVE/المحددة أثناء الفحص الذي تم تكوينه.
  • زغب تلقائي يولد القيم العامة. ولا يعيد كتابة حمولات CVE أو المطابقات المؤلفة.
  • يقوم JSON الاستشاري فقط بربط أدلة المنتج/الإصدار. لا يخترع طلب استغلال العمل.
  • قد تتطلب القوالب الأولية أو المعقدة أو ذات التعليمات البرمجية أو مقطوعة الرأس أو الملفات أو غير HTTP محركًا رسميًا منفصلاً ومنحًا إضافية، أو قد تظل محظورة.

قم باستيراد حزم المساعدة النسبية التي تمت مراجعتها باستخدام القوالب التي تحتاج إليها. يعد وقت التشغيل الأصلي غير المتاح أو الطلب خارج النطاق أو الموافقة المفقودة أو الميزة غير المدعومة سببًا للفحص، وليس اختبارًا سلبيًا ناجحًا.

مكدس الخادم والمحلل الذكي

استخدم كشف البرمجيات لجمع الملاحظات النطاقية المدعومة. تصفح الصفحات التمثيلية واحتفظ بالإجابات المناسبة عندما تحتاج إلى أدلة جسدية. ثم اختر تحليل الأدلة المسجلة لارتباط سلبي محلي يصل إلى 200 استجابات مخزنة حديثة. لا يضيف المحلل نفسه أي طلبات مستهدفة.

يفصل العرض بين مكونات المتصفح وWAF/CDN/edge وخادم الويب/الوكيل العكسي وإشارات التطبيق/وقت التشغيل. يمكن أن تؤدي الرؤوس الخاصة بالمنتج وأسماء ملفات تعريف الارتباط وهياكل الأصول/تمهيد التشغيل ونص الخطأ إلى زيادة الثقة. يتم استبعاد نصوص صفحة التحدي من أخذ بصمات التطبيق. لا يثبت شعار 403 أو nginx أو حافة CDN العامة أنه تم تمكين قاعدة WAF معينة.

تشرح بطاقات التكوين المحتملة أدلتها والتحقق المقترح. إنها فرضيات: لا يمكن لاستجابات المتصفح تحديد عنوان IP الأصلي أو الشبكات الفرعية الخاصة أو إعدادات قاعدة البيانات الخلفية أو إنهاء TLS أو قواعد جدار الحماية أو قوائم ثقة الوكيل بدقة. يمكن للعديد من المنبع واللافتات المعاد كتابتها إخفاء الطبقات أو التعرف عليها بشكل خاطئ.

توصيات WAF ومعالجة الأسعار

تطبيق توصيات المسح المحافظة يمكّن بشكل صريح تحقيقات SQL المجتمعية والتنوعات الذكية ومعدل التكيف ويخفض المعدل المكوّن إلى 0.5 طلب/ثانية على الأكثر. ولا يبدأ الفحص أو يمنح إمكانات متقدمة.

تنظر التحقيقات المؤهلة في ثلاثة تمثيلات بديلة على الأكثر ضمن الميزانيات الحالية. يتم تخطي خط الأساس المحظور. تحتاج تحديات المتصفح إلى دقة عادية للمتصفح؛ إن رفض ACL العادي لا يبرر محاولات التجاوز التي لا نهاية لها. إن تغيير الحظر للسماح هو دليل على إمكانية الوصول، وليس دليلاً على الضعف.

يمكن أن تؤدي التحديات الصريحة المتكررة إلى خفض معدل الذاكرة الداخلية إلى النصف وتتسبب في انتظار لمدة عشر ثوانٍ على الأقل. HTTP 429 أو 503 مع إعادة المحاولة بعد إيقاف المزيد من التحقيقات المجدولة؛ يتم احترام فترات إعادة المحاولة الأطول. ولا يرتفع المعدل تلقائيا مرة أخرى. تبدأ عمليات التشغيل الجديدة بالمعدل المحدد.

بحث مكافحة التطرف العنيف

ابحث عن مكافحة التطرف العنيف على الإنترنت يستعلم عن NVD/OSV لإحداثيات المنتج/الحزمة المدعومة بعد الحصول على إذن. يرسل الطلب إحداثيات، وليس عناوين URL المستهدفة أو ملفات تعريف الارتباط أو محتوى الصفحة. الإصدارات غير المعروفة، والمنافذ الخلفية للموردين، واستنتاجات الحد من وجود الحزمة التي لم يتم التحقق منها. لا تثبت إدخالات npm/PyPI اليدوية التثبيت.

عدم وجود تطابقات لا يعني عدم وجود CVEs. المباراة مرشحة استشارية؛ فحص المتطلبات الأساسية والاستخدام ابحث عن نماذج التحقق لتحديد موقع الشيكات المستوردة المناسبة. يقوم هذا الزر بتصفية القوالب بدلاً من تنفيذها.

إعداد وتفسير OAST

OAST يلاحظ تفاعلات DNS/HTTP الناتجة عن المسبار عندما لا تكشف الاستجابة العادية عن السلوك. تمتلك Longshot مفاتيح التسجيل/الارتباط الخاصة بها؛ رد الاتصال العشوائي الذي تم إنشاؤه مسبقًا من عميل آخر غير قابل للتبديل.

  1. اختر خدمة متوافقة مع Interactsh تتحكم فيها أو مسموح لك باستخدامها.
  2. أدخل عنوان URL للموفر: العنوان الأساسي الكامل لواجهة برمجة التطبيقات (API) للموفر، عادةً HTTPS. يُسمح بـ HTTP فقط لموفري الاسترجاع.
  3. أدخل المطابقة مجال رد الاتصال بدون http://أو منفذ أو مسار.
  4. أدخل رمز الموفر فقط إذا كان هذا المزود يتطلب ذلك.
  5. تعيين TTL والفاصل الزمني للاستقصاء؛ تمكين OAST بالإضافة إلى خيارات SSRF/XXE/Log4Shell/command ذات الصلة.
  6. استخدم اختبار اتصال OAST للتحقق من التسجيل / الاقتراع.
  7. استخدم اختبار رد الاتصال OAST لإرسال كناري مرتبط منفصل من هذا المتصفح.
  8. حفظ ومراجعة والموافقة على الفحص الفعلي. فحص الارتباط الدقيق والبروتوكول في تفاعلات OAST.

على سبيل المثال، في حالة استخدام الخدمة العامة المطابقة على https://oast.pro، قاعدة رد الاتصال الخاصة بها هي oast.pro. وهذا مثال، وليس ضمانًا للتوفر أو متطلبًا لاستخدام ذلك الموفر. يحتاج مقدم الخدمة المستضاف ذاتيًا إلى مجال الوصول إليه المفوض بشكل صحيح، DNS/المستمعين وTLS؛ لا يعد مستمع HTTP للكمبيوتر المحمول وحده خدمة رد اتصال عامة. اتبع إعداد Interactsh الرسمي.

الملاحظة ما يؤسس
يمر اختبار الاتصال تم التسجيل والاقتراع من خلال مسار المتصفح
اجتياز اختبار رد الاتصال للمتصفح يمكن لهذا المتصفح تشغيل واسترداد تفاعله المترابط
ينتج مسبار الهدف تفاعلًا مطابقًا حدث تفاعل مترابط؛ - تحديد المصدر وتقييم معناه
لا رد الاتصال غير حاسمة: قد يفسر ذلك الخروج المستهدف أو إمكانية الوصول إلى المزود أو انتهاء الصلاحية أو التصفية أو السياق غير المدعوم

يمكن أن يأتي تحليل DNS من خدمة وسيطة/أمان. رد الاتصال وحده لا يثبت الوصول الداخلي التعسفي أو سرقة البيانات أو تنفيذ التعليمات البرمجية. يمتلك محرك Nuclei المنفصل تسجيل Interactsh الأصلي الخاص به؛ هذه الأحداث ليست تسجيل عميل المتصفح.

لا يتطلب عميل OAST الموجود على جانب المتصفح واجهة برمجة تطبيقات Go أو Node أو Agent. قامت اختبارات الإصدار بإجراء التسجيل الرسمي للخادم، واسترجاع رد اتصال HTTP المشفر والارتباط عند الاسترجاع؛ لم يثبتوا توفر الموفر العام أو خروج الخادم المستهدف. لا يعد أي تعديل لملف المضيفين جزءًا من إعداد OAST العادي المفوض بشكل صحيح.

جسر المتصفح: وكيل الأداة الأصلية

ما يرسل

تقوم أداة خارجية بإنشاء الطلب، بما في ذلك حمولة الهجوم والطريقة والنص والاستعلام. يقوم المحول الأصلي بإعادة توجيهه من خلال mitmproxy، مع تطبيق تغييرات ملفات تعريف الارتباط/الرأس التي تم تكوينها فقط. إنه كذلك لا اطلب من Firefox إجراء عملية الجلب نيابةً عن ZAP أو أداة أخرى.

يحافظ ذلك على دلالات HTTP الأصلية وتوليد الحمولة النافعة للأداة، ولكن ليس بايتات الأسلاك الأصلية التعسفية: يقوم mitmproxy بتوزيع/تسلسل HTTP وإنشاء اتصال TLS الصادر الخاص به. لا تجعل سلسلة وكيل المستخدم للمتصفح بصمة TLS/الشبكة الأصلية مطابقة لمتصفح Firefox.

قم بتثبيت المحول الذي تم تنزيله

  1. مفتوح جسر المتصفح. فقط وكيل الأداة الأصلية متاح في 2.18.1.
  2. اختر قم بتنزيل المحول الأصلي واستخرجها.
  3. أدخل المستخرجة native-bridge الدليل. أنه يحتوي على cli.js, bootstrap.py, config.json والعقدة المجمعة ws التبعية.
  4. قم بتثبيت Node.js 20+ وPython 3.12+ إذا لم تكن متوفرة بالفعل.
  5. قم بتشغيل إعداد Python لمرة واحدة:

sh cd /absolute/path/to/native-bridge python3 bootstrap.py

وهذا يخلق المحلية .venv ويقوم بتثبيت mitmproxy 12.2.3. التثبيت يحتاج إلى الوصول إلى الإنترنت. لا يؤدي بدء التشغيل العادي إلى تنزيل رمز الماسح الضوئي أو قوائم الحمولة.

  1. استخدم الأمر الموضح بواسطة الخاص بك صفحة الامتداد:

sh node cli.js --config config.json \ --extension-origin moz-extension://YOUR-LONGSHOT-UUID

استبدل العنصر النائب بأصل الامتداد الحالي الكامل. إنه ليس موقع الويب المستهدف أو معرف الوظيفة الإضافية أو الأصل المنسوخ من ملف تعريف Firefox آخر.

  1. حافظ على تشغيل المحطة. بعد أن يصبح مستمع الوكيل جاهزًا، فإنه يطبع عنوان الوكيل ومنفذ التحكم ورمز الاقتران/الوكيل الجديد ومسار شهادة CA.

عند التطوير من ملف ZIP المصدر بدلاً من استخدام أرشيف المحول المجمع، قم بتثبيت تبعية العقدة المثبتة أولاً في حالة عدم وجودها:

cd /absolute/path/to/longshot-source
npm --prefix native-bridge ci --omit=dev
cd native-bridge
python3 bootstrap.py

--mitmdump /absolute/path/to/mitmdump أو LONGSHOT_MITMDUMP يختار وقت التشغيل الحالي. --data-dir /absolute/private/run-directory يحدد دليل CA/التدقيق؛ الافتراضي هو run داخل المحول الأصلي. Ctrl+C يوقف المحول.

الوكيل الأصلي اليدوي منفصل عن تسجيل مضيف Agent API. لا حاجة لذلك node bridge/bin/longshot-bridge install مجرد وكيل حليقة/ZAP. تم ممارسة Linux/Firefox في اختبارات تكامل الإصدار؛ لا تستنتج دعم مثبت المراسلة الأصلي على نظام أساسي آخر من مسار بدء تشغيل Node/Python اليدوي هذا.

قم بإقران علامة التبويب المحددة

  1. حدد المعتمد علامة التبويب الهدف في جسر المتصفح.
  2. تحقق من أصله المعروض ومخزن ملفات تعريف الارتباط. استخدم تحديث علامات التبويب إذا لزم الأمر.
  3. أدخل منفذ التحكم 8901ما لم يتم تغييره في تكوين المحول.
  4. لصق الحالي رمز الاقتران / الوكيل من محول التشغيل.
  5. اختر إقران الجسر الأصلي والتحقق من حالة الاستعداد.
  6. قم بمراجعة مفاتيح ملفات تعريف الارتباط/الرأس قبل حركة مرور أداة التوجيه.

يقوم الحقل بمسح الرمز المميز بعد الاقتران الناجح. تؤدي إعادة التشغيل إلى ظهور رمز مميز جديد: قم بإقرانه مرة أخرى وتحديث بيانات اعتماد الوكيل في كل أداة خارجية. منفذ الوكيل 8900 للأدوات؛ منفذ التحكم 8901 هو لمتصفح فايرفوكس. ولا يستخدم أي منهما الرمز المميز لحامل Agent API من المنفذ 8765.

عناوين URL المستهدفة الفعلية وbridge.invalid

استخدم العنوان الحقيقي، مثل http://localhost:8080/search?q=apple، في أداتك. في حالة اختبار HTTPS، استخدم الحقيقي https://... عنوان. يبقى عنوان الوكيل الخاص http://127.0.0.1:8900 لأن هذا هو مستمع وكيل HTTP المحلي، بما في ذلك اتصال HTTPS.

لا /etc/hosts هناك حاجة للدخول. القديم bridge.invalid كان العنوان عبارة عن اسم مستعار خاص بالمحول لتعيين عنوان URL HTTP الخاص بالأداة المساعدة على هدف جلب المتصفح المحدد. يدعم الوكيل الأصلي الحالي عناوين URL المستهدفة الفعلية وHTTPS CONNECT، لذا فإن التعيين غير ضروري.

localhost ليس اسمًا مستعارًا قابلاً للتبديل لكل هدف: فهو يقوم بتسمية الجهاز المحلي من بيئة الشبكة الخاصة بالعملية ذات الصلة. يكون هذا صحيحًا فقط عندما يكون الهدف محليًا بالفعل في ذلك الأصل. يمكن لاسم مضيف مختلف تحديد مضيف افتراضي مختلف أو سياسة ملفات تعريف الارتباط أو الأصل حتى لو كان كلا الاسمين يتطابقان مع عنوان IP نفسه.

إدخال المضيفين القديمين الحاليين لا علاقة له بسير العمل الجديد؛ لا تستخدمه في عناوين URL للأداة. لم يتم إجراء أي تعديل على ملف المضيفين أثناء إعداد هذا البرنامج التعليمي.

ثقة HTTPS

يقوم المحول بإنشاء CA المحلي الخاص به ضمن دليل البيانات المحدد، عادةً:

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

تكوين تكوين ثقة تقييم الأداة الخارجية مع طباعة مسار الشهادة العامة عند بدء التشغيل. لا تشارك المفتاح الخاص أو تفترض أنه تم تغيير مخزن الثقة الخاص بالنظام/فايرفوكس. لا يقوم المحول بتثبيت CA الخاص به في أي من مخزن الثقة.

لتجعيد الشعر:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

استبدال CURRENT_TOKEN ومسار الهدف/الشهادة. بالنسبة لهدف محلي يستخدم HTTP فقط، --cacert غير ضروري. --noproxy '' يضمن أن cur لا يتجاوز بصمت الوكيل لهدف الاسترجاع.

هناك نوعان من اختبارات TLS المميزة:

  • يتحقق العميل من الشهادة المقدمة بواسطة المحول. قم بتكوين ثقة العميل باستخدام المحول CA.
  • يتحقق المحول من الخادم الرئيسي الحقيقي. tls.verifyUpstream الافتراضيات صحيحة. العميل --cacert لا يوفر CA أصل خاص للمحول.

لا تعامل تعطيل التحقق كحل عادي لأخطاء الشهادة. بالنسبة للتركيبات الموقعة ذاتيًا المملوكة، tls.verifyUpstream:false يعد استثناءً صريحًا للتقييم في تكوين المحول، متبوعًا بإعادة التشغيل؛ إنه يضعف هذا الفحص المنفصل للمنبع. انظر سلوك شهادة mitmproxy.

الإخلاص المروري وحدوده

يدعم الوكيل الأصلي لا يؤسس ولا يدعم
الأساليب المولدة بالأداة، والحمولات والأجسام الاستعلامية وحدات بايت الرأس/الطلب/الغلاف الأصلية الدقيقة أو الإطار المشوه
HTTP/1.1، HTTP/2، اتصال HTTPS HTTP/3، أو أوضاع الماسح الضوئي TCP أو غير HTTP
تجاوزات الجلسة/الرأس التي تم تكوينها بصمة المتصفح الكاملة أو تنفيذ تحدي JavaScript أو TLS المملوك للمتصفح
ترقيات WebSocket على المسار الأصلي أداة عامة للتحقق من الثغرات الأمنية في بروتوكول التطبيق
تتحقق أداة رأس المضيف مع الاحتفاظ بوجهة HTTPS CONNECT المعتمدة هدف اتصال غير مقيد أو ترخيص هدف جديد تلقائي
تم تحديد نطاق الأصول الإضافية دون تصدير جلسة المتصفح تتم مشاركة ملفات تعريف الارتباط/بيانات اعتماد الرأس في المتصفح تلقائيًا عبر الأصول

لا يحتوي المسار الأصلي على خيار احتياطي لجلب المتصفح. بالنسبة لأبحاث تهريب الطلبات الأولية أو الإطارات السلكية غير العادية أو أبحاث TLS المخصصة، استخدم وسيلة نقل منفصلة مناسبة. لا تقم بتسمية هذا الوكيل الذي تم تحليله بأنه بايت شفاف.

تكوين الجسر الأصلي

قم بتنزيل التكوين من Browser Bridge أو قم بتحرير ملف المحول config.json. يتم رفض المفاتيح غير المعروفة والأنواع غير الصالحة والقيم خارج النطاق. حقول المحول القديمة ليست مرادفات تكوين أصلية.

يعد تكوين المحول قيد التشغيل موثوقًا عند الاقتران. تطبيق التجاوزات تدعم التغييرات خيارات تجاوز المتصفح للاقتران الحالي. تحميل التكوين يحتفظ بالتكوين المحدد للبدء التالي. لا يؤدي تحرير حقول JSON العامة إلى إعادة تكوين منافذ المستمع أو TLS أو التوجيه أو الحدود بصمت في عملية قيد التشغيل بالفعل: الحفظ/التنزيل وإعادة التشغيل وإعادة الإقران.

نطاقات التحقق الأصلية: المنافذ 1024–65535، المعدل 0.1–100، التزامن 1–32، سقف الطلب 1–1,000,000، الحد الأقصى للنص 1 كيلو بايت–256 ميجابايت، المهلة 1–600 ثانية، مهلة التحكم 1000–120000 مللي ثانية. هذه هي حدود التكوين المقبولة، وليست توصيات للتحميل الآمن للهدف.

أسماء الرؤوس غير حساسة لحالة الأحرف. أسماء ملفات تعريف الارتباط حساسة لحالة الأحرف. استخدم القيم المنطقية JSON true/false، وليس سلاسل. عام headers.set لا يمكن استبدال حقول المضيف أو ملف تعريف الارتباط أو التفويض أو الإطارات أو التحكم بالوكيل. استخدم خيارات ملفات تعريف الارتباط/التفويض المخصصة وقيمة المضيف الخاصة بالأداة.

لتقليل التحميل لتشغيل أداة أصلية، يمكن للتكوين الجزئي أن يتجاوز الإعدادات الافتراضية، على سبيل المثال:

{
  "schemaVersion": 1,
  "limits": {
    "rate": 0.5,
    "concurrency": 1,
    "maxRequests": 500

}

لا يوجد مفتاح تكوين أصلي عام يقوم بتحديث الرموز المميزة لنص النموذج أو يخترع سير عمل تسجيل الدخول إلى المتصفح.

يتم تجاوز ملف تعريف الارتباط والرأس دون إتلاف المجسات

سلوك ملفات تعريف الارتباط الافتراضي

استخدم ملفات تعريف الارتباط للمتصفح و حفظ تحديثات مجموعة ملفات تعريف الارتباط الخاصة بالاستجابة قيد التشغيل بشكل افتراضي. يظل وكيل المستخدم ولغة القبول والتفويض خاضعين للتحكم بالأدوات بشكل افتراضي.

بالنسبة للطلب الأصلي، يحدد Firefox ملفات تعريف الارتباط القابلة للتطبيق لعنوان URL من مخزن ملفات تعريف الارتباط لعلامة التبويب المقترنة والقسم المطابق. لا يتم دمج الحاويات/المخازن الخاصة الأخرى. تظل قواعد المجال/المسار/الآمن/انتهاء الصلاحية وترتيب مسار الاسم نفسه ذات صلة. يتم توفير القيم إلى الوكيل الأصلي حتى يتمكن من إنشاء رأس ملف تعريف الارتباط الصادر؛ وعلى عكس مسار جلب المتصفح الذي تمت إزالته، يتعامل المساعد الأصلي مع أسرار الجلسة في الذاكرة.

مع cookies.mode:"replace"، إن جرة المتصفح موثوقة، بما في ذلك عندما تكون فارغة. تتم إزالة ملف تعريف ارتباط المتصفح المحذوف من الجرة من الطلبات المُدارة لاحقًا. تحظى الأسماء المحمية بشكل صريح وتغييرات الأداة المكتشفة بالأولوية. مع mode:"merge"، يمكن أن تظل ملفات تعريف الارتباط الخاصة بالأدوات غير ذات الصلة أثناء تحديث الأسماء التي يديرها المتصفح.

يتم تطبيق حقول ملفات تعريف الارتباط لمجموعة الاستجابة بشكل فردي على نفس المتجر المحدد باستخدام واجهة برمجة تطبيقات ملفات تعريف الارتباط الخاصة بـ Firefox، بما في ذلك سمات Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition المدعومة. يمكن رفض ملفات تعريف الارتباط غير الصالحة؛ فحص الأخطاء المبلغ عنها. لا تتلقى الأصول الإضافية التي تم تكوينها ملفات تعريف الارتباط للمتصفح أو الرؤوس المشتقة من المتصفح.

مفاتيح الطلب والاستجابة مستقلة

طلب تجاوز ملفات تعريف الارتباط مزامنة الاستجابة النتيجة
على على استخدم ملفات تعريف الارتباط الخاصة بـ Firefox وقم بتحديث الجرة من الاستجابة Set-Cookie
إيقاف على احتفظ بملفات تعريف الارتباط الخاصة بطلب الأداة؛ لا يزال بإمكان الاستجابات المستهدفة تغيير جرة Firefox
على إيقاف استخدم ملفات تعريف الارتباط الخاصة بفايرفوكس؛ لا تكتب ملفات تعريف الارتباط للاستجابة مرة أخرى من خلال هذا المساعد
إيقاف إيقاف اجعل ملفات تعريف الارتباط الخاصة بالطلبات خاضعة للتحكم ولا تقم بمزامنة الاستجابات

بالنسبة لتشويش ملفات تعريف الارتباط أو تجربة الجلسة التي يجب أن تترك جرة المتصفح دون تغيير، فكر في كلا المفتاحين. يؤثر تجاوز التجاوز لكل طلب على التجاوزات من جانب الطلب؛ ولا يؤدي إلى تعطيل إعداد مزامنة ملفات تعريف الارتباط للاستجابة العالمية المستقلة.

حماية الحقول التي تحتوي على حمولات الهجوم

لنفترض اختبارات ZAP session=ATTACK_PAYLOAD. قد يؤدي استبدال هذه القيمة بشكل أعمى بجلسة المتصفح الصالحة إلى مسح الاختبار. وعلى العكس من ذلك، فإن الاحتفاظ بملف تعريف الارتباط القديم في كل طلب قد يجعل الفحص المصادق عليه عديم الفائدة.

الافتراضي الحفاظ على تغييرات ملف تعريف الارتباط/الرأس للأداة بعد طلبها الأول يسجل خط الأساس لكل اتصال/أصل للعميل ويحافظ على التغييرات اللاحقة. أرسل طلب بذور عادي أولاً. لا يمكن للوكيل استنتاج النية بشكل موثوق عند الطلب الأول، ويقوم الاتصال الجديد بإنشاء خط أساس جديد. هذا الكشف عن مجريات الأمور ليس حماية كاملة.

لإجراء اختبار يمكن التنبؤ به، اختر إحدى هذه الآليات:

  1. قم بتعطيل تجاوز ملف تعريف الارتباط/الرأس المحدد الذي يتم اختباره.
  2. أضف أسماء ملفات تعريف الارتباط إلى cookies.protectedNames أو رؤوس ل headers.protectedNames.
  3. أرسل تعليقًا توضيحيًا انتقائيًا لكل طلب:

http X-Longshot-Preserve: cookie:session, User-Agent, Authorization

يؤدي هذا إلى الاحتفاظ بحقول ملفات تعريف الارتباط/الرؤوس المسماة للأداة. cookie بدون اسم يحافظ على رأس ملف تعريف الارتباط للأداة الكاملة.

  1. تجاوز كافة التجاوزات من جانب الطلب لهذا الطلب:

http X-Longshot-Override: off

يقوم المحول بإزالة رؤوس التعليقات التوضيحية هذه قبل إعادة التوجيه. لا تزال مصادقة الوكيل ونطاقه وحدوده سارية. تكوين التعليقات التوضيحية في الأداة الأصلية؛ إن وضعها في صفحة ويب مستهدفة لا يعد آلية لتكوين الجسر.

على سبيل المثال، حفظ session يسمح protected لـ ZAP بتغييره بينما يمكن للمساعد مواصلة تحديث ملف غير ذي صلة preferences ملف تعريف الارتباط. بالنسبة للاختبار الشامل لملفات تعريف الارتباط/الترخيص/وكيل المستخدم، يؤدي تعطيل هذه التجاوزات إلى تجنب الاعتماد على الأساليب البحثية لاكتشاف التغيير.

ترخيص المتصفح والرؤوس الأخرى

يتم تمكين ترخيص المتصفح من خلال تكوين JSON. يتم التقاطه من طلب فعلي بواسطة علامة التبويب الهدف المقترنة فقط بعد تمكين مصادر المتصفح. إنه ليس قارئًا تلقائيًا لكل رمز مميز في ذاكرة التخزين المحلية أو ذاكرة التطبيق. قد تكون هناك حاجة إلى طلب متصفح لاحق قبل وجود قيمة ملحوظة. يؤدي إيقاف تشغيل ترخيص المتصفح إلى إيقاف القيمة التي تم التقاطها بواسطة المساعد.

يؤدي اختيار وكيل المستخدم أو قبول اللغة للمتصفح إلى تغيير حقول HTTP هذه فقط. فهو لا يقوم بتشغيل JavaScript الهدف أو تحديث رمز CSRF الأساسي أو إعادة إنتاج TLS للمتصفح أو ضمان قبول WAF. لا تزال المصادقة المرتبطة بـ IP/الجهاز وتحديث OAuth بحاجة إلى سير عمل التطبيق.

VHOST/التعامل مع المضيف

لا يقوم المساعد الأصلي باستبدال الاسم المستعار للجسر الداخلي في حقل مضيف الأداة. اسمح للأداة بإرسال قيمة المضيف المطلوبة لاختبار المضيف الظاهري المعتمد. بالنسبة لـ HTTPS، تظل وجهة CONNECT هي الهدف المعتمد بينما يمكن الحفاظ على رأس مضيف الأداة.

لا يؤدي تغيير رأس المضيف إلى منح الوصول إلى وجهة شبكة أخرى. قد يقوم الوكيل العكسي بتوجيهه إلى تطبيق آخر؛ قم بتضمين سلوك المضيف الافتراضي هذا في ترخيص التقييم. توجد وحدات بايت الرأس المشوهة والإطارات المتعارضة خارج هذا الوكيل الذي تم تحليله.

التدقيق والخصوصية

حركة المرور الأصلية يعرض بيانات تعريف الطلب وأسماء الحقول المتغيرة/المحمية. يحذف التدقيق القيم السرية لملفات تعريف الارتباط/الرأس وقيم الاستعلام ونصوصه. هذا لا يعني أن الوكيل لا يتعامل أبدًا مع الأسرار: يجب أن يعالجها لإرسال حركة مرور تمت المصادقة عليها. تحتفظ الأدوات الخارجية بسجلاتها/نتائجها الخاصة، والتي يمكن أن تحتوي على تلك القيم.

احتفظ برموز التكوين الخاصة ومفاتيح CA وأدلة البيانات خارج أرشيفات التقارير/المصادر. يمكن أن يؤدي تنزيل التكوين باستخدام قيم التفويض المخصصة إلى إنشاء ملف يحتوي على تلك القيم.

الأدوات الخارجية ومسح ZAP الفعلي

ابدأ بطلب واحد

قم بإقران الجسر، ثم اختبر الهدف المحلي الفعلي:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  'http://localhost:8080/'

استخدم مسار قراءة معتمد ومعروفًا للتحقق من سلوك الجلسة. 200 من الصفحة الرئيسية العامة ليست كافية. تأكد من ظهور الطلب في حركة المرور الأصلية، وأن مخزن ملفات تعريف الارتباط المحدد صحيح، وأن الأداة تلقت المحتوى المتوقع. لا تستنتج أن جميع الطلبات اللاحقة تستخدم الوكيل لمجرد أن هذا الطلب يستخدمه.

ZAP الوكيل الصادر

  1. قم بتثبيت/بدء تشغيل ZAP بشكل منفصل واستخدام جلسة ZAP الخاصة بالتقييم.
  2. في ZAP خيارات → الشبكة → اتصال، تمكين وكيل HTTP الصادر.
  3. تعيين المضيف 127.0.0.1، ميناء 8900 (أو منفذ الوكيل الحالي الذي تم تكوينه).
  4. تمكين مصادقة الوكيل: اسم المستخدم bridge، كلمة مرور الرمز المميز للمحول الحالي.
  5. قم بتعطيل وكيل SOCKS الخاص بـ ZAP لهذه السلسلة. يكون لإعداد SOCKS الخاص بـ ZAP الأسبقية على وكيل HTTP الخاص به.
  6. تحقق من استثناءات وكيل HTTP حتى لا يتم تجاوز الهدف المقصود، خاصة بالنسبة للخدمة المحلية.
  7. قم بتكوين CA المحول في إعداد الثقة/التحقق TLS القابل للتطبيق للأداة عند الحاجة. تتم طباعة موقعه عند بدء تشغيل المحول.
  8. الوصول إلى عنوان URL المستهدف الفعلي من ZAP والتحقق من تاريخه بالإضافة إلى بيانات تعريف الجسر.
  9. حدد الهدف/السياق الخاص بـ ZAP، وسياسة الفحص، والاستثناءات، وفحوصات المصادقة، ومعدل الطلبات المتواضع. قم بتشغيل العنكبوت/المسح النشط الفعلي على النحو المصرح به.
  10. مراجعة النتائج والتغطية في ZAP. عند تشويش حقول مصادقة ملفات تعريف الارتباط/الرأس بشكل متعمد، استخدم آليات الحماية/التجاوز المذكورة أعلاه.

هذا الإعداد هو ZAP اتصال الصادرة، وليس مستمع الوكيل المحلي للمتصفح الوارد. لا يلزم إعادة تكوين Firefox لاستخدام ZAP فقط لتوفير ملفات تعريف الارتباط الخاصة بعلامة التبويب المحددة لهذه السلسلة.

يقوم ZAP بإنشاء حمولاته الحقيقية ذات القاعدة النشطة؛ يرسل mitmproxy الطلبات الأصلية الناتجة. يقوم Longshot بتغيير حقول الطلب التي تم اختيارها فقط. يؤدي هذا إلى زيادة سياق الجلسة القابلة للاستخدام للأداة الخارجية ولكنه لا يجعل فحص أي من الأداتين شاملاً. انظر إعدادات اتصال ZAP.

يعد عنوان URL للوكيل الذي يحتوي على بيانات الاعتماد حساسًا. استخدم تكوين التقييم الخاص لأداتك حيثما كان ذلك متاحًا. لا تقم بلصق الرموز المميزة الحالية في التقارير المشتركة. بالنسبة لكل أداة، قم بتأكيد حركة المرور الموجهة بدلاً من افتراض أن كل بروتوكول أو عملية فرعية تحترم إعداد وكيل HTTP الخاص بها.

مثال على مكتبة Linux Python القياسية لهدف محلي للقراءة فقط؛ فهو يطالب بالرمز المميز بدلاً من تشفيره ويمسح تجاوز وكيل البيئة لهذه العملية:

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

التحقق من الطلب في حركة المرور الأصلية؛ يمكن أن تحتوي الأنظمة الأساسية الأخرى على قواعد تجاوز وكيل النظام الإضافية. مثال الضفيرة مع صريح --noproxy '' هو التحقق من صحة مسار الاسترجاع الأبسط. يحتاج عملاء HTTPS Python بالإضافة إلى ذلك إلى حزمة سياق SSL/CA التي تثق في شهادة المحول.

وقفة وأخطاء

إيقاف الطلبات الأصلية مؤقتًا يمنع الخروج الأصلي الجديد. يمكن أيضًا لحالات المصادقة 401/419/440 أو HTTP 429 أو إغلاق علامة التبويب/التغييرات خارج الأصل أو حدود الميزانية إيقاف العمل مؤقتًا. استئناف بعد التحقق من علامة التبويب يستأنف فقط بعد مراجعة حالة الاقتران.

توقف وافصل إنهاء اقتران المتصفح؛ ولا ينهي عملية العقدة التي بدأت بشكل منفصل. استخدم Ctrl+C في المحطة الطرفية لإيقاف هذه العملية.

قد تنتهي الطلبات على متن الطائرة. يتلقى عملاء الوكيل أخطاء بسبب العمل المحظور؛ لا يقوم المحول بتعليق عمليات الأداة التعسفية أو إعادة تشغيل طلباتها. افحص الطلبات التي نجحت واستخدم عناصر التحكم الخاصة بإعادة المحاولة/الاستئناف الخاصة بالأداة. تؤدي إعادة التشغيل/إعادة الاقتران إلى تغيير الرمز المميز وتتطلب تحديث مصادقة الأداة.

قد يتم توقع 401/419/440 في اختبارات المصادقة السلبية المتعمدة. إذا لزم الأمر، اضبط session.pauseStatuses لهذا التشغيل وإعادة التشغيل الذي تمت مراجعته؛ لا يستنتج المحول ما إذا كان كل فشل في المصادقة هو مسبار مقصود.

توجيه تور والبصل

تتبع طلبات Longshot المستندة إلى المتصفح شبكة المتصفح المحدد. يعد المحول الأصلي عملية مختلفة ولا يرث إعدادات وكيل متصفح Firefox/Tor.

الجوارب/تور هو إيقاف بشكل افتراضي في التكوين الأصلي. للحصول على تقييم بصلي معتمد، استخدم خدمة SOCKS موجودة بشكل صريح مع تحليل اسم المضيف عن بعد، على سبيل المثال هذا التجاوز إذا كان هذا هو مستمع Tor المحلي الخاص بك حقًا:

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

هذا المثال لا يقوم بتشغيل Tor أو إثبات وجود المنفذ 9050. حدد الخدمة الفعلية التي تم تكوينها؛ قد يستخدم مثيل متصفح Tor مستمعًا مختلفًا. أعد تشغيل المحول وأعد الاقتران. HTTP(S) upstream.url و routing.socks5 متنافية.

تعمل الرقائق الأصلية على حل أسماء المضيفين من خلال SOCKS ولا يوجد بها أي تراجع مباشر صامت. بدون تكوين مسار المنبع/SOCKS بشكل صريح، يتم رفض الوجهات البصلية المباشرة قبل DNS المستهدف. يمكن أن يشير عنوان URL الخاص بـ SOCKS أيضًا إلى نفق SSH معتمد أو خدمة SOCKS5 أخرى؛ فهو ليس دليلاً جوهريًا على توجيه Tor.

لا تؤدي مشاركة ملفات تعريف الارتباط إلى جعل عنوان IP للخروج من المسار الأصلي أو بصمة TLS/المتصفح مطابقة لمتصفح Firefox. قد ترفضه التحديات أو ربط الجلسة. تحقق من المسار والجلسة المتوقعة بشكل مستقل.

تختلف النوى الأصلية المعزولة التي أطلقها Agent API: لا يحتوي المرحل المدمج على مسار Tor/SOCKS ويحظر الأهداف البصلية قبل نظام DNS. استخدم عمليات التحقق المؤهلة من جانب المتصفح في المتصفح المقصود، أو أداة خارجية تم تكوينها بشكل منفصل من خلال الوكيل الأصلي. لا تفترض أن خانة الاختيار Nuclei ترث routing.socks5 من جسر المتصفح

Agent API وMCP وعملاء النموذج المحلي

استخدم هذا عندما يتعين على الوكيل/البرنامج النصي تشغيل Longshot أو استرداد الأدلة أو حفظ ملفات التقييم. إنه ليس وكيل حركة المرور: 8900.

قم بالتسجيل والاتصال بالمضيف الأصلي

من المحتفظ بها المصدر يحتوي الدليل manifest.json و bridge/:

cd /absolute/path/to/longshot-source
node bridge/bin/longshot-bridge install

هذا يسجل longshot.bridge ومشغّل يشير إلى المجلد المصدر والعقدة القابلة للتنفيذ. احتفظ بكلاهما في مكانه. إذا تحرك أي منهما، قم بالتسجيل مرة أخرى.

مفتوح الإعدادات ← الاتصال والإعداد ← توصيل الجسر الأصلي ومنح إذن المراسلة الأصلية لـ Firefox. يمكن للمضيف أن يبدأ البرنامج الخفي الخاص به تلقائيًا. إذا قمت بتشغيل البرنامج الخفي يدويًا عن عمد:

node bridge/bin/longshot-bridge serve

تجنب البرنامج الخفي الثاني في نفس دليل المنفذ/البيانات. يؤدي قطع الاتصال إلى إغلاق الاتصال الأصلي للامتداد؛ فهو لا يوقف بالضرورة البرنامج الخفي الذي بدأ بشكل مستقل.

مطلوب Node.js 20+. لا يحتاج MCP للمراسلة الأصلية إلى تثبيت Python/mitmproxy الخاص بالوكيل. Linux هو الإعداد الممارس. يتم توفير دعم تسجيل macOS ولكن لم يتم التحقق من وقت التشغيل هنا؛ لا يحتوي هذا الإصدار على مثبت Windows Firefox الأصلي. لا يؤدي التسجيل في WSL إلى تسجيل مضيف لنظام التشغيل Windows Firefox. عزل النواة الأصلية هو نظام Linux فقط.

الخدمة الافتراضية: http://127.0.0.1:8765. عنوان المضيف المحلي هذا عبارة عن واجهة برمجة تطبيقات تحكم، ليس الهدف الممسوح ضوئيا. الرمز المميز/المقبس افتراضيًا $XDG_DATA_HOME/longshot أو ~/.local/share/longshot. مخصص --port و --data-dir يجب أن يتطابق عبر التثبيت والخدمة وMCP. استخدم مسار بيانات Unix قصيرًا لأن مسار المقبس الخاص به له حد يبلغ 100 بايت.

مثال الراحة

من نفس المجلد المصدر:

longshot_token_file="$(node bridge/bin/longshot-bridge token-path)"
longshot_api_token="$(cat "$longshot_token_file")"

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/health

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/targets

ال token-path يقوم الأمر بطباعة اسم الملف، وليس الرمز المميز. تستخدم واجهة برمجة التطبيقات (API) مصادقة الحامل، على عكس مصادقة اسم المستخدم/كلمة المرور للوكيل. فهو يرفض عملاء عدم الاسترجاع وطلبات أصل المتصفح ولا يكشف عن واجهة برمجة تطبيقات CORS العامة. لا تنشره من خلال وكيل عكسي عام.

ابدأ فحصًا صغيرًا فقط بعد توصيل/تنشيط الهدف المقصود والتحقق من خياراته المحفوظة:

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  -H 'Content-Type: application/json' \
  --data '{"target_id":"PROFILE_ID","mode":"safe","budget":150}' \
  http://127.0.0.1:8765/v1/scans

استبدل PROFILE_ID بمعرف ملف التعريف المحدد. safe خرائط لـ Spider فقط؛ ولا يقوم بإعادة تعيين كل خيار متقدم محفوظ أو يعمل كتجاوز عالمي. البداية غير متزامنة. اقرأ معرف التشغيل الذي تم إرجاعه، ثم قم بالمراقبة /v1/scans/RUN_ID, /eta, /findings أو /report?format=html. POST /pause, /resume و /stop السيطرة على المدى. استشارة موثقة /openapi.json للمخططات الدقيقة.

ملفات تعريف دعم REST/JSON-RPC وعمليات المسح والنتائج/التقارير والقوالب وعمليات OAST وعمليات الجلسة. /rpc يحمل JSON-RPC؛ /mcp يقدم MCP HTTP، مع خيارات stdio وSSE. قد تحتفظ سلاسل إصدار البروتوكول/واجهة برمجة التطبيقات (API) الخاصة بالخدمة بإصدارات المخطط الأقدم؛ استخدم بيان الامتداد لإصدار إصدار واجهة المستخدم المثبت.

إعداد عميل MCP

بالنسبة للعميل الذي يدعم تكوين stdio MCP:

{
  "mcpServers": {
    "longshot": {
      "command": "node",
      "args": [
        "/absolute/path/to/longshot-source/bridge/bin/longshot-bridge",
        "mcp"
      ]
    }
  }
}

استخدم عقدة مطلقة قابلة للتنفيذ إذا كان لدى العميل مسار مقيد. أضف المطابقة --port / --data-dir الحجج عند تخصيصها. يتصل مساعد stdio بالخدمة المحلية المصادق عليها؛ فهو لا يحل محل اتصال Firefox.

يحتوي كتالوج أدوات MCP الحالي على 21 أداة: أدوات المسح/القالب/التقرير/OAST بالإضافة إلى واجهة المستخدم واكتشاف/تحكم الأوامر الدلالية. اكتشف الكتالوج الفعلي بدلاً من الاعتماد على البرنامج التعليمي القديم المكون من ثماني أدوات.

لا تزال عناصر التحكم المعطلة والنطاق المستهدف والدولة والميزانيات سارية. تتطلب المراجع القديمة لقطة جديدة؛ النقرة المرسلة وحدها لا تثبت النجاح. تظل مطالبات إذن Firefox/OS عناصر تحكم منفصلة للمتصفح/نظام التشغيل.

حدود الموافقة: لا يمكن لأوامر الموافقة الدلالية المباشرة إصدار منحة تشغيل عدوانية. يمكن أن تعمل أتمتة واجهة المستخدم الكاملة الموثقة على تشغيل مربع حوار الموافقة الخاص بلوحة المعلومات المقيدة، بما في ذلك زر الموافقة الخاص بها. ومن ثم، فإن منح عنصر التحكم في واجهة المستخدم للوكيل يمنحه إمكانية واجهة المستخدم هذه؛ لا تصف هذا الوصول بأنه غير قادر على النقر فوق الموافقة. لا تزال عمليات التحقق من الهدف/التكوين/انتهاء الاستخدام أحادية الاستخدام سارية.

Hermes/Ollama أو وكيل نموذج محلي آخر

لا يقبل Longshot دفق دردشة LLM تعسفيًا أو تحديد نموذج. ال تطبيق الوكيل يوفر اتصال النموذج وحلقة استدعاء الأداة. إذا كان وكيلك يدعم MCP، فقم بتكوين خادم MCP أعلاه في هذا الوكيل. يرسل الوكيل استدعاءات الأدوات المدعومة ويستقبل نتائج الأداة؛ يمكنه فحص/التنقل/ملء الامتداد من خلال أدوات واجهة المستخدم المكشوفة بالإضافة إلى استدعاء أوامر الفحص.

اختر نموذج Ollama والخادم في التكوين الخاص بـ Hermes/الوكيل. استخدم مجموعة النموذج/العميل التي تدعم تنسيق استدعاء أداة الوكيل، وتأكد من السماح للوكيل فعليًا باستدعاء أدوات MCP. تكوين Longshot لا يحتوي على model, ollama أو إعداد مفتاح API للموفر. يعد الوصول إلى النموذج والوصول إلى shell والتحكم في نظام الملفات غير ذي الصلة من إمكانيات مضيف الوكيل، ولا يتم منحها عن طريق تثبيت هذا الامتداد.

اجعل النطاق والميزانيات والحساب والإجراءات المقصودة واضحة في مهمة الوكيل. التحقق من صحة النتائج التي تم التوصل إليها مقابل الأدلة المسجلة؛ النص النموذجي ليس نتيجة الماسح الضوئي أو منح الإذن.

التحكم الاختياري في منفذ التصحيح

يتضمن المصدر مساعدي تحكم BiDi/CDP وأمر واحد bridge/bin/longshot-ui واجهة. هذا هو التحكم المتقدم في الصفحات المملوكة للامتداد. إصدار Chrome عبارة عن حزمة Manifest V3 منفصلة؛ يجب أن تظل طاولة العمل المرئية مفتوحة. يعد فتح مستمع تصحيح أخطاء المتصفح خيارًا منفصلاً لبدء تشغيل المتصفح؛ انظر أمان الوكيل البعيد لـ Firefox.

يستخدم مساعد التصحيح الاختياري المثبت ws التبعية في native-bridge/node_modules/ws/. تشغيل npm --prefix native-bridge ci --omit=dev من الخروج المصدر المحتجز أولا. تم تصحيح هذا المسار في سلسلة 2.18؛ محول جلب المتصفح التاريخي الذي تمت إزالته غير مطلوب.

مستكشف واجهة برمجة التطبيقات

اتصل وتصفح أولاً، ثم اختر فحص الصفحة الحالية. استيراد المطور المقدمة OpenAPI JSON الوصف عندما يكون متاحًا، يصل إلى 2 ميجابايت. يقرأ JSON المحلي، وليس صفحة بعيدة عشوائية أو ملف YAML. يمكن لمراجع المواصفات المحلية وأمثلة الطلب/الافتراضيات المتاحة أن توفر مدخلات ملموسة مدعومة؛ القيم/الأجسام المفقودة والبنيات غير المدعومة تترك فجوات.

نقطة النهاية هي عنوان؛ العملية هي عنوان بالإضافة إلى الأسلوب. تظهر مدخلات الاستعلام بعد ذلك ?ومدخلات المسار في مسار العنوان ومدخلات النص في المحتوى المقدم. العملية المدرجة هي مخزون، وليست دليلاً على أن الحساب الحالي يمكنه الوصول إلى كل كائن يعالجه.

استخدم مكرر بجانب عملية GET/HEAD المدعومة لإعداد طلب دون إرساله بعد. راجع عنوان URL/الطريقة/المدخلات، ثم أرسلها عمدًا. لا تزال عمليات الكتابة للمخزون فقط تتطلب منك إعداد الطلب المناسب والحصول على موافقة الكتابة.

مكرر ومقارنة

يقوم المكرر بإجراء طلب جديد محدد النطاق باستخدام جلسة المتصفح المرتبطة. GET/HEAD/OPTIONS استخدم المسار العادي. تظل أساليب الكتابة وتغييرات الجسم وإمكانيات التدمير/التحميل خاضعة للسياسة والموافقة. لا يمكن استبدال قيم ملفات تعريف الارتباط/الترخيص/المضيف المُدارة بحرية من خلال محرر الرأس الخاص بها؛ استخدم مسار الأداة الخارجية الأصلي لاختبارات الرأس/ملفات تعريف الارتباط التي تم تكوينها بشكل صريح.

اتبع عمليات إعادة التوجيه من نفس المصدر يتحكم في ما إذا كنت تقوم بفحص إعادة التوجيه نفسها أو الاستجابة النهائية المسموح بها. عمليات إعادة التوجيه خارج النطاق ليست تفويضًا شاملاً. احتفظ بنصوص الاستجابة عند الحاجة للمراجعة، ثم اختر استجابتين محفوظتين فيها قارن. قارن لا يرسل أي طلبات؛ يمكن أن يفسر المحتوى الديناميكي أو حالة تسجيل الدخول أو التقييد أو صفحات WAF الفرق.

WebSocket وSSE والمرافق

اختر قناة تم اكتشافها داخل النطاق أو أدخل عنوان URL الدقيق الخاص بها. إن الاستماع وإرسال الإطار المخصص هما عمليات معتمدة، وليس ماسحًا ضوئيًا عامًا للبروتوكول. نص الخطأ الذي تم التقاطه هو عميل متوقع؛ لا ينشئ ترخيصًا للرسالة أو خللًا في العرق/المنطق.

تقوم الأدوات المساعدة بتشفير/فك تشفير القيم وحساب SHA-256 وتنسيق JSON وفحص مطالبات JWT محليًا. لا يعد فك تشفير JWT بمثابة التحقق من التوقيع ولا يثبت أن الخادم يقبل رمزًا مميزًا مزورًا. لا يتم تنفيذ الإدخال المحول أو إرساله تلقائيًا.

قم بتعيين حالة المراجعة والملاحظات، ثم حفظ المراجعة. لا يؤدي هذا إلى استبدال الحكم/الثقة الأصلية للماسح الضوئي. تبقى الإيجابيات الكاذبة أدلة محتفظ بها. مرشحات، بما في ذلك إظهار سلبي / محظور، تغيير الرؤية، وليس سجل التنفيذ.

تسميات الدعم:

  • الفحص النشط: توجد قاعدة مخصصة تم تنفيذها عند تمكينها، للمدخلات التي تم الوصول إليها المدعومة.
  • التحقق الاختياري: يتم تطبيق خيارات أو أذونات أو موفر أو متطلبات تنفيذ إضافية.
  • المؤشرات فقط: إشارة/مقارنة سلبية تتطلب تفسيرًا يدويًا.
  • تعتمد على القالب: يحدد القالب والمنفذ المستوردان الحالة التي تم اختبارها.
  • غير مغطى: لا يوجد أداة تحقق مدمجة مخصصة لتلك الفئة؛ لا تقوم الحمولات المخصصة العامة بإنشاء التغطية تلقائيًا.

هذا هو تدقيق القدرة على أساس المصدر، ليست نسبة الكشف المقاسة. وهو يصف الماسح الضوئي المدمج في Longshot ومراحله الاختيارية، وليس مجموعة قواعد ZAP الخارجية بأكملها.

OWASP 2025 الضعف / الضعف الدعم ما يعمل / الخيارات المطلوبة حدود
A05 حقن SQL: أخطاء قاعدة البيانات والاختلافات المنطقية فحص نشط تمكين حقن SQL. تستخدم تحقيقات خطأ قاعدة البيانات المتكررة ومقارنات الصواب/الخطأ ضوابط جديدة على المدخلات المكتشفة. يحتاج المرشحون إلى المراجعة. لا يوجد استخراج لقاعدة البيانات أو تغطية عمياء شاملة خاصة بنظام إدارة قواعد البيانات (DBMS).
A05 حقن SQL الأعمى: التوقيت التحقق الاختياري تمكين تحقيقات التوقيت المتكررة بموافقة صارمة. تتم مقارنة ثلاثة توقيتات نظيفة مع ثلاثة تحقيقات SLEEP على نقطة الإدراج الأولى. بناء جملة SQL ضيق وتوقيت إرشادي؛ يمكن أن يؤدي الارتعاش وWAFs ولهجات قاعدة البيانات المختلفة إلى إخفاء النتيجة أو تقليدها.
A05 حقن NoSQL فحص نشط تمكين حقن NoSQL لتوقيعات خطأ MongoDB/BSON المتكررة. يحاول التحقق من التوقيت الاختياري أيضًا إجراء تأخير MongoDB $where على أجسام JSON. لا يوجد تجاوز عام للمصادقة المستندة إلى المشغل، أو استخراج NoSQL أعمى أو تغطية لكل محرك NoSQL.
A05 البرمجة النصية عبر المواقع المنعكسة (XSS) فحص نشط تمكين XSS المنعكس. تحدد علامة الانعكاس الفريدة وتحقيقات سياق HTML الخاملة المتكررة العلامات ذات المظهر القابل للتنفيذ. أدلة سياق HTML هي المرشحة. ولا يقوم بإنشاء تنفيذ البرنامج النصي أو تجاوز سياسة أمان المحتوى.
A05 DOM XSS من استعلام URL أو مدخلات الأجزاء التحقق الاختياري تمكين التحقق المباشر من DOM XSS والموافقة على الأذونات العدوانية. يجب تنفيذ قطعتي كناري طازجتين في نفس علامات تبويب متجر ملفات تعريف الارتباط التي يمكن التخلص منها؛ يجب أن تظل السيطرة سلبية. مدخلات URL المقيدة فقط. تظل CSP والتبعيات مفروضة؛ المهلات والموارد المحظورة تترك فجوات.
A05 DOM XSS من تدفقات postMessage أو التخزين أو البيانات العشوائية غير مغطى قد تحدد تلميحات المصدر/المصدر السلبي أنماط JavaScript المضمنة القريبة للمراجعة. لا يوجد تتبع عام للشوائب أو إنشاء رسائل عشوائية أو اختبار تنفيذ مصدر التخزين.
A05 XSS المخزن والحقن من الدرجة الثانية متعدد الخطوات غير مغطى قد تحتوي الصفحة التي تمت زيارتها على تعليمات برمجية مشبوهة أو مرشح منعكس. لا يوجد ارتباط عام بين الكتابة والتخزين والقراءة أو إعادة تشغيل سير العمل أو التحقق من تنفيذ الحمولة النافعة المخزنة.
A05 حقن القالب من جانب الخادم (SSTI) فحص نشط تمكين حقن قالب الخادم. يجب أن تتكرر النتائج الحسابية العشوائية ذات العلامات الفريدة مقابل عناصر التحكم. عائلات التعبير المدعومة فقط؛ لا يتم تغطية تنفيذ القالب الأعمى وكل محرك قالب.
A05 حقن التعليمات البرمجية من جانب الخادم فحص نشط تمكين حقن التعليمات البرمجية من جانب الخادم. تميز طيور الكناري JavaScript/PHP المحسوبة التقييم عن الانعكاس البسيط. مجموعة لغة/سياق صغيرة؛ ليس اختبارًا عالميًا لتنفيذ التعليمات البرمجية عن بُعد.
A05 حقن أوامر نظام التشغيل التحقق الاختياري تمكين مؤشرات أوامر نظام التشغيل لتحقيقات إخراج المعرف المتكررة. يمكن أن تقوم تحقيقات الأوامر الاختيارية مع موفر OAST المستمع بربط رد اتصال DNS. يتطلب سياق أمر متوافقًا، ولعمليات رد الاتصال، يتطلب الخروج المستهدف. لا رد الاتصال لا يؤسس السلامة.
A05 CRLF / حقن رأس الاستجابة فحص نشط تمكين حقن رأس الاستجابة. يجب أن تتكرر علامة رأس الاستجابة التي تم إنشاؤها وأن تكون غائبة عن عناصر التحكم. يحد التعامل مع عنوان URL/الرأس في المتصفح من الحمولات. لم يتم إنشاء تقسيم الاستجابة الأولية وتسميم ذاكرة التخزين المؤقت وتأطير الهجمات.
A05 LDAP، XPath ولغات الحقن الأخرى غير المنفذة غير مغطى يمكن أن تساعد الحمولات المخصصة أو التشويش التلقائي أو القالب الذي تمت مراجعته في إجراء تحقيق منفصل. لا يوجد أداة تحقق مدمجة خاصة باللغة؛ اختلاف الاستجابة ليس تأكيدا.
A01 اجتياز المسار / إدراج الملف المحلي فحص نشط تمكين اجتياز / إدراج الملف. يجب أن تتكرر تواقيع محتوى الملف المدعومة على نقاط الإدراج المكتشفة. لا يغطي كل ترميز أو نظام تشغيل أو تضمين عن بعد أو ملف عشوائي. لا يوجد دليل جرد القوة الغاشمة.
A01 تزوير الطلب من جانب الخادم (SSRF) التحقق الاختياري تمكين SSRF وOAST مع موفر معتمد يمكن الوصول إليه. يسجل الارتباط الدقيق للمسبار تفاعل DNS/HTTP. الاختلافات في استجابة العنوان الداخلي هي مجرد تلميحات. يؤدي رد الاتصال إلى إنشاء تفاعل، وليس الوصول الداخلي أو سرقة البيانات؛ قد يقوم الوسطاء بحل الحمولات.
A01 IDOR / ترخيص الكائن أو الوظيفة المكسورة المؤشرات فقط قم بتمكين المقارنة مع الجلسة B باستخدام حاوية Firefox مميزة/مخزن ملفات تعريف الارتباط الخاص. ما يصل إلى عشرة طلبات قراءة تقارن الحالة وتجزئات النص. لا توجد ملكية كائن أو نموذج دور متوقع؛ الصفحات العامة المتطابقة يمكن أن تكون مشروعة. لا يوجد دليل عام على تصعيد الامتياز.
A01 تزوير الطلب عبر المواقع (CSRF) المؤشرات فقط تقارير مراجعة النماذج تنشر النماذج دون حقول الرمز المميز المعترف بها وتتحقق من سمات ملفات تعريف الارتباط المرئية. لا يوجد أي استغلال عبر المواقع أو اختبار التحقق من صحة الرمز المميز للخادم. يحتاج SameSite والعناوين المخصصة وعناصر التحكم في سير العمل إلى مراجعة يدوية.
A01 استغلال تقاسم الموارد عبر الأصل (CORS). المؤشرات فقط تقوم مراجعة CORS بفحص رؤوس الأصل المسموح به وبيانات الاعتماد. لا يوجد اختبار تعسفي لانعكاس الأصل أو التحقق من قراءة بيانات أصل المهاجم. تم رفض أحرف البدل التي تحتوي على بيانات الاعتماد بواسطة المتصفحات.
A01 فتح إعادة التوجيه فحص نشط تمكين عمليات إعادة التوجيه المفتوحة. يجب تكرار الوجهة التي تم إنشاؤها .غير صالحة في رأس الموقع. لا يتم اتباع الوجهات الخارجية. لا يتم تغطية عمليات إعادة توجيه JavaScript وعمليات إعادة توجيه تسجيل الدخول متعددة الخطوات وكل تجاوز لتطبيع عنوان URL.
A01 عزل المستأجر وتصعيد الأدوار وتفويض سير العمل غير مغطى يمكن أن توفر مقارنة الجلسات والطلبات المستوردة دليلاً للمحلل. لا يوجد فهم لملكية المستأجر أو الأدوار أو تحولات الحالة أو الإجراءات التجارية المسموح بها.
A02 رؤوس الأمان مفقودة وضعف CSP ودفاعات Clickjacking المؤشرات فقط تقوم مراجعة الرأس السلبية أثناء الفحص بفحص CSP والتقييم غير الآمن وسياسة التأطير والتعرف على الاستجابات التي تمت ملاحظتها. الدفاعات المفقودة هي إشارات تصلب. لم يتم تحديد قابلية الاستغلال واكتمال السياسة وتأثير معالجة واجهة المستخدم.
A02 قوائم الدليل، والكشف عن المصدر/التكوين، وآثار التصحيح المؤشرات فقط تتعرف المراجعة السلبية على علامات القائمة ومصدر PHP وتعيينات مفاتيح التكوين وتتبعات المكدس المحددة في المحتوى الذي تم إرجاعه. المحتوى والتوقيعات التي تمت ملاحظتها فقط؛ لا يوجد ملف نسخ احتياطي شامل أو اكتشاف سري أو مخفي للمسؤول.
A02 حقن كيان خارجي XML (XXE) التحقق الاختياري قم بتمكين XXE وموفر OAST للاستماع بموافقة صارمة. يتم استبدال نص طلب XML بخاصية رد الاتصال للكيان الخارجي. يتطلب طلب XML المجرد. لا يوجد محلل شامل أو SOAP أو قراءة الملفات أو كيان المعلمة أو تغطية الاستخراج الأعمى.
A02 طرق HTTP الخطيرة المؤشرات فقط تمكين طرق HTTP المعلن عنها. تقوم OPTIONS بتسجيل رأس السماح بالاستجابة. لا يحاول كتابة PUT/DELETE غير المصرح به أو إثبات أن الأساليب المعلن عنها قابلة للاستغلال.
A02 معالجة معلمات الاستعلام المكررة المؤشرات فقط تمكين معالجة معلمات الاستعلام المكررة لمقارنات الاستجابة المتكررة من الدرجة الأولى/الأخيرة. لا يثبت اختلاف التحليل تجاوز WAF، أو فشل التحكم في الوصول، أو عدم توافق الوكيل/الواجهة الخلفية.
A02 أذونات السحابة وخدمات الإدارة المخفية وتكوين الواجهة الخلفية غير مغطى توفر بصمات الأصابع وطرق عرض الهيكل فرضيات مرئية للمتصفح. لا يوجد وصول إلى الحساب السحابي أو تدقيق البنية التحتية أو فحص تكوين الخادم أو اكتشاف شامل للشبكة الداخلية.
A03 تبعيات جافا سكريبت للمتصفح الضعيفة المعروفة التحقق الاختياري قم بتمكين SCA لمكتبة العميل من مقارنة إصدارات الأصول التي تمت ملاحظتها مع قاعدة البيانات الاستشارية المجمعة الصغيرة. ارتباط الإصدار/التوقيع فقط؛ لم يتم التحقق من المنافذ الخلفية والتعليمات البرمجية الضعيفة التي يمكن الوصول إليها وأشجار التبعية الكاملة والأصول غير المرئية.
A03 CVEs تبعية الخادم ونقاط الضعف في المنتج تعتمد على القالب تتطلب المرحلة التلقائية لمكافحة التطرف العنيف قوالب مستوردة مؤهلة؛ يتم تشغيل طلباتهم المؤلفة والمطابقات فقط. تتطلب Native Nuclei محركًا منفصلاً وموافقة. مطابقات البصمة/الاستشارية وحدها هي المرشحات. لا يوفر اثنان من المجتمعات المبتدئة المجمعة تغطية شاملة لمكافحة التطرف العنيف.
A03 الحزم المخترقة وCI/CD وتحديثات سلسلة التوريد الضارة غير مغطى يمكن لأسماء التبعيات أو الإصدارات أن تساعد في إنشاء تعليمات برمجية منفصلة وبناء المراجعة. لا يوجد اكتمال SBOM أو تدقيق المستودع/البناء أو أصالة الحزمة أو التحقق من سلسلة التوقيع.
A04 نماذج كلمة مرور HTTP وHSTS ومراجع الموارد غير الآمنة المؤشرات فقط تتعرف عمليات التحقق السلبية على نماذج كلمة المرور باستخدام HTTP/GET وغياب HSTS وموارد HTTP المحددة المشار إليها بواسطة ترميز HTTPS. ليس اكتشافًا شاملاً للبيانات الحساسة؛ لا يثبت تعرض البيانات أثناء الراحة أو تقييم جميع سلوكيات النقل.
A04 بروتوكولات/أصفار TLS ضعيفة وإدارة المفاتيح والتشفير في حالة عدم النشاط غير مغطى يوفر المتصفح اتصال TLS العادي الخاص به. لا يوجد تعداد للتشفير/البروتوكول، أو مخزون الشهادات، أو مراجعة تصميم التشفير، أو تدقيق تجزئة كلمة المرور، أو الوصول إلى المفتاح من جانب الخادم.
A06 منطق الأعمال والتلاعب في الدفع/الأسعار وإساءة استخدام سير العمل غير مغطى تساعد الطلبات التي تمت ملاحظتها والمكرر في الاختبار اليدوي. لا يوجد نموذج للأسعار الصحيحة أو أرصدة الحسابات أو قواعد العمل أو أمر المعاملة أو سلوك التطبيق المقصود.

تفسير تغطية التشغيل الفعلية

تشتمل الخريطة المرجعية الكاملة لـ WSTG على مجموعات فرعية آلية وعمل مساعد وتقييم يدوي. في تغطية المدخلات الفعلية:

  • مكتمل يعني أن القاعدة المطبقة انتهت على هذا الإدخال، وليس أن الإدخال آمن.
  • جزئي يعني تنفيذ بعض الأعمال ولكن هناك حدًا أو انقطاعًا أو حالة أخرى حالت دون إكمالها.
  • تم تخطيه يعني أن القاعدة/الإدخال لم يتم تشغيله؛ فحص السبب.

يمكن أن يؤدي WAF، أو الدور المفقود، أو الجلسة غير الصالحة، أو سير العمل المخفي / الذي لم تتم زيارته، أو نص الطلب غير المتاح، أو CSP أو الميزانية المستنفدة إلى ترك المدخلات الضعيفة دون اختبار. لا يؤدي إقران الوكيل الأصلي إلى إزالة هذه الحدود من الماسح الضوئي المدمج. إن إصدار CVE الذي تمت ملاحظته أو الرأس المفقود أو الاستجابة المختلفة لا يعد بمثابة استغلال تلقائيًا.

اجتاز الإصدار 2.18.1 192 اختبارًا آليًا للوحدة/الانحدار، وثمانية اختبارات حقيقية لـ Chrome وثمانية اختبارات حقيقية لـ Firefox، بما في ذلك التحقق من ZIP/YAML CSP وحركة مرور ZAP الأصلية مقابل تثبيتات SQLite المملوكة. يتم التحقق من مكتبات المتصفح الرسمية الخاصة به بايت مقابل بايت، كما أن إعادة بناء المصدر النظيف تعيد إنتاج Firefox XPI تمامًا. تتحقق هذه الاختبارات من صحة سلوك التنفيذ المسمى؛ ولا تظهر اكتشافًا لكل تحديات Juice Shop أو WebGoat أو bWAPP أو NodeGoat. تتحقق نتيجة ZAP SQLi الخارجية من مسار الوكيل، وليس استدعاء Longshot عبر جميع الثغرات الأمنية.

تخزين المتصفح وملفات الجلسة الاختيارية

يظل تخزين المتصفح نشطًا بشكل مستقل عن أي من الجسرين المحليين. فهو يحتفظ بسجل الملف الشخصي والنتائج والمراجعات والمخزون والخيارات. يمكن الاحتفاظ بهيئات الاستجابة من خلال تنقيحها بأقصى جهد؛ غالبًا ما تحتوي حركة المرور التي تتم مراقبتها بواسطة المتصفح على بيانات وصفية بدون نص تم التقاطه.

لنقاط فحص الملفات التلقائية:

  1. التسجيل/الاتصال واجهة برمجة تطبيقات الوكيل، وليس فقط جسر المتصفح.
  2. مفتوح الإعدادات ← جلسات التقييم ← التعليمات.
  3. أدخل المطلقة مجلد الجلسة على كمبيوتر Agent API.
  4. تمكين حفظ ملفات الجلسة تلقائيًا واختر حفظ إعدادات الجلسة.
  5. استخدم احفظ الجلسة الآن لنقطة تفتيش فورية؛ تؤدي التغييرات العادية أيضًا إلى عمليات الحفظ.
  6. استخدم تصدير الجلسة الحالية / استيراد ملف الجلسة للنقل اليدوي؛ لا يتطلب الاستيراد اليدوي المضيف الأصلي.

تستخدم الملفات معرفات ملفات التعريف الثابتة مع .longshot.json، مما يسمح بملفات تعريف واضحة لأصل واحد. وهي عبارة عن أرشيفات تقييم قابلة للقراءة وغير مشفرة ويمكن أن تحتوي على بيانات التطبيق والنماذج المؤلفة والهيئات المحتجزة. يتم استبعاد ملفات تعريف الارتباط التي يديرها المتصفح ورموز الموفر ومنح التنفيذ.

عمليات الكتابة هي نقاط تفتيش ذرية للملف الخاص. يمكن للإنهاء المفاجئ استرداد آخر عملية حفظ مكتملة فقط. تتم مقاطعة عمليات المسح الجارية المستعادة. إذا تم قطع اتصال الجسر، يستمر تخزين المتصفح وينتظر حفظ الملف؛ يمكن أن تتطلب نقاط التفتيش الممكّنة التي لم يتم حلها إعادة الاتصال أو تعطيل حفظ الملف قبل تبديل الأهداف. الحد الأقصى لحجم ملف الجلسة هو 256 ميجابايت مع وجود خطأ صريح.

يختلف تقييم تصدير الأرشيف عن تحميل التكوين في جسر المتصفح. الأول يحفظ أدلة/خيارات التقييم؛ هذا الأخير يحفظ إعدادات الوكيل الأصلية.
