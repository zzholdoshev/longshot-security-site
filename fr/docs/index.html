Longshot 2.18.1 — guide et référence des fonctionnalités

Mis à jour le 10 novembre 2026 pour Longshot 2.18.1 (éditions Firefox et Chrome) et ses proxy d'outil HTTP/HTTPS natif. Ceci remplace le didacticiel général 2.11.1. Les instructions ci-dessous décrivent l'implémentation livrée, y compris ses limites ; les anciens exemples de ponts ne sont pas interchangeables avec cette version.

Longshot est un atelier de session de navigateur pour l'évaluation d'applications Web autorisées. Il combine la découverte, son propre scanner actif JavaScript, des outils HTTP manuels, des modèles importés, une révision des résultats et des rapports. Le Browser Bridge en option permet aux outils externes d'utiliser les valeurs de session Firefox sélectionnées tout en envoyant leurs propres requêtes HTTP natives.

Un premier passage utile est : ouvrez l'application → connectez-vous → lancez Longshot à partir de cet onglet → Connectez-vous → validez la session → découvrez les entrées → exécutez les vérifications sélectionnées → examinez les preuves.

Si votre application traite de l’argent ou des données sensibles, faites réaliser un audit professionnel par une équipe de cybersécurité, y compris si elle a été développée avec l’IA. Le scan d’une extension ne remplace ni les tests d’autorisation, ni l’examen de la logique métier, ni une évaluation indépendante. Une liste de résultats vide ne prouve pas que l’application est sûre.

Ce document explique les commandes ; sa mise à jour n'installe pas de logiciel, n'enregistre pas d'hôte, ne modifie pas les paramètres du navigateur et n'exécute aucune analyse. Exécutez des exemples uniquement par rapport à votre objectif d’évaluation autorisé. L'échantillon http://localhost:8080 est un exemple de cible locale, pas un service Longshot intégré.

Codée par l’IA. Mise en ligne. Et la sécurité ?

Imaginez ceci : votre application est mise en ligne, un attaquant trouve la faille et un utilisateur ouvre son compte avec un solde nul. Tout leur argent a disparu.

Le code avait l'air convaincant. L'IA a déclaré que cela semblait sécurisé. Ce n'était pas suffisant.

Les réponses d’un modèle peuvent varier. Il peut manquer une faille tout en se montrant très sûr de lui. Prenez un deuxième avis avec Longshot.

Longshot transforme Firefox en un atelier de sécurité pour les applications Web que vous créez. Exécutez des vérifications répétées sur l'application en cours d'exécution, inspectez les preuves HTTP et étudiez les faiblesses avant que vos utilisateurs n'en paient le prix.

Couverture des chèques prise en charge Injection SQL/NoSQL, injection de code et de modèles côté serveur, candidats XSS réfléchis, traversée de chemin/inclusion de fichiers, redirections ouvertes et injection CRLF/en-tête, avec vérification DOM XSS en direct en option. Examen en-têtes de sécurité faibles, politiques de cookies et CORS, configuration exposée et divulgations d'erreurs, avec des vérifications facultatives pour d'autres classes d'attaque.

Commencez à partir de l’onglet du navigateur que vous utilisez déjà. Conservez les cookies en direct, configurez la validation de session, récupérez après la perte de session et organisez les paramètres, l'historique et les résultats de chaque cible.

Confiez des tâches à l’IA. Vérifiez son travail. Connectez un agent via MCP pour exécuter des contrôles autorisés et examiner les résultats. Utilisez le Browser Bridge natif pour intégrer ZAP, sqlmap, curl, ffuf ou wget dans la session de navigateur connectée sans copier manuellement les valeurs des cookies. Les outils envoient leurs propres requêtes HTTP et charges utiles ; Les remplacements des cookies du navigateur sont activés par défaut et peuvent être désactivés.

Les utilisateurs avancés peuvent importer des fichiers compatibles Modèles CVE et corréler Rappels OAST avec les sondes qui les ont provoqués. Examinez et enregistrez vos verdicts, puis exportez des données riches en preuves Rapports HTML, JSON, CSV ou SARIF, avec sortie impression/PDF. Expliquer les résultats avec le visionneuse cinématique, y compris le contexte de page CSS/JavaScript en direct, les éléments 3D animés, les commandes de pause et plein écran. Choisissez un thème précis et personnalisez le mouvement et le son en fonction de votre espace de travail.

La confiance ne suffit pas. Vérifiez les faits. Longshot.

Notes de publication

L'histoire de la perte de compte est hypothétique et ne constitue pas une affirmation concernant un client réel ou une garantie que Longshot prévient les pertes financières. L'extension effectue des évaluations, et non un blocage continu des attaques. Les résultats nécessitent un examen ; le tableau de couverture explique le support limité et les lacunes manuelles uniquement. L'analyse DOM inclut des indicateurs et des canaris d'exécution pris en charge, et non une couverture universelle des exploits DOM. La séquence cinématographique explique les preuves ; il n'ajoute pas de preuve d'exploitation.

MCP et Browser Bridge nécessitent une configuration locale. Le proxy de l'outil natif utilise un processus Node/Python/mitmproxy distinct, et l'interception HTTPS nécessite la configuration de confiance de l'outil pour l'autorité de certification de l'adaptateur. Il s’agit d’un transport HTTP analysé, et non d’un TCP brut transparent en octets. Les remplacements de cookies peuvent être désactivés ; un cookie de navigateur ou un agent utilisateur ne garantit pas une mise en réseau identique au navigateur ou l'acceptation du WAF. Le ZAP externe reste installé séparément. L'exécution du modèle dépend de la compatibilité/des durées d'exécution ; OAST nécessite un fournisseur configuré. La validation de l’authentification nécessite un point de terminaison/marqueur protégé significatif. Les profils cibles séparent les données d'évaluation ; l'onglet/conteneur fournit la session de cookie.

Pour les applications traitant des données ou de l'argent sensibles, engagez une équipe de cybersécurité et utilisez Longshot dans le cadre de l'évaluation. Utilisez-le uniquement sur les applications que vous possédez ou que vous êtes autorisé à tester.

Si vous réutilisez des images de campagne générées précédemment, étiquetez-les comme compositions et utilisez de véritables captures d'écran actuelles partout où une interface utilisateur au pixel près est requise. Ce didacticiel relie les captures d'écran de validation 2.18.1 réelles dans la section apparence ; il n'inclut pas de nouveau pack de campagne de huit images et ne revendique pas l'approbation d'un tiers.

Installez l'édition Chrome

  1. Téléchargez le Code postal Chrome à partir des liens de version ci-dessus/ci-dessous et extrayez-le dans un dossier que vous conservez.
  2. Ouvert chrome://extensions, activez Mode développeur, sélectionnez Chargement déballé, puis choisissez le dossier extrait contenant manifest.json.
  3. Ouvrez votre application autorisée, connectez-vous, lancez Longshot à partir de cet onglet et connectez-vous.
  4. Gardez l'onglet du plan de travail ouvert pendant la numérisation et le couplage natif. Sa fermeture met fin au travail du moteur sous tension ; les preuves enregistrées restent et sont restaurées sans rejouer les demandes incertaines.
  5. Pour le démarrage d'un proxy d'outil natif, utilisez l'origine exacte indiquée par Chrome, telle que chrome-extension://YOUR_INSTALLED_ID, plutôt qu'un Firefox moz-extension:// origine. Le proxy utilise de véritables URL cibles ; aucune entrée de fichier hosts n'est nécessaire.

Enregistrement de l'API/MCP de l'agent Chrome

À partir de l'extraction des sources complètes conservées, après avoir installé la dépendance d'assistance épinglée :

npm --prefix native-bridge ci --omit=dev
node bridge/bin/longshot-bridge install --browser chrome \
  --extension-id YOUR_INSTALLED_32_LETTER_ID \
  --port 8775 --data-dir /absolute/private/longshot-chrome
node bridge/bin/longshot-bridge mcp \
  --port 8775 --data-dir /absolute/private/longshot-chrome

Pour une utilisation en chrome --browser chromium. Utilisez l'identifiant réel dans chrome://extensions; inscrivez-vous à nouveau si l'installation de l'édition magasin donne un identifiant différent. Le répertoire port/data séparé évite une collision avec un hôte Firefox. Cette API d'agent est distincte du proxy de l'outil HTTP (ports par défaut 8900/8901). Linux est la plate-forme hôte native testée ; L'enregistrement macOS est implémenté mais n'a pas été testé ici, et aucun programme d'installation d'hôte natif Windows n'est fourni.

La configuration détaillée du Browser Bridge est également disponible dans le fichier de l'extension. Pont de navigateur → Informations dialogue. La version longue du README et les nouveaux documents de plateforme/confidentialité sont en anglais ; La sélection groupée de la langue de l'interface utilisateur ne traduit pas les preuves cibles, les charges utiles ou les exemples exécutables.

Installer ou mettre à jour dans Firefox Nightly

Utilisez le 2.18.1 XPI, pas un ancien adaptateur ZIP renommé en module complémentaire. Extrayez l'archive source correspondante dans un dossier que vous conservez en place, affiché comme /path/to/longshot dans des exemples. Ne déplacez pas un hôte natif enregistré sans l'enregistrer à nouveau.

Les fichiers de version sont :

  • FirefoxXPI
  • Code postal Chrome
  • ZIP source de l'extension correspondante
  • Notes de version et sommes de contrôle
  • Adaptateur natif ZIP : téléchargez-le dans Browser Bridge ; il est inclus dans chaque package d’extension.

Ce sont des versions de développement/soumission. La signature de la boutique Firefox et les approbations des deux marchés sont en attente. Suivez la procédure de chargement de développement applicable plutôt que d'attendre que le XPI non signé s'installe normalement dans la version Firefox.

Le manifeste nécessite Firefox 140 ou une version ultérieure. Les vérifications d'intégration de la version ont utilisé le bureau Firefox 159 sous Linux. La prise en charge de la plate-forme/du runtime pour les assistants facultatifs est distincte de la prise en charge des extensions de base.

Pour une installation temporaire non signée :

  1. Ouvert about:debugging#/runtime/this-firefox.
  2. Choisissez Charger le module complémentaire temporaire et sélectionnez le XPI.
  3. Confirmez la version affichée de Longshot, puis ouvrez la cible et lancez son bouton de barre d'outils.
  4. Rechargez l'extension après avoir remplacé une version de développement décompressée.

Un module complémentaire temporaire disparaît après le redémarrage de Firefox. C'est prévu; ce n'est pas l'adaptateur qui supprime l'extension. Une distribution publique persistante nécessite la signature de Mozilla. Nightly propose des options de développement non signées supplémentaires décrites par Le guide de signature de Mozilla; le chargement temporaire ne nécessite pas de modifier ces paramètres. Voir installation temporaire.

Le XPI regroupe l'adaptateur natif sous forme d'archive téléchargeable. Il ne peut pas démarrer un processus Node/Python arbitraire ou installer l'hôte natif uniquement via les modules complémentaires Firefox. Le démarrage du proxy et l'enregistrement de l'API de l'agent sont des étapes de configuration locale facultatives distinctes.

Prise en main et sessions cibles

Connectez l'onglet de droite

  1. Ouvrez la cible autorisée dans Firefox par exemple http://localhost:8080.
  2. Connectez-vous avec le compte de test prévu et complétez n'importe quel défi de navigateur.
  3. Lancer Longshot à partir de cet onglet cible. Gardez l'onglet Application ouvert.
  4. Vérifiez l'adresse cible et choisissez Se connecter.
  5. Utiliser Commencer dans l’en-tête de la procédure pas à pas en huit étapes mise en évidence. Il peut être rejoué ; il ne démarre pas les analyses ni ne modifie les paramètres lui-même.
  6. Parcourez les pages d'applications représentatives afin que Longshot puisse observer les itinéraires et les entrées utiles.

Une origine cible se compose d’un schéma, d’un nom d’hôte et d’un port. http://localhost:8080, http://127.0.0.1:8080 et https://localhost:8080 sont d’origines différentes, même s’ils accèdent finalement au même service. Connectez-vous et utilisez l’adresse exacte prévue pour l’évaluation. Une adresse IP observée derrière un nom d'hôte ne devient pas automatiquement une cible autorisée supplémentaire.

Profils et comptes

Cibles sépare l'historique, les résultats, le journal des demandes, les points finaux découverts, les examens et la configuration de l'analyse. Le retour à un profil restaure les données d'évaluation, et non une ancienne session de navigateur authentifiée. Les profils explicites peuvent partager une origine.

Deux onglets Firefox ordinaires partagent normalement des cookies. Utilisez des conteneurs indépendants ou un magasin de cookies privé distinct pour des identités de test véritablement différentes. Changer de profil ne crée pas de deuxième session de compte. La comparaison de session B nécessite la même origine cible et un magasin distinct.

Découverte de la lumière et analyse active ciblée

Premier passage : découverte et examen passif

  1. Ensemble Requêtes par seconde à 0,5-1, profondeur d'exploration à 1 et nombre maximal d'URL découvertes à 25-50.
  2. Partir Résultats maximum, Agressif, phase automatique CVE, OAST et exécution native désactivées.
  3. Ensemble Fuzz automatique → Désactivé. Laissez les clics/défilement de page et les tests DOM/timing/rappel en direct désactivés.
  4. Sélectionnez les groupes de présentation passifs : en-têtes, cookies, divulgation, formulaires, examen des sources/récepteurs DOM et CORS.
  5. Choisissez Araignée seulement et commencer.
  6. Inspecter Plan du site, Historique HTTP, Explorateur d'API, Pile de serveur et Résultats.

Spider suit les liens/formulaires découverts dans le champ d'application sans soumettre d'écritures de formulaire. Il ne connaît pas tous les points de terminaison cachés. Les requêtes GET peuvent toujours avoir des effets secondaires spécifiques à l’application ; La « méthode de lecture » n’établit pas de cible sans effets secondaires.

Deuxième passage : une évaluation active limitée

  1. Garder Fuzz automatique → Désactivé pour rendre les règles actives intégrées plus faciles à examiner séparément.
  2. Sélectionnez les vérifications actives de présentation pertinentes, telles que l'injection SQL et Reflected XSS.
  3. Utilisez de petites limites, par exemple 150 requêtes actives, 10 URL actives et cinq paramètres actifs.
  4. Choisissez Chèques actifs uniquement pour réutiliser la page actuelle et l'inventaire enregistré, ou Spider + contrôles actifs à découvrir en premier.
  5. Commencez, examinez toute approbation requise et surveillez le nombre d’activités et de demandes.
  6. Inspectez la demande de chaque constatation, la ligne de base, les preuves de sonde/contrôle répétées, le verdict et la confiance.
  7. Ouvert Contrôles WSTG → Couverture réelle des entrées pour voir les travaux terminés, partiels et sautés.

Auto-fuzz Off ne désactive pas les vérifications actives. Les règles SQLi/XSS/SSTI et autres règles dédiées génèrent leurs propres sondes. À l’inverse, cocher une règle active ne fournit pas une entrée manquante et ne permet pas à une exécution Spider uniquement d’exécuter la phase active générique.

Options agressives et approbation d'exécution

Agressif active des méthodes/capacités explicitement approuvées ; il n'effectue pas tous les contrôles et ne garantit pas des preuves plus solides.

  1. Découvrez les entrées et validez d’abord l’authentification.
  2. Activez uniquement les options avancées nécessaires et les autorisations d’écriture/téléchargement/suppression.
  3. Enregistrer les options de numérisation.
  4. Choisissez Examiner/approuver la prochaine course agressive.
  5. Passez en revue la cible, les fonctionnalités, les autorisations de méthode et les budgets.
  6. Cliquez Approuver cette prochaine exécution. Cette action utilisateur demande toutes les autorisations Firefox combinées manquantes et crée l'autorisation de prochaine exécution.
  7. Démarrez l’exécution avec la configuration révisée.

La subvention est à usage unique, expire après 30 minutes et est invalidée par les modifications pertinentes de cible/configuration/paramètre de demande. Une nouvelle analyse nécessite normalement une nouvelle subvention. La sauvegarde des options inachevées est autorisée ; le démarrage ou l’approbation valide les champs obligatoires.

Firefox nécessite permissions.request() provenir directement d’une action réelle de l’utilisateur. La modification d'un paramètre n'est pas une raison pour accorder des autorisations arbitraires en arrière-plan. Si l'autorisation est refusée, vérifiez la fonctionnalité exacte, réessayez à partir du bouton d'approbation ou désactivez cette fonctionnalité. Les invites normales d’autorisation du système d’exploitation/navigateur restent en dehors de l’automatisation du DOM de l’extension.

Les résultats maximaux sont un large préréglage

Ce préréglage active de nombreuses phases, notamment la vérification avancée, la comparaison OAST et Session B, et étend plusieurs budgets. Il ne s’agit pas d’un commutateur « tout trouver ». Il ne crée pas de compte OAST, ne remplit pas le domaine d'URL/de rappel du fournisseur, ne sélectionne pas une session B valide, n'installe pas Nuclei ou n'authentifie pas les rôles manquants.

Si l'approbation signale des champs OAST vides ou une session B manquante, configurez-les ou désactivez ces options. Ceci est distinct de la validité de l'URL cible.

Deux commandes d'injection de commande

Présentation → Indicateurs de commande du système d'exploitation permet des sondes de sortie de commande directes orientées Unix. Il est désactivé par défaut. Options d'analyse → Sondes de commande contrôle l'itinéraire de rappel aveugle supplémentaire lorsque OAST écoute. Une case à cocher ne configure pas automatiquement l'autre chemin. Passez en revue les exigences d’autorisation pour l’exécution réelle.

Fuzzer de requête manuelle

  1. Connectez la cible et choisissez une URL étendue. URL relatives telles que /search?q=apple sont acceptés contre l’origine connectée.
  2. Entrez le nom du paramètre de requête existant ou choisissez Utiliser à côté d'une entrée découverte.
  3. Choisissez une classe de charge utile et une mutation de valeur.
  4. Pour Charges utiles personnalisées téléchargées par l'utilisateur, activez d'abord un pack personnalisé approprié.
  5. Choisissez Exécuter le fuzzer, puis inspectez la référence, la demande, le statut, la durée/le calendrier et les preuves.

Une URL, un paramètre ou un ensemble personnalisé vide manquant produit un message de validation spécifique. Changer une réponse à lui seul n’établit pas un défaut d’injection. La limitation du serveur peut arrêter le paramètre même s'il se produit sur la ligne de base.

Entrées découvertes par fuzz automatique

Utiliser Aperçu des entrées découvertes d'abord. Il lit l'inventaire enregistré et signale les demandes éligibles/ignorées sans envoyer de sondes. Le fuzz automatique n'a pas besoin des champs URL/paramètres du fuzzer manuel. Parcourez ou Spider d'abord si l'inventaire est vide.

Sélectionnez les classes de charge utile et choisissez les classes distinctes Auto-fuzz bouton. Inclure les corps de requête découverts démarre et nécessite une approbation Agressive et pour la prochaine exécution. Les formulaires liés à des jetons, les méthodes non prises en charge, les corps indisponibles et le XML sont ignorés par ce sélecteur d'entrée automatique. Les exclusions existantes, les limites de requêtes et le comportement de limitation s'appliquent toujours.

Les cases à cocher de classe disponibles sont SQLI, NOSQLI, CODE, XSS, SSTI, TRAVERSAL, COMMAND, SSRF, REDIRECT, CRLF et CUSTOM. Les nouvelles valeurs par défaut activent SQLI, SSTI, TRAVERSAL, REDIRECT et CRLF. La boucle générique ignore SSRF ; utiliser Canaris SSRF / rappels pour sa vérification mise en œuvre. CUSTOM utilise les valeurs personnalisées saisies/activées et signale les différences de réponse de faible confiance, à moins qu'un comparateur dédié n'en établisse davantage.

Vos charges utiles et modèles importés

Télécharger des listes littérales

Sous Options d'analyse ou Fuzzer → Bibliothèque de sondes → Vos charges utiles et modèles CVE, choisissez la catégorie, puis Télécharger un fichier personnalisé.

Formulaires de liste acceptés :

  • .txt: une valeur littérale non vide par ligne ; les espaces et la casse sont préservés.
  • .json: un tableau de chaînes ou un objet contenant name, category et payloads.
  • Catégories : custom, waf, sqli, nosqli, code, xss, ssti, traversal, crlf, redirect, command.
{
  "name": "My SQL review probes",
  "category": "sqli",
  "payloads": ["'", "\"", "' AND 1=1 -- "]
}

Les packs sont spécifiques à une cible et initialement désactivé. Inspectez l’aperçu et activez explicitement le pack prévu. Les packs téléchargés activés nécessitent un mode agressif et une approbation ; le téléchargement seul ne fonctionne rien.

Limites : 256 Ko par fichier de charge utile, 200 chaînes par pack, 2 000 caractères par valeur et au maximum 10 packs/500 valeurs/512 Ko de configuration de pack par cible. Les chaînes en double dans un pack sont supprimées. Les méthodes, la portée, le budget et les protections SQL destructives existantes s'appliquent toujours.

Les packs catégorisés complètent les valeurs de classe intégrées. Les packs WAF nécessitent également des variantes intelligentes et des preuves de filtrage éligibles. Une charge utile personnalisée littérale n’est pas un outil de correspondance de sortie attendue ou un code d’extension exécutable. Le téléchargement d’un numéro CVE à lui seul ne peut pas vérifier ce CVE.

Importer des modèles de demande/matcher

Choisissez la catégorie de modèles CVE/Nuclei avant de télécharger YAML/YML/JSON ; la limite du fichier modèle est de 2 Mo. Examinez-le dans Modèles, y compris l'exécuteur testamentaire et la raison concrète Prêt/Bloqué. Les modèles importés utilisent la bibliothèque partagée ; les packs de charges utiles restent avec leur cible.

  • Exécuter sélectionné exécute directement les modèles sélectionnés et ne nécessite pas de phase automatique CVE.
  • Phase automatique CVE prend en compte les importations éligibles marquées/identifiées par CVE lors d’une analyse configurée.
  • Auto-fuzz génère des valeurs génériques ; il ne réécrit pas les charges utiles ou les matchers CVE créés.
  • Le JSON consultatif uniquement met en corrélation les preuves de produit/version. Il n’invente pas une demande d’exploit fonctionnelle.
  • Les modèles bruts, complexes, de code, sans tête, de fichier ou non HTTP peuvent nécessiter le moteur officiel distinct et des subventions supplémentaires, ou rester bloqués.

Importez les bundles d'assistance relative révisés avec les modèles qui en ont besoin. Un runtime natif indisponible, une demande hors de portée, une approbation manquante ou une fonctionnalité non prise en charge sont une raison d'inspecter, et non un test négatif réussi.

Browser Bridge : outil proxy natif

Ce qu'il envoie

Un outil externe génère la requête, y compris sa charge utile d'attaque, sa méthode, son corps et sa requête. L'adaptateur natif le transmet via mitmproxy, en appliquant uniquement les modifications configurées en matière de cookie/en-tête. C'est le cas pas demandez à Firefox d'effectuer une récupération au nom de ZAP ou d'un autre outil.

Cela préserve la sémantique HTTP native et la génération de charge utile de l'outil, mais pas les octets de fil d'origine arbitraires : mitmproxy analyse/sérialise HTTP et établit sa propre connexion TLS sortante. Une chaîne User-Agent de navigateur ne rend pas l’empreinte digitale TLS/réseau native identique à Firefox.

Non /etc/hosts une entrée est nécessaire. Confiance HTTPS

L'adaptateur génère sa propre autorité de certification locale sous le répertoire de données sélectionné, normalement :

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

Configurez le configuration de la confiance d'évaluation de l'outil externe avec le chemin du certificat public imprimé au démarrage. Ne partagez pas la clé privée et ne supposez pas que le magasin de confiance système/Firefox a été modifié. L'adaptateur n'installe son autorité de certification dans aucun des magasins de clés certifiées.

Pour les boucles :

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

Remplacer CURRENT_TOKEN et le chemin cible/certificat. Pour une cible locale HTTP uniquement, --cacert est inutile. --noproxy '' garantit que curl ne contourne pas silencieusement le proxy pour une cible de bouclage.

Il existe deux vérifications TLS distinctes :

  • Le client vérifie le certificat présenté par l'adaptateur. Configurez l'approbation du client avec l'autorité de certification de l'adaptateur.
  • L'adaptateur vérifie le véritable serveur en amont. tls.verifyUpstream la valeur par défaut est vrai. Client --cacert ne fournit pas d'autorité de certification d'origine privée à l'adaptateur.

Ne considérez pas la désactivation de la vérification comme une solution normale aux erreurs de certificat. Pour un luminaire détenu et auto-signé, tls.verifyUpstream:false est une exception d'évaluation explicite dans la configuration de l'adaptateur, suivie d'un redémarrage ; cela affaiblit ce contrôle séparé en amont. Voir comportement du certificat mitmproxy.

Remplacement des cookies et des en-têtes sans endommager les sondes

Comportement des cookies par défaut

Utiliser les cookies du navigateur et Enregistrer les mises à jour des Set-Cookies de réponse sont activés par défaut. User-Agent, Accept-Language et Authorization restent contrôlés par l’outil par défaut.

Pour une requête native, Firefox sélectionne les cookies applicables pour l'URL dans le magasin de cookies de l'onglet associé et dans la partition correspondante. Les autres conteneurs/magasins privés ne sont pas fusionnés. Les règles de domaine/chemin/sécurisé/expiration et l’ordre des chemins du même nom restent pertinents. Les valeurs sont fournies au proxy natif afin qu'il puisse construire l'en-tête Cookie sortant ; contrairement au chemin de récupération du navigateur supprimé, l'assistant natif gère donc les secrets de session en mémoire.

Avec cookies.mode:"replace", le fichier jar du navigateur fait autorité, y compris lorsqu'il est vide. Un cookie de navigateur supprimé du fichier jar est supprimé des demandes gérées ultérieures. Les noms explicitement protégés et les modifications d’outils détectées sont prioritaires. Avec mode:"merge", les cookies d'outils non liés peuvent rester pendant que les noms gérés par le navigateur sont mis à jour.

Les champs Response Set-Cookie sont appliqués individuellement au même magasin sélectionné à l'aide de l'API de cookies de Firefox, y compris les attributs Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition pris en charge. Les cookies invalides peuvent être rejetés ; inspecter les erreurs signalées. Les origines configurées supplémentaires ne reçoivent pas de cookies de navigateur ni d'en-têtes dérivés du navigateur.

Autorisation du navigateur et autres en-têtes

L'autorisation du navigateur est facultative via la configuration JSON. Il est capturé à partir d'une requête réelle par l'onglet cible associé uniquement après avoir activé le sourcing du navigateur. Il ne s'agit pas d'un lecteur automatique pour chaque jeton dans le stockage local ou dans la mémoire de l'application. Une requête ultérieure du navigateur peut être nécessaire avant qu’une valeur observée n’existe. La désactivation de l'autorisation du navigateur arrête la valeur capturée fournie par l'assistant.

Choisir le navigateur User-Agent ou Accept-Language modifie uniquement ces champs HTTP. Il n'exécute pas le JavaScript cible, n'actualise pas un jeton CSRF de corps, ne reproduit pas le TLS du navigateur et ne garantit pas l'acceptation du WAF. L'authentification liée à l'IP/à l'appareil et l'actualisation OAuth nécessitent toujours leur flux de travail d'application.

VHOST / Gestion des hôtes

L'assistant natif ne remplace pas un alias de pont interne dans le champ Hôte de l'outil. Laissez l'outil envoyer la valeur d'hôte nécessaire pour le test d'hôte virtuel autorisé. Pour HTTPS, la destination CONNECT reste la cible autorisée tandis que l'entête Host de l'outil peut être conservé.

La modification d’un en-tête Host n’accorde pas l’accès à une autre destination réseau. Un proxy inverse peut l'acheminer vers une autre application ; inclure ce comportement d'hôte virtuel dans l'autorisation de l'évaluation. Les octets d’en-tête mal formés et les trames conflictuelles se trouvent en dehors de ce proxy analysé.

Audit and privacy

Trafic natif affiche les métadonnées de la demande et les noms de champs modifiés/protégés. L'audit omet les valeurs secrètes des cookies/en-têtes, les valeurs et les corps des requêtes. Cela ne signifie pas que le proxy ne gère jamais les secrets : il doit les traiter pour envoyer du trafic authentifié. Les outils externes conservent leurs propres historiques/résultats, qui peuvent contenir ces valeurs.

Conservez les jetons de configuration privés, les clés CA et les répertoires de données hors des rapports/archives sources. Le téléchargement de la configuration avec des valeurs d'autorisation personnalisées peut créer un fichier contenant ces valeurs.

Exemple de bibliothèque standard Linux Python pour une cible locale en lecture seule ; il demande le jeton au lieu de le coder en dur et efface le contournement du proxy d'environnement pour ce processus :

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

Vérifiez la demande dans le trafic natif ; d'autres plates-formes peuvent avoir des règles supplémentaires de contournement du proxy système. Les clients HTTPS Python ont en outre besoin d'un ensemble de contexte SSL/CA qui fait confiance au certificat de l'adaptateur.

Pause et erreurs

Suspendre les requêtes natives bloque les nouvelles sorties natives. Les statuts d'authentification 401/419/440, HTTP 429, la fermeture d'onglets/les modifications hors origine ou les limites budgétaires peuvent également suspendre le travail. Reprendre après avoir vérifié l'onglet ne reprend qu'après avoir examiné l'état d'appairage.

Arrêter et déconnecter met fin au couplage du navigateur ; il ne met pas fin au processus Node démarré séparément. Utilisez Ctrl+C dans son terminal pour arrêter ce processus.

Les demandes en vol peuvent se terminer. Les clients proxy reçoivent des erreurs pour les travaux bloqués ; l'adaptateur ne suspend pas les processus d'outils arbitraires et ne relit pas leurs demandes. Inspectez les requêtes qui ont réussi et utilisez les propres contrôles de nouvelle tentative/reprise de l'outil. Le redémarrage/ré-appairage modifie le jeton et nécessite la mise à jour de l'authentification de l'outil.

401/419/440 peut être attendu lors de tests d'authentification délibérément négatifs. Si nécessaire, ajustez session.pauseStatuses pour cette exécution et ce redémarrage examinés ; l'adaptateur ne déduit pas si chaque échec d'authentification est une sonde intentionnelle.

Routage Tor et oignon

Les requêtes Longshot basées sur le navigateur suivent la mise en réseau du navigateur sélectionné. L'adaptateur natif est un processus différent et n'hérite pas des paramètres de proxy du navigateur Firefox/Tor.

CHAUSSETTES/Tor est désactivé par défaut dans la configuration native. Pour une évaluation d'oignon autorisée, utilisez un service SOCKS existant explicitement configuré avec une résolution de nom d'hôte à distance, par exemple ce remplacement s'il s'agit réellement de votre écouteur Tor local :

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

Cet exemple ne démarre pas Tor et n'établit pas que le port 9050 existe. Sélectionnez le service réellement configuré ; une instance du navigateur Tor peut utiliser un écouteur différent. Redémarrez l'adaptateur et ré-appairez. Un HTTP(S) upstream.url et routing.socks5 s'excluent mutuellement.

Le shim natif résout les noms d’hôtes via SOCKS et n’a pas de solution de repli directe et silencieuse. Sans route amont/SOCKS explicitement configurée, les destinations directes d'oignon sont rejetées avant le DNS cible. Une URL SOCKS peut également faire référence à un tunnel SSH autorisé ou à un autre service SOCKS5 ; ce n'est pas intrinsèquement une preuve du routage Tor.

Le partage de cookies ne rend pas l'adresse IP de sortie de la route native ou l'empreinte digitale TLS/navigateur identique à Firefox. Les défis ou la liaison de session peuvent le rejeter. Vérifiez l'itinéraire et la session prévue de manière indépendante.

Les noyaux natifs isolés lancés par l'API de l'agent sont différents : son relais intégré n'a pas de route Tor/SOCKS et bloque les cibles oignon avant le DNS du système. Utilisez des vérifications éligibles côté navigateur dans le navigateur prévu ou un outil externe configuré séparément via le proxy natif. Ne présumez pas que la case Nuclei hérite routing.socks5 à partir du pont de navigateur.

Connectez-vous et parcourez d'abord, puis choisissez Inspecter la page actuelle. Importer un fichier fourni par le développeur OuvrirAPI JSON description lorsqu'elle est disponible, jusqu'à 2 Mo. Il lit le JSON local, pas une page distante arbitraire ou un fichier YAML. Les références de spécifications locales et les exemples de requêtes/valeurs par défaut disponibles peuvent fournir des entrées concrètes prises en charge ; les valeurs/corps manquants et les constructions non prises en charge laissent des espaces.

Un point de terminaison est une adresse ; une opération est une adresse plus une méthode. Les entrées de requête apparaissent après ?, les entrées de chemin dans le chemin d'adresse et les entrées de corps dans le contenu soumis. Une opération répertoriée est un inventaire, et non une preuve que le compte courant peut accéder à chaque objet auquel il s'adresse.

Utiliser Répéteur à côté d'une opération GET/HEAD prise en charge pour préparer une requête sans l'envoyer encore. Vérifiez l'URL/la méthode/les entrées, puis envoyez-les délibérément. Les opérations d'écriture de stock uniquement nécessitent toujours que vous prépariez la demande appropriée et obteniez l'approbation d'écriture.

Répéteur et comparaison

Repeater effectue une nouvelle requête étendue à l'aide de la session de navigateur liée. GET/HEAD/OPTIONS utilise la route ordinaire. Les méthodes d'écriture, les modifications du corps et les capacités de destruction/téléchargement restent soumises à la politique et à l'approbation. Les valeurs gérées des cookies/autorisations/hôtes ne peuvent pas être librement remplacées via son éditeur d'en-tête ; utilisez la route native des outils externes pour les tests d’en-tête/cookie explicitement configurés.

Suivre les redirections de même origine contrôle si vous inspectez la redirection elle-même ou la réponse finale autorisée. Les redirections hors champ ne constituent pas une autorisation générale. Conservez les corps de réponse lorsque cela est nécessaire pour examen, puis choisissez deux réponses enregistrées dans Comparez. Compare n'envoie aucune demande ; le contenu dynamique, l'état de connexion, la limitation ou les pages WAF peuvent expliquer une différence.

Intercepteur

Activez l'intercepteur et Appliquer l'interception. Accordez l'autorisation facultative de blocage de Firefox via son action utilisateur normale. L'interception démarre désactivée après le redémarrage de l'extension.

En-têtes de demande de conservation Inspecter/modifier les en-têtes de requête autorisés avant la transmission
Conserver les en-têtes de réponse Suspendre la livraison une fois que la demande a atteint le serveur ; impossible d'annuler une action côté serveur

L'application/le navigateur peut expirer avant que vous ne libériez une demande de longue date. Jusqu'à 20 étapes peuvent attendre ; le dépassement de la limite de file d’attente annule le trafic correspondant. Changer les filtres libère les étapes actuelles inchangées. La fermeture du dernier tableau de bord de contrôle libère les étapes en suspens et désactive l'interception.

Les en-têtes autorisés utilisent un tableau JSON de paires nom/valeur ; les champs sensibles/gérés par le navigateur/cadrage sont protégés. La réécriture de méthode/corps/statut de la requête réseau en attente n’est pas disponible. Envoyer au répéteur crée une forme de demande distincte pour une modification délibérée ; il ne s’agit pas d’une réécriture transparente du corps en vol.

Seul le trafic HTTP de l'onglet cible sélectionné est éligible. Le transport du scanner contourne l’interception pour éviter les blocages. Le trafic proxy natif externe se situe en dehors de cet intercepteur de navigateur. Les messages WebSocket après la mise à niveau nécessitent leur atelier de canal séparé.

WebSocket, SSE et utilitaires

Choisissez une chaîne découverte dans le champ d'application ou saisissez son URL exacte. L'écoute et les envois de trames personnalisées sont des opérations approuvées limitées, et non un scanner de protocole général. Le texte d'erreur capturé est une piste ; il n'établit pas d'autorisation de message ni de défaut de race/logique.

Les utilitaires encodent/décodent les valeurs, calculent SHA-256, formatent JSON et inspectent les réclamations JWT localement. Le décodage d'un JWT ne constitue pas une vérification de signature et n'établit pas que le serveur accepte un jeton falsifié. L’entrée transformée n’est pas automatiquement exécutée ou soumise.

Résultats et visionneuse cinématique

Lisez d'abord les preuves

Un résultat comporte des champs distincts :

Champ Signification
Gravité Estimation du préjudice potentiel si le problème est exploitable
Verdict Ce que le scanner a observé : potentiel/correspondant/vulnérable, négatif, bloqué ou non concluant, selon le cas
Confiance La force des preuves mises en œuvre, et non l’ampleur des dommages
Statut de l'examen Votre évaluation : Non examinée, Confirmée par l'évaluateur, Faux positif ou Risque accepté
WSTG / CWE Classification de référence, pas une preuve que le test/la catégorie complet a été complété

Inspectez l'URL, le point d'insertion, la demande, la ligne de base, la charge utile, la réponse et les répétitions/contrôles. Vérifiez si le contenu a été tronqué ou si la réponse était une page de défi/connexion/erreur. Une erreur répétée de niveau de confiance élevé peut toujours constituer un résultat d’injection potentiel nécessitant un examen.

Définissez le statut de révision et les notes, puis Enregistrer l'avis. Cela n’écrase pas le verdict/la confiance d’origine du scanner. Les faux positifs restent des preuves conservées. Filtres, y compris Afficher négatif / bloqué, modifiez la visibilité, pas l'enregistrement d'exécution.

visionneuse cinématique

Le bouton est délibérément nommé visionneuse cinématique dans cette version. Il ouvre l'explication 3D thématique pour le résultat sélectionné.

La séquence dure environ 9,3 secondes : localisez la zone affectée, affichez l'entrée, illustrez le traitement, affichez les preuves des résultats enregistrés, puis affichez la gravité et une explication du risque potentiel en langage simple. Les contrôles disponibles incluent Pause/reprise, rejouer, étapes numérotées, passer à l'impact, Profondeur 3D et Plein écran. Les réglages de mouvement réduit peuvent directement avoir un impact.

Mode Ce que ça montre
Live / CSS + JS Un onglet d'aperçu Firefox normal charge la page actuelle avec son CSS/JavaScript et le contexte de cookie sélectionné ; le spectateur reçoit des images rendues et des rectangles d'éléments
Capturé uniquement Preuve conservée avec du HTML purifié et non exécutable ou une capture ; aucune ressource ou script externe n'est exécuté par cette solution de secours hors ligne
Résultat enregistré Le plan de preuve/résultat de l'analyse enregistré, qui peut différer de la page en direct actuelle

Il s'agit d'une fenêtre d'affichage cinématographique, pas d'un DOM de site cloné interactif. Ouvrir l'onglet en direct ouvre la vraie page pour l'interaction. Un chargement en direct normal peut effectuer des requêtes de ressources/applications ordinaires du site, mais l'ouverture de la visionneuse ne soumet pas le formulaire d'attaque enregistré, ne rejoue pas un POST ou ne réexécute pas l'exploit.

La position de la caméra n'est exacte que lorsqu'une entrée/un nom/un identifiant correspondant peut être localisé. Les résultats de l'API/en-tête/cookie ne peuvent avoir aucun formulaire HTML ; une vue de contexte de page est étiquetée comme telle. L’animation ne transforme jamais une découverte potentielle en preuve d’exploitation. Si le rendu en direct échoue, utilisez les preuves capturées et les détails du texte/de la demande.

L'onglet d'aperçu appartenant à la visionneuse est fermé lors du nettoyage normal de la visionneuse/du tableau de bord ; un onglet interactif explicitement ouvert reste à votre disposition. La connexion actuelle, l'état du site, le chargement des dépendances et le CSP peuvent modifier ce qui est affiché en mode direct.

Couverture OWASP Top 10

Ouvert Options de numérisation → Informations pour le tableau d'implémentation consultable/filtrable à 44 entrées, également accessible via le bouton Informations de la page. Il utilise OWASPTop 10:2025 avec d'anciennes références 2021 pour orientation. SSRF est désormais regroupé sous Broken Access Control. Les exemples peuvent chevaucher les catégories ; la liste n'est pas le catalogue complet du CWE.

Étiquettes prises en charge :

  • Vérification active : une règle implémentée dédiée existe lorsqu'elle est activée, pour les entrées atteintes prises en charge.
  • Vérification facultative : des options, autorisations, fournisseurs ou conditions d'exécution supplémentaires s'appliquent.
  • Indicateurs uniquement : un signal/comparaison passif nécessitant une interprétation manuelle.
  • En fonction du modèle : le modèle importé et l'exécuteur déterminent la condition testée.
  • Non couvert : pas de vérificateur intégré dédié pour cette classe ; les charges utiles personnalisées génériques n’établissent pas automatiquement la couverture.

Il s'agit d'un audit de capacité basé sur la source, pas un pourcentage de détection mesuré. Il décrit le scanner intégré de Longshot et ses phases facultatives, et non l'ensemble des règles ZAP externes.

Interprétation de la couverture réelle des courses

La carte de référence WSTG complète comprend des sous-ensembles automatisés, un travail assisté et une évaluation manuelle. Dans Couverture réelle des intrants:

  • Terminé signifie que la règle implémentée s'est terminée sur cette entrée, et non que l'entrée est sécurisée.
  • Partielle signifie que certains travaux ont été exécutés mais qu'une limite, une interruption ou une autre condition a empêché leur achèvement.
  • Sauté signifie que la règle/l'entrée n'a pas été exécutée ; inspectez la raison.

Un WAF, un rôle manquant, une session invalide, un flux de travail masqué/non visité, un corps de demande indisponible, un CSP ou un budget épuisé peuvent laisser une entrée vulnérable non testée. Le couplage proxy natif ne supprime pas ces limites du scanner intégré. Une version CVE observée, un en-tête manquant ou une réponse différente ne constitue pas automatiquement un exploit.

La version 2.18.1 a réussi 192 tests unitaires/de régression automatisés, huit vérifications réelles de Chrome et huit vérifications réelles de Firefox, y compris la vérification ZIP/YAML CSP et le trafic ZAP natif par rapport à un appareil SQLite détenu. Ses bibliothèques officielles de navigateur sont vérifiées octet par octet et une reconstruction source propre reproduit exactement le Firefox XPI. Ces tests valident le comportement d'implémentation nommé ; ils ne montrent pas la détection de chaque défi Juice Shop, WebGoat, bWAPP ou NodeGoat. Le résultat externe du ZAP SQLi vérifie le chemin du proxy, et non le rappel de Longshot pour toutes les vulnérabilités.

Stockage du navigateur et fichiers de session facultatifs

Le stockage du navigateur reste actif indépendamment de l’un ou l’autre pont local. Il conserve l'historique, les résultats, les avis, l'inventaire et les options par profil. Les corps de réponse peuvent être conservés avec une rédaction au mieux ; Le trafic observé par le navigateur contient souvent des métadonnées sans corps capturé.

Pour les points de contrôle automatiques des fichiers :

  1. S'inscrire/se connecter API des agents, pas seulement Browser Bridge.
  2. Ouvert Paramètres → Séances d'évaluation → Instruction.
  3. Entrez un absolu Dossier de session sur l'ordinateur de l'API de l'agent.
  4. Activer Enregistrer automatiquement les fichiers de session et choisissez Enregistrer les paramètres de session.
  5. Utiliser Enregistrer la session maintenant pour un point de contrôle immédiat ; les changements normaux déclenchent également des sauvegardes.
  6. Utiliser Exporter la session en cours / Importer un fichier de session pour le transfert manuel ; l'importation manuelle ne nécessite pas l'hôte natif.

Les fichiers utilisent des ID de profil stables avec .longshot.json, autorisant des profils explicites pour une origine. Il s'agit d'archives d'évaluation lisibles et non cryptées et peuvent contenir des données de candidature, des modèles créés et des corps conservés. Les cookies gérés par le navigateur, les jetons de fournisseur et les autorisations d'exécution sont exclus.

Les écritures sont des points de contrôle atomiques de fichiers privés. Une résiliation brutale ne peut récupérer que la dernière sauvegarde terminée. Les analyses en cours restaurées sont interrompues. Si le pont se déconnecte, le stockage du navigateur continue et les sauvegardes de fichiers attendent ; les points de contrôle activés non résolus peuvent nécessiter une reconnexion ou la désactivation de l'enregistrement des fichiers avant de changer de cible. La taille maximale du fichier de session est de 256 Mo avec une erreur explicite.

L’exportation des archives d’évaluation est différente de Télécharger la configuration dans le pont du navigateur. Le premier enregistre les preuves/options d’évaluation ; ce dernier enregistre les paramètres de proxy natifs.
