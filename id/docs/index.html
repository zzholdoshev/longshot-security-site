Longshot 2.18.1 — tutorial umum dan referensi kontrol

Diperbarui 10 November 2026 untuk Longshot 2.18.1 (Edisi Firefox dan Chrome) dan nya proksi alat HTTP/HTTPS asli. Ini menggantikan tutorial umum 2.11.1. Petunjuk di bawah menjelaskan implementasi yang dikirimkan, termasuk batasannya; contoh jembatan lama tidak dapat dipertukarkan dengan rilis ini.

Longshot adalah meja kerja sesi browser untuk penilaian aplikasi web resmi. Ini menggabungkan penemuan, pemindai aktif JavaScript-nya sendiri, alat HTTP manual, templat yang diimpor, tinjauan temuan, dan laporan. Browser Bridge opsional memungkinkan alat eksternal menggunakan nilai sesi Firefox yang dipilih sambil mengirimkan permintaan HTTP asli mereka sendiri.

Pass pertama yang berguna adalah: buka aplikasi → masuk → luncurkan Longshot dari tab itu → Hubungkan → validasi sesi → temukan masukan → jalankan pemeriksaan yang dipilih → tinjau bukti.

Untuk aplikasi yang menangani data atau uang pengguna yang sensitif, termasuk aplikasi yang dibuat dengan AI atau aplikasi berkode getaran, pekerjakan tim keamanan siber untuk melakukan penilaian profesional. Pemindaian ekstensi tidak menggantikan pengujian otorisasi, tinjauan logika bisnis, atau penilaian keamanan independen. Daftar temuan yang kosong bukanlah sertifikat keamanan.

Dokumen ini menjelaskan perintah; memperbaruinya tidak menginstal perangkat lunak, mendaftarkan host, mengubah pengaturan browser atau menjalankan pemindaian apa pun. Jalankan contoh hanya terhadap target penilaian resmi Anda. Sampel http://localhost:8080 adalah contoh target lokal, bukan layanan Longshot bawaan.

Penutup cek didukung Injeksi SQL/NoSQL, kode sisi server dan injeksi templat, kandidat XSS yang tercermin, traversal jalur/penyertaan file, pengalihan terbuka, dan injeksi CRLF/header, dengan verifikasi DOM XSS langsung opsional. Ulasan header keamanan yang lemah, kebijakan cookie dan CORS, konfigurasi terbuka, dan pengungkapan kesalahan, dengan pemeriksaan opsional untuk kelas serangan lebih lanjut.

Catatan publikasi

Kisah kehilangan rekening bersifat hipotetis, bukan klaim tentang pelanggan sebenarnya atau jaminan bahwa Longshot mencegah kerugian finansial. Ekstensi melakukan penilaian, bukan pemblokiran serangan berkelanjutan. Temuan memerlukan peninjauan; tabel cakupan menjelaskan dukungan terbatas dan kesenjangan manual saja. Analisis DOM mencakup indikator dan canary eksekusi yang didukung, bukan cakupan eksploitasi DOM universal. Urutan sinematik menjelaskan bukti; itu tidak menambahkan bukti eksploitasi.

MCP dan Jembatan Browser memerlukan pengaturan lokal. Proksi alat asli menggunakan proses Node/Python/mitmproxy terpisah, dan intersepsi HTTPS memerlukan konfigurasi kepercayaan alat untuk CA adaptor. Ini adalah transportasi HTTP yang diurai, bukan TCP mentah transparan-byte. Penggantian cookie dapat dinonaktifkan; cookie browser atau Agen Pengguna tidak menjamin jaringan yang identik dengan browser atau penerimaan WAF. ZAP eksternal tetap dipasang secara terpisah. Eksekusi template bergantung pada kompatibilitas/runtime; OAST memerlukan penyedia yang dikonfigurasi. Validasi autentikasi memerlukan titik akhir/penanda yang dilindungi secara bermakna. Profil target data penilaian terpisah; tab/wadah menyediakan sesi cookie.

Untuk aplikasi yang menangani data sensitif atau uang, pekerjakan tim keamanan siber dan gunakan Longshot sebagai salah satu bagian dari penilaian. Gunakan hanya pada aplikasi yang Anda miliki atau yang diizinkan untuk diuji.

Jika menggunakan kembali gambar kampanye yang dibuat sebelumnya, beri label sebagai komposisi dan gunakan tangkapan layar aktual saat ini jika UI dengan piksel persis diperlukan. Tutorial ini menghubungkan screenshot validasi 2.18.1 yang sebenarnya di bagian tampilan; itu tidak termasuk paket kampanye delapan gambar baru atau klaim dukungan pihak ketiga.

Instal edisi Chrome

  1. Unduh ZIP Krom dari tautan rilis di atas/bawah dan ekstrak ke folder yang Anda simpan.
  2. Buka chrome://extensions, aktifkan Mode pengembang, pilih Muatan dibongkar, lalu pilih folder hasil ekstrak yang berisi manifest.json.
  3. Buka aplikasi resmi Anda, masuk, luncurkan Longshot dari tab itu dan Hubungkan.
  4. Biarkan tab meja kerja tetap terbuka selama pemindaian dan pemasangan asli. Menutupnya mengakhiri kerja mesin secara langsung; bukti yang disimpan tetap ada dan dipulihkan tanpa mengulangi permintaan yang tidak pasti.
  5. Untuk permulaan proksi alat asli, gunakan asal persis yang ditunjukkan oleh Chrome, seperti chrome-extension://YOUR_INSTALLED_ID, bukan Firefox moz-extension:// asal. Proksi menggunakan URL target sebenarnya; tidak diperlukan entri file host.

Pendaftaran API Agen Chrome/MCP

Dari checkout sumber lengkap yang dipertahankan, setelah menginstal ketergantungan pembantu yang disematkan:

npm --prefix native-bridge ci --omit=dev
node bridge/bin/longshot-bridge install --browser chrome \
  --extension-id YOUR_INSTALLED_32_LETTER_ID \
  --port 8775 --data-dir /absolute/private/longshot-chrome
node bridge/bin/longshot-bridge mcp \
  --port 8775 --data-dir /absolute/private/longshot-chrome

Untuk penggunaan Kromium --browser chromium. Gunakan ID sebenarnya di chrome://extensions; daftar lagi jika menginstal edisi toko memberikan ID yang berbeda. Direktori port/data terpisah menghindari tabrakan dengan host Firefox. API Agen ini berbeda dari proksi alat HTTP (port default 8900/8901). Linux adalah platform host asli yang teruji; Pendaftaran macOS telah diterapkan tetapi belum diuji di sini, dan tidak ada penginstal host asli Windows yang disediakan.

Instal atau perbarui di Firefox Nightly

Gunakan 2.18.1 XPI, bukan adaptor lama ZIP yang diganti namanya menjadi add-on. Ekstrak arsip sumber yang cocok ke folder yang Anda simpan, seperti yang ditunjukkan sebagai /path/to/longshot dalam contoh. Jangan memindahkan host asli yang terdaftar tanpa mendaftarkannya lagi.

File rilisnya adalah:

  • Firefox XPI
  • ZIP Krom
  • ZIP sumber ekstensi yang cocok
  • Catatan rilis dan checksum
  • ZIP adaptor asli: unduh di dalam Browser Bridge; itu disertakan dalam setiap paket ekstensi.

Ini adalah pembangunan pengembangan/pengajuan. Penandatanganan toko Firefox dan persetujuan kedua pasar sedang menunggu keputusan. Ikuti prosedur pemuatan pengembangan yang berlaku daripada mengharapkan XPI yang tidak ditandatangani untuk diinstal secara normal di rilis Firefox.

Manifesnya memerlukan Firefox 140 atau lebih baru. Pemeriksaan integrasi rilis menggunakan desktop Firefox 159 di Linux. Dukungan platform/runtime untuk pembantu opsional terpisah dari dukungan ekstensi dasar.

Untuk instalasi sementara yang tidak ditandatangani:

  1. Buka about:debugging#/runtime/this-firefox.
  2. Pilih Muat Add-on Sementara dan pilih XPI.
  3. Konfirmasikan versi Longshot yang ditampilkan, lalu buka target dan luncurkan tombol toolbarnya.
  4. Muat ulang ekstensi setelah mengganti build pengembangan yang belum dibongkar.

Add-on sementara menghilang setelah Firefox dimulai ulang. Hal ini diharapkan; itu bukan adaptor yang menghapus ekstensi. Distribusi publik yang persisten memerlukan penandatanganan Mozilla. Nightly memiliki opsi pengembangan tambahan yang tidak ditandatangani yang dijelaskan oleh Panduan penandatanganan Mozilla; pemuatan sementara tidak memerlukan perubahan pengaturan tersebut. Lihat instalasi sementara.

XPI menggabungkan adaptor asli sebagai arsip yang dapat diunduh. Itu tidak dapat memulai proses Node/Python secara sewenang-wenang atau menginstal host asli hanya melalui Add-on Firefox. Memulai proksi dan mendaftarkan API Agen merupakan langkah penyiapan lokal opsional yang berbeda.

Memulai dan menargetkan sesi

Hubungkan tab kanan

  1. Buka target resmi di Firefox, misalnya http://localhost:8080.
  2. Masuk dengan akun pengujian yang dimaksud dan selesaikan tantangan browser apa pun.
  3. Luncurkan Longshot dari tab target itu. Biarkan tab aplikasi tetap terbuka.
  4. Periksa alamat target dan pilih Hubungkan.
  5. Gunakan Memulai di header untuk panduan delapan langkah yang disorot. Itu bisa diputar ulang; itu tidak memulai pemindaian atau mengubah pengaturan itu sendiri.
  6. Jelajahi halaman aplikasi yang representatif sehingga Longshot dapat mengamati rute dan masukan yang berguna.

Asal target terdiri dari skema, nama host, dan port. http://localhost:8080, http://127.0.0.1:8080 dan https://localhost:8080 berasal dari tempat yang berbeda, meskipun pada akhirnya mencapai layanan yang sama. Hubungkan dan gunakan alamat persis yang dimaksudkan untuk penilaian. Alamat IP yang ditemukan di belakang nama host tidak secara otomatis menjadi target resmi tambahan.

Simpan pengaturan dan gunakan Ikhtisar → Periksa sesi. Halaman publik yang menghasilkan 200 bukanlah bukti autentikasi. Pengalihan ke halaman login yang diikuti dengan 200 masih dapat menunjukkan sesi yang tidak valid; pilih titik akhir yang dilindungi dan penanda yang bermakna.

Pemindai internal menggunakan cookie browser yang berlaku pada tab terikat, termasuk cookie HttpOnly. Firefox memilih cookie berdasarkan URL, jalur, atribut keamanan, dan penyimpanan cookie. Bidang Cookie/Otorisasi/Host yang dilindungi pemindai bukanlah input fuzz biasa yang dapat diedit.

Profil dan akun

Target memisahkan riwayat, temuan, jurnal permintaan, titik akhir yang ditemukan, tinjauan, dan konfigurasi pemindaian. Kembali ke profil akan memulihkan data penilaian, bukan sesi browser lama yang diautentikasi. Profil eksplisit dapat berbagi asal usul.

Dua tab Firefox biasa biasanya berbagi cookie. Gunakan wadah independen atau penyimpanan kue pribadi terpisah untuk identitas pengujian yang benar-benar berbeda. Beralih profil tidak membuat sesi akun kedua. Perbandingan sesi B memerlukan asal target yang sama dan penyimpanan terpisah.

Penemuan ringan dan pemindaian aktif terfokus

Lulus pertama: penemuan dan tinjauan pasif

  1. Tetapkan Permintaan per detik menjadi 0,5–1, kedalaman perayapan menjadi 1 dan URL maksimum yang ditemukan menjadi 25–50.
  2. Pergi Temuan maksimal, Agresif, fase otomatis CVE, OAST, dan eksekusi asli nonaktif.
  3. Tetapkan Fuzz otomatis → Mati. Biarkan klik/gulir halaman dan aktifkan pengujian DOM/waktu/panggilan balik.
  4. Pilih grup Ikhtisar pasif: header, cookie, pengungkapan, formulir, tinjauan sumber/sink DOM, dan CORS.
  5. Pilih Hanya laba-laba dan mulai.
  6. Periksa Peta situs, riwayat HTTP, penjelajah API, Tumpukan server dan Temuan.

Spider mengikuti tautan/formulir dalam cakupan yang ditemukan tanpa mengirimkan penulisan formulir. Ia tidak mengetahui setiap titik akhir yang tersembunyi. Permintaan GET masih dapat memiliki efek samping khusus aplikasi; "metode baca" tidak menetapkan target bebas efek samping.

Lulus kedua: penilaian aktif terbatas

  1. Simpan Fuzz otomatis → Mati untuk membuat aturan aktif bawaan lebih mudah ditinjau secara terpisah.
  2. Pilih pemeriksaan aktif Ikhtisar yang relevan, seperti injeksi SQL dan XSS Tercermin.
  3. Gunakan batasan kecil, misalnya 150 permintaan aktif, 10 URL aktif, dan lima parameter aktif.
  4. Pilih Hanya pemeriksaan aktif untuk menggunakan kembali halaman saat ini dan inventaris yang disimpan, atau Spider + pemeriksaan aktif untuk menemukan terlebih dahulu.
  5. Mulai, tinjau persetujuan yang diperlukan, dan lihat Aktivitas dan jumlah permintaan.
  6. Periksa setiap permintaan temuan, data dasar, bukti penyelidikan/pengendalian berulang, keputusan dan keyakinan.
  7. Buka Pemeriksaan WSTG → Cakupan input aktual untuk melihat pekerjaan yang selesai, sebagian, dan dilewati.

Auto-fuzz Off tidak mematikan pemeriksaan aktif. SQLi/XSS/SSTI dan aturan khusus lainnya menghasilkan probe mereka sendiri. Sebaliknya, mencentang aturan aktif tidak akan memberikan masukan yang hilang atau membuat proses khusus Spider menjalankan fase aktif umum.

Opsi agresif dan jalankan persetujuan

Agresif memungkinkan metode/kemampuan yang disetujui secara eksplisit; hal ini tidak membuat setiap pemeriksaan berjalan atau menjamin bukti yang lebih kuat.

  1. Temukan masukan dan validasi otentikasi terlebih dahulu.
  2. Aktifkan hanya opsi lanjutan yang diperlukan dan izin tulis/unggah/hapus.
  3. Simpan opsi Pemindaian.
  4. Pilih Tinjau/setujui proses agresif berikutnya.
  5. Tinjau target, fitur, izin metode, dan anggaran.
  6. Klik Setujui proses berikutnya. Tindakan pengguna ini meminta izin gabungan Firefox yang hilang dan membuat hibah yang dijalankan berikutnya.
  7. Mulai jalankan dengan konfigurasi yang ditinjau.

Hibah ini bersifat sekali pakai, habis masa berlakunya setelah 30 menit dan tidak valid karena perubahan target/konfigurasi/pengaturan permintaan yang relevan. Pemindaian baru biasanya memerlukan hibah baru. Menyimpan opsi yang belum selesai diperbolehkan; memulai atau menyetujui memvalidasi bidang yang diperlukan.

Firefox membutuhkan permissions.request() berasal langsung dari tindakan pengguna nyata. Mengubah pengaturan bukan alasan untuk memberikan izin sewenang-wenang di latar belakang. Jika izin ditolak, tinjau fitur sebenarnya, coba lagi dari tombol persetujuan atau nonaktifkan fitur tersebut. Permintaan izin OS/browser normal tetap berada di luar otomatisasi ekstensi DOM.

Temuan maksimal merupakan preset yang luas

Prasetel ini mengaktifkan banyak fase, termasuk verifikasi lanjutan, perbandingan OAST dan Sesi B, dan memperluas beberapa anggaran. Ini bukan tombol “temukan segalanya”. Itu tidak membuat akun OAST, mengisi URL Penyedia/domain Panggilan Balik, memilih Sesi B yang valid, menginstal Nuclei atau mengautentikasi peran yang hilang.

Jika persetujuan melaporkan kolom OAST kosong atau Sesi B hilang, konfigurasikan atau nonaktifkan opsi tersebut. Hal ini terpisah dari valid atau tidaknya URL target.

Dua kontrol injeksi perintah

Ikhtisar → Indikator perintah OS mengaktifkan probe keluaran perintah berorientasi Unix langsung. Ini dinonaktifkan secara default. Opsi pemindaian → Probe perintah mengontrol rute panggilan balik ekstra buta saat OAST mendengarkan. Satu kotak centang tidak secara otomatis mengonfigurasi jalur lainnya. Tinjau persyaratan otorisasi untuk pengoperasian sebenarnya.

Fuzzer kueri manual

  1. Hubungkan target dan pilih URL cakupan. URL relatif seperti /search?q=apple diterima terhadap asal terhubung.
  2. Masukkan nama parameter kueri yang ada, atau pilih Gunakan di samping masukan yang ditemukan.
  3. Pilih kelas payload dan mutasi nilai.
  4. Untuk Muatan khusus yang diunggah pengguna, aktifkan paket khusus yang sesuai terlebih dahulu.
  5. Pilih Jalankan fuzzer, lalu periksa data dasar, permintaan, status, durasi/waktu, dan bukti.

URL, parameter, atau kumpulan kustom kosong yang hilang menghasilkan pesan validasi tertentu. Mengubah respons saja tidak menyebabkan cacat injeksi. Pembatasan server dapat menghentikan parameter meskipun terjadi pada baseline.

Input yang ditemukan fuzz otomatis

Gunakan Pratinjau masukan yang ditemukan pertama. Itu membaca inventaris yang disimpan dan melaporkan permintaan yang memenuhi syarat/dilewati tanpa mengirimkan pemeriksaan. Fuzz otomatis tidak memerlukan kolom URL/parameter fuzzer manual. Telusuri atau Spider terlebih dahulu jika inventaris kosong.

Pilih kelas muatan dan pilih yang terpisah Bulu halus otomatis tombol. Sertakan badan permintaan yang ditemukan dimulai dan memerlukan persetujuan Agresif plus dijalankan selanjutnya. Formulir yang terikat token, metode yang tidak didukung, isi yang tidak tersedia, dan XML dilewati oleh pemilih masukan otomatis ini. Pengecualian yang ada, batas permintaan, dan perilaku pembatasan masih berlaku.

Kotak centang kelas yang tersedia adalah SQLI, NOSQLI, CODE, XSS, SSTI, TRAVERSAL, COMMAND, SSRF, REDIRECT, CRLF dan CUSTOM. Default baru mengaktifkan SQLI, SSTI, TRAVERSAL, REDIRECT dan CRLF. Perulangan generik melewati SSRF; gunakan Kenari/callback SSRF untuk verifikasi yang diterapkan. CUSTOM menggunakan nilai khusus yang dimasukkan/diaktifkan dan melaporkan perbedaan respons berkeyakinan rendah kecuali jika pencocokan khusus menentukan lebih banyak.

Muatan Anda dan templat yang diimpor

Unggah daftar literal

Di bawah Opsi pemindaian atau Fuzzer → Perpustakaan probe → Payload dan templat CVE Anda, lalu pilih kategori Unggah file khusus.

Formulir daftar yang diterima:

  • .txt: satu nilai literal yang tidak kosong per baris; ruang dan kotak dipertahankan.
  • .json: array string atau objek yang berisi name, category dan payloads.
  • Kategori: custom, waf, sqli, nosqli, code, xss, ssti, traversal, crlf, redirect, command.
{
  "name": "My SQL review probes",
  "category": "sqli",
  "payloads": ["'", "\"", "' AND 1=1 -- "]
}

Paket bersifat spesifik target dan pada awalnya dengan disabilitas. Periksa pratinjau dan aktifkan paket yang dimaksud secara eksplisit. Paket unggahan yang diaktifkan memerlukan Agresif dan persetujuan; mengunggah saja tidak menghasilkan apa-apa.

Batasan: 256 KB per file payload, 200 string per paket, 2.000 karakter per nilai, dan maksimal 10 paket / 500 nilai / 512 KB konfigurasi paket per target. String duplikat dalam paket akan dihapus. Metode, cakupan, anggaran, dan penjaga SQL destruktif yang ada masih berlaku.

Paket yang dikategorikan melengkapi nilai kelas bawaan. Paket WAF juga memerlukan variasi cerdas dan bukti pemfilteran yang memenuhi syarat. Payload khusus literal bukanlah pencocokan keluaran yang diharapkan atau kode ekstensi yang dapat dieksekusi. Mengunggah nomor CVE saja tidak dapat memverifikasi CVE tersebut.

Impor templat permintaan/pencocokan

Pilih kategori template CVE/Nuclei sebelum mengunggah YAML/YML/JSON; batas file templat adalah 2 MB. Tinjau di Templat, termasuk eksekutor dan alasan Siap/Diblokir yang konkrit. Templat yang diimpor menggunakan perpustakaan bersama; paket muatan tetap pada targetnya.

  • Jalankan dipilih mengeksekusi templat yang dipilih secara langsung dan tidak memerlukan fase otomatis CVE.
  • Fase otomatis CVE mempertimbangkan impor yang diberi tag/identifikasi CVE yang memenuhi syarat selama pemindaian yang dikonfigurasi.
  • Bulu halus otomatis menghasilkan nilai-nilai umum; itu tidak menulis ulang muatan atau pencocokan CVE yang dibuat.
  • JSON khusus penasehat menghubungkan bukti produk/versi. Itu tidak menciptakan permintaan eksploitasi yang berfungsi.
  • Templat mentah, kompleks, kode, tanpa kepala, file, atau non-HTTP mungkin memerlukan mesin resmi terpisah dan hibah tambahan, atau tetap diblokir.

Impor bundel pembantu relatif yang telah ditinjau dengan templat yang memerlukannya. Waktu proses asli yang tidak tersedia, permintaan di luar cakupan, persetujuan yang hilang, atau fitur yang tidak didukung adalah alasan untuk melakukan pemeriksaan, bukan pengujian negatif yang berhasil.

Tumpukan server dan penganalisis cerdas

Gunakan Deteksi perangkat lunak untuk mengumpulkan pengamatan terbatas yang didukung. Jelajahi halaman representatif dan simpan tanggapan yang sesuai saat Anda membutuhkan bukti tubuh. Lalu pilih Analisis bukti-bukti yang tercatat untuk korelasi pasif lokal hingga 200 tanggapan tersimpan terbaru. Penganalisis itu sendiri tidak menambahkan permintaan target.

Tampilan tersebut memisahkan komponen browser, WAF/CDN/edge, server web/proxy terbalik, dan sinyal aplikasi/runtime. Header khusus produk, nama cookie, struktur aset/bootstrap, dan teks kesalahan dapat meningkatkan kepercayaan diri. Badan halaman tantangan dikecualikan dari sidik jari aplikasi. 403 generik, spanduk nginx, atau tepi CDN tidak menetapkan bahwa aturan WAF tertentu diaktifkan.

Kartu konfigurasi yang mungkin menjelaskan buktinya dan verifikasi yang disarankan. Hipotesisnya adalah: respons browser tidak dapat secara tepat menetapkan IP asal, subnet pribadi, pengaturan database backend, penghentian TLS, aturan firewall, atau daftar kepercayaan proxy. Beberapa upstream dan spanduk yang ditulis ulang dapat menyembunyikan atau salah mengidentifikasi lapisan.

Rekomendasi WAF dan penanganan tarif

Terapkan rekomendasi pemindaian konservatif secara eksplisit mengaktifkan probe SQL komunitas, variasi cerdas, dan kecepatan adaptif serta menurunkan kecepatan yang dikonfigurasi hingga maksimal 0,5 permintaan/detik. Itu tidak memulai pemindaian atau memberikan kemampuan tingkat lanjut.

Penyelidikan yang memenuhi syarat mempertimbangkan paling banyak tiga representasi alternatif dalam anggaran yang ada. Garis dasar yang diblokir dilewati. Tantangan browser memerlukan resolusi browser normal; penolakan ACL biasa tidak membenarkan upaya bypass tanpa akhir. Perubahan yang dilarang untuk dibolehkan adalah bukti keterjangkauan, bukan bukti kerentanan.

Tantangan eksplisit yang berulang dapat mengurangi separuh kecepatan dalam memori dan menyebabkan waktu tunggu setidaknya sepuluh detik. HTTP 429 atau 503 dengan Retry-After menghentikan pemeriksaan terjadwal lebih lanjut; interval Coba Lagi-Setelah yang lebih lama dipatuhi. Tarifnya tidak otomatis naik lagi. Proses baru dimulai dengan laju yang dikonfigurasi.

pencarian CVE

Cari CVE online menanyakan NVD/OSV untuk koordinat produk/paket yang didukung setelah izin. Permintaan mengirimkan koordinat, bukan URL target, cookie, atau konten halaman. Kesimpulan versi tidak diketahui, backport vendor, dan kehadiran paket yang tidak terverifikasi. Entri npm/PyPI manual tidak membuktikan instalasi.

Tidak ada kecocokan bukan berarti tidak ada CVE. Yang cocok adalah calon penasehat; memeriksa prasyarat dan penggunaan Temukan templat verifikasi untuk menemukan cek impor yang sesuai. Tombol itu memfilter templat daripada menjalankannya.

Pengaturan dan interpretasi OAST

OAST mengamati interaksi DNS/HTTP yang disebabkan oleh penyelidikan ketika respons normal tidak mengungkapkan perilaku tersebut. Longshot memiliki kunci registrasi/korelasinya; panggilan balik acak yang dibuat sebelumnya dari klien lain tidak dapat dipertukarkan.

  1. Pilih layanan yang kompatibel dengan Interactsh yang Anda kendalikan atau diizinkan untuk digunakan.
  2. Masuk URL Penyedia: alamat dasar API lengkap penyedia, biasanya HTTPS. HTTP hanya diperbolehkan untuk penyedia loopback.
  3. Masukkan yang cocok Domain panggilan balik tanpa http://, port atau jalur.
  4. Masuk Token penyedia hanya jika penyedia tersebut memerlukannya.
  5. Atur TTL dan interval polling; aktifkan OAST ditambah opsi SSRF/XXE/Log4Shell/perintah yang relevan.
  6. Gunakan Uji koneksi OAST untuk memeriksa pendaftaran/polling.
  7. Gunakan Uji panggilan balik OAST untuk mengirim canary berkorelasi terpisah dari browser ini.
  8. Simpan, tinjau, dan setujui pemindaian sebenarnya. Periksa korelasi dan protokol yang tepat dalam interaksi OAST.

Misalnya jika menggunakan layanan publik yang cocok di https://oast.pro, basis panggilan baliknya adalah oast.pro. Ini adalah contoh, bukan jaminan ketersediaan atau persyaratan untuk menggunakan penyedia tersebut. Penyedia yang dihosting sendiri memerlukan domain, DNS/pendengar, dan TLS yang dapat didelegasikan dengan benar; pendengar HTTP laptop saja bukanlah layanan panggilan balik publik. Ikuti pengaturan Interactsh resmi.

Jembatan Browser: proksi alat asli

Apa yang dikirimkannya

Alat eksternal menghasilkan permintaan, termasuk muatan serangan, metode, isi, dan kuerinya. Adaptor asli meneruskannya melalui mitmproxy, hanya menerapkan perubahan cookie/header yang dikonfigurasi. Memang benar tidak minta Firefox untuk melakukan pengambilan atas nama ZAP atau alat lain.

Hal ini mempertahankan semantik HTTP asli dan pembuatan payload alat, namun bukan byte kabel asli yang sewenang-wenang: mitmproxy mem-parsing/membuat serial HTTP dan membuat koneksi TLS keluarnya sendiri. String Agen-Pengguna browser tidak membuat sidik jari TLS/jaringan asli identik dengan Firefox.

Instal adaptor yang diunduh

  1. Buka Jembatan Peramban. Hanya saja Proksi alat asli tersedia di 2.18.1.
  2. Pilih Unduh adaptor asli dan mengekstraknya.
  3. Masukkan hasil ekstraknya native-bridge direktori. Ini berisi cli.js, bootstrap.py, config.json dan Node.js yang dibundel ws ketergantungan.
  4. Instal Node.js 20+ dan Python 3.12+ jika belum tersedia.
  5. Jalankan pengaturan Python satu kali:

sh cd /absolute/path/to/native-bridge python3 bootstrap.py

Hal ini menciptakan lokal .venv dan menginstal mitmproxy 12.2.3 yang disematkan. Instalasi memerlukan akses Internet. Startup normal tidak mengunduh kode pemindai atau daftar muatan.

  1. Gunakan perintah yang ditunjukkan oleh milikmu halaman ekstensi:

sh node cli.js --config config.json \ --extension-origin moz-extension://YOUR-LONGSHOT-UUID

Ganti placeholder dengan asal ekstensi lengkap saat ini. Ini bukan situs web target, ID tambahan, atau asal yang disalin dari profil Firefox lain.

  1. Biarkan terminal tetap berjalan. Setelah pendengar proksi siap, ia akan mencetak alamat proksi, port kontrol, token pemasangan/proksi baru, dan jalur sertifikat CA.

Saat mengembangkan dari ZIP sumber daripada menggunakan arsip adaptor yang dibundel, instal ketergantungan Node yang disematkan terlebih dahulu jika tidak ada:

cd /absolute/path/to/longshot-source

--mitmdump /absolute/path/to/mitmdump atau LONGSHOT_MITMDUMP memilih runtime yang ada. --data-dir /absolute/private/run-directory memilih direktori CA/audit; standarnya adalah run di dalam adaptor asli. Ctrl+C menghentikan adaptor.

Proksi asli manual terpisah dari pendaftaran host API Agen. Itu tidak perlu node bridge/bin/longshot-bridge install hanya untuk proxy curl/ZAP. Linux/Firefox dilaksanakan dalam uji integrasi rilis; jangan menyimpulkan dukungan penginstal pesan asli pada platform lain dari jalur startup Node/Python manual ini.

Pasangkan tab yang dipilih

  1. Pilih yang berwenang Tab sasaran di Jembatan Peramban.
  2. Verifikasi asal yang ditampilkan dan penyimpanan cookie. Gunakan Segarkan tab jika perlu.
  3. Masuk Pelabuhan kontrol 8901, kecuali diubah pada konfigurasi adaptor.
  4. Tempelkan arusnya Memasangkan/token proksi dari adaptor yang sedang berjalan.
  5. Pilih Pasangkan jembatan asli dan verifikasi status siap.
  6. Tinjau peralihan cookie/header sebelum merutekan lalu lintas alat.

Bidang ini menghapus token setelah pemasangan berhasil. Pengulangan ulang menghasilkan token baru: pasangkan kembali dan perbarui kredensial proxy di setiap alat eksternal. Pelabuhan proksi 8900 adalah untuk alat; port kendali 8901 adalah untuk Firefox. Tidak ada yang menggunakan token pembawa API Agen dari port 8765.

URL target sebenarnya dan bridge.invalid

Gunakan alamat sebenarnya, misalnya http://localhost:8080/search?q=apple, di alat Anda. Jika menguji HTTPS, gunakan yang asli https://... alamat. Alamat proxy itu sendiri tetap ada http://127.0.0.1:8900 karena itu adalah pendengar proxy HTTP lokal, termasuk untuk HTTPS CONNECT.

Tidak /etc/hosts diperlukan entri. Yang lama bridge.invalid alamat adalah alias khusus adaptor untuk memetakan URL HTTP utilitas ke target pengambilan browser yang dipilih. Proksi asli saat ini mendukung URL target sebenarnya dan HTTPS CONNECT, sehingga pemetaan tidak diperlukan.

localhost bukanlah alias yang dapat dipertukarkan untuk setiap target: ia memberi nama mesin lokal dari lingkungan jaringan proses yang relevan. Ini benar hanya jika targetnya benar-benar lokal di tempat asal tersebut. Nama host yang berbeda dapat memilih host virtual, kebijakan cookie, atau asal yang berbeda meskipun kedua nama tersebut memiliki IP yang sama.

Entri host yang sudah usang tidak relevan dengan alur kerja baru; jangan menggunakannya di URL alat. Tidak ada modifikasi file host yang dilakukan saat mempersiapkan tutorial ini.

kepercayaan HTTPS

Adaptor menghasilkan CA lokalnya sendiri di bawah direktori data yang dipilih, biasanya:

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

Konfigurasikan konfigurasi kepercayaan penilaian alat eksternal dengan jalur sertifikat publik yang dicetak saat startup. Jangan membagikan kunci pribadi atau menganggap sistem/penyimpanan kepercayaan Firefox telah diubah. Adaptor tidak menginstal CA-nya ke salah satu penyimpanan kepercayaan.

Untuk ikal:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

Ganti CURRENT_TOKEN dan jalur sasaran/sertifikat. Untuk target lokal khusus HTTP, --cacert tidak diperlukan. --noproxy '' memastikan curl tidak secara diam-diam mem-bypass proxy untuk target loopback.

Ada dua pemeriksaan TLS yang berbeda:

  • Klien memverifikasi sertifikat yang diberikan oleh adaptor. Konfigurasikan kepercayaan klien dengan adaptor CA.
  • Adaptor memverifikasi server upstream yang sebenarnya. tls.verifyUpstream defaultnya benar. Klien --cacert tidak menyediakan CA asal privat ke adaptor.

Jangan perlakukan penonaktifan verifikasi sebagai perbaikan normal untuk kesalahan sertifikat. Untuk perlengkapan yang ditandatangani sendiri, tls.verifyUpstream:false adalah pengecualian penilaian eksplisit dalam konfigurasi adaptor, diikuti dengan restart; hal ini melemahkan pemeriksaan hulu yang terpisah. Lihat perilaku sertifikat mitmproxy.

Cookie dan header diganti tanpa merusak probe

Perilaku cookie default

Gunakan cookie browser dan Simpan respons pembaruan Set-Cookie aktif secara default. Agen Pengguna, Bahasa Terima, dan Otorisasi tetap dikontrol alat secara default.

Untuk permintaan asli, Firefox memilih cookie yang berlaku untuk URL dari penyimpanan cookie tab berpasangan dan partisi yang cocok. Kontainer/toko pribadi lainnya tidak digabungkan. Aturan domain/jalur/Aman/kedaluwarsa dan pengurutan jalur dengan nama yang sama tetap relevan. Nilai diberikan ke proksi asli sehingga dapat membuat header Cookie keluar; tidak seperti jalur pengambilan browser yang dihapus, helper asli menangani rahasia sesi di memori.

Dengan cookies.mode:"replace", toples browser bersifat otoritatif, termasuk saat kosong. Cookie browser yang dihapus dari toples akan dihapus dari permintaan terkelola selanjutnya. Nama yang dilindungi secara eksplisit dan perubahan alat yang terdeteksi menjadi prioritas. Dengan mode:"merge", cookie alat yang tidak terkait dapat tetap ada selama nama yang dikelola browser diperbarui.

Bidang Set-Cookie Respons diterapkan satu per satu ke penyimpanan terpilih yang sama menggunakan API cookie Firefox, termasuk atribut Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition yang didukung. Cookie yang tidak valid dapat ditolak; memeriksa kesalahan yang dilaporkan. Asal tambahan yang dikonfigurasi tidak menerima cookie browser atau header turunan browser.

Untuk pengaburan cookie atau eksperimen sesi yang harus membiarkan toples browser tidak berubah, pertimbangkan kedua sakelar. Bypass pengesampingan per permintaan memengaruhi pengesampingan sisi permintaan; itu tidak menonaktifkan pengaturan sinkronisasi cookie respons global yang independen.

Lindungi bidang yang berisi muatan serangan

Misalkan tes ZAP session=ATTACK_PAYLOAD. Mengganti nilai tersebut secara membabi buta dengan sesi browser yang valid dapat menghapus pengujian. Sebaliknya, menyimpan cookie basi di setiap permintaan dapat membuat pemindaian yang diautentikasi menjadi tidak berguna.

Standarnya Pertahankan perubahan cookie/header alat setelah permintaan pertama mencatat garis dasar per koneksi/asal klien dan menyimpan perubahan selanjutnya. Kirim permintaan benih biasa terlebih dahulu. Proksi tidak dapat secara andal menyimpulkan maksud pada permintaan pertama, dan koneksi baru akan membuat garis dasar baru. Heuristik ini bukanlah perlindungan lengkap.

Untuk pengujian yang dapat diprediksi, pilih salah satu mekanisme berikut:

  1. Nonaktifkan penggantian cookie/header tertentu yang sedang diuji.
  2. Tambahkan nama cookie ke cookies.protectedNames atau header ke headers.protectedNames.
  3. Kirim anotasi selektif per permintaan:

http X-Longshot-Preserve: cookie:session, User-Agent, Authorization

Ini mempertahankan bidang cookie/header yang diberi nama alat tersebut. cookie tanpa nama mempertahankan alat lengkap Header cookie.

  1. Abaikan semua penggantian sisi permintaan untuk permintaan tersebut:

http X-Longshot-Override: off

Adaptor menghapus header anotasi ini sebelum meneruskannya. Otentikasi proxy, cakupan dan batasannya masih berlaku. Konfigurasikan anotasi di alat asal; memasukkannya ke halaman web target bukanlah mekanisme konfigurasi jembatan.

Misalnya saja menjaga session dilindungi memungkinkan ZAP memvariasikannya sementara pembantu dapat terus memperbarui yang tidak terkait preferences kue. Untuk pengujian Cookie/Otorisasi/Agen-Pengguna yang menyeluruh, menonaktifkan penggantian tersebut akan menghindari ketergantungan pada heuristik deteksi perubahan.

Otorisasi Browser dan header lainnya

Otorisasi Browser diikutsertakan melalui konfigurasi JSON. Itu diambil dari permintaan sebenarnya oleh tab target yang dipasangkan hanya setelah mengaktifkan sumber browser. Ini bukan pembaca otomatis untuk setiap token di Penyimpanan lokal atau memori aplikasi. Permintaan browser yang lebih baru mungkin diperlukan sebelum nilai yang diamati ada. Mematikan Otorisasi browser akan menghentikan nilai yang diambil yang diberikan oleh helper.

Memilih Agen Pengguna browser atau Bahasa Terima hanya akan mengubah bidang HTTP tersebut. Itu tidak menjalankan JavaScript target, menyegarkan token CSRF badan, mereproduksi TLS browser, atau menjamin penerimaan WAF. Otentikasi terikat IP/perangkat dan penyegaran OAuth masih memerlukan alur kerja aplikasinya.

Penanganan VHOST / Host

Helper asli tidak menggantikan alias jembatan internal ke dalam bidang Host alat. Biarkan alat mengirimkan nilai Host yang diperlukan untuk pengujian host virtual resmi. Untuk HTTPS, tujuan CONNECT tetap menjadi target resmi sementara header Host alat dapat dipertahankan.

Mengubah header Host tidak memberikan akses ke tujuan jaringan lain. Proksi terbalik dapat mengarahkannya ke aplikasi lain; sertakan perilaku host virtual tersebut dalam otorisasi penilaian. Format header byte yang salah dan framing yang bertentangan berada di luar proksi yang diuraikan ini.

Audit dan privasi

Lalu lintas asli menunjukkan metadata permintaan dan nama bidang yang diubah/dilindungi. Audit menghilangkan nilai rahasia cookie/header, nilai kueri, dan isi. Ini tidak berarti proxy tidak pernah menangani rahasia: proxy harus memprosesnya untuk mengirimkan lalu lintas yang diautentikasi. Alat eksternal menyimpan riwayat/hasilnya sendiri, yang dapat berisi nilai-nilai tersebut.

Jauhkan token konfigurasi pribadi, kunci CA, dan direktori data dari laporan/arsip sumber. Mengunduh konfigurasi dengan nilai Otorisasi khusus dapat membuat file yang berisi nilai tersebut.

Alat eksternal dan pemindaian ZAP yang sebenarnya

Mulailah dengan satu permintaan

Pasangkan jembatan, lalu uji target lokal sebenarnya:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  'http://localhost:8080/'

Gunakan jalur baca terautentikasi yang diketahui untuk memeriksa perilaku sesi. 200 dari halaman beranda publik tidaklah cukup. Konfirmasikan permintaan muncul di lalu lintas asli, penyimpanan cookie yang dipilih sudah benar, dan alat menerima konten yang diharapkan. Jangan menyimpulkan semua permintaan selanjutnya menggunakan proxy hanya karena yang ini melakukannya.

Proksi keluar ZAP

  1. Instal/mulai ZAP secara terpisah dan gunakan sesi ZAP khusus penilaian.
  2. Di ZAP Pilihan → Jaringan → Koneksi, aktifkan proksi HTTP keluar.
  3. Tetapkan tuan rumah 127.0.0.1, pelabuhan 8900 (atau port proxy yang dikonfigurasi saat ini).
  4. Aktifkan otentikasi proxy: nama pengguna bridge, sandi token adaptor saat ini.
  5. Nonaktifkan proksi SOCKS milik ZAP untuk rantai ini. Pengaturan SOCKS ZAP lebih diutamakan daripada proxy HTTP-nya.
  6. Periksa pengecualian proxy HTTP agar target yang dituju tidak dilewati, terutama untuk layanan lokal.
  7. Konfigurasikan CA adaptor dalam pengaturan kepercayaan/verifikasi TLS yang berlaku pada alat tersebut bila diperlukan. Lokasinya dicetak saat adaptor dinyalakan.
  8. Akses URL target sebenarnya dari ZAP dan verifikasi riwayatnya ditambah metadata jembatan.
  9. Tentukan target/konteks ZAP, kebijakan pemindaian, pengecualian, pemeriksaan otentikasi, dan tingkat permintaan sederhana. Jalankan pemindaian laba-laba/aktif yang sebenarnya sesuai izin.
  10. Tinjau temuan dan liputan di ZAP. Saat dengan sengaja mengaburkan bidang autentikasi cookie/header, gunakan mekanisme perlindungan/bypass di atas.

Pengaturan ini adalah milik ZAP sambungan keluar, bukan pendengar proksi browser masuk lokalnya. Firefox tidak perlu dikonfigurasi ulang untuk menggunakan ZAP hanya untuk memasok cookie tab yang dipilih ke rantai ini.

ZAP menghasilkan muatan aturan aktif yang sebenarnya; mitmproxy mengirimkan permintaan asli yang dihasilkan. Perubahan jangka panjang hanya bidang permintaan yang diikutsertakan. Hal ini meningkatkan konteks sesi alat eksternal yang dapat digunakan tetapi tidak membuat pemindaian alat mana pun menjadi komprehensif. Lihat Pengaturan koneksi ZAP.

URL proksi yang berisi kredensial bersifat sensitif. Gunakan konfigurasi penilaian pribadi alat Anda jika tersedia. Jangan tempelkan token saat ini ke dalam laporan bersama. Untuk setiap alat, konfirmasikan lalu lintas yang dirutekan daripada berasumsi bahwa setiap protokol atau subproses mematuhi pengaturan proksi HTTP-nya.

Contoh perpustakaan standar Linux Python untuk target lokal hanya-baca; itu meminta token alih-alih melakukan hardcoding dan menghapus bypass proksi lingkungan untuk proses ini:

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

Verifikasi permintaan dalam lalu lintas asli; platform lain dapat memiliki aturan bypass proxy sistem tambahan. Contoh curl dengan eksplisit --noproxy '' adalah pemeriksaan validasi rute loopback yang lebih sederhana. Klien HTTPS Python juga memerlukan konteks SSL/bundel CA yang mempercayai sertifikat adaptor.

Jeda dan kesalahan

Jeda permintaan asli memblokir jalan keluar asli yang baru. Status autentikasi 401/419/440, HTTP 429, penutupan tab/perubahan di luar asal, atau batas anggaran juga dapat menjeda pekerjaan. Lanjutkan setelah memeriksa tab dilanjutkan hanya setelah meninjau status pemasangan.

Berhenti dan putuskan sambungan mengakhiri pemasangan browser; itu tidak menghentikan proses Node yang dimulai secara terpisah. Gunakan Ctrl+C di terminalnya untuk menghentikan proses itu.

Permintaan dalam penerbangan mungkin selesai. Klien proxy menerima kesalahan untuk pekerjaan yang diblokir; adaptor tidak menangguhkan proses alat yang sewenang-wenang atau memutar ulang permintaannya. Periksa permintaan mana yang berhasil dan gunakan kontrol coba lagi/lanjutkan alat itu sendiri. Memulai ulang/memasangkan ulang akan mengubah token dan memerlukan pembaruan autentikasi alat.

401/419/440 mungkin diharapkan dalam pengujian autentikasi negatif yang disengaja. Jika perlu, sesuaikan session.pauseStatuses untuk yang ditinjau, jalankan dan mulai ulang; adaptor tidak menyimpulkan apakah setiap kegagalan otentikasi merupakan penyelidikan yang dimaksudkan.

Perutean Tor dan bawang

Permintaan Longshot berbasis browser mengikuti jaringan browser yang dipilih. Adaptor asli adalah proses yang berbeda dan tidak mewarisi pengaturan proksi Firefox/Tor Browser.

SOCKS/Tor adalah mati secara default dalam konfigurasi asli. Untuk penilaian bawang yang sah, gunakan layanan SOCKS yang dikonfigurasi secara eksplisit dengan resolusi nama host jarak jauh, misalnya penggantian ini jika itu benar-benar pendengar Tor lokal Anda:

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

Contoh ini tidak memulai Tor atau menetapkan bahwa port 9050 ada. Pilih layanan terkonfigurasi yang sebenarnya; contoh Tor Browser mungkin menggunakan pendengar yang berbeda. Nyalakan ulang adaptor dan pasangkan kembali. HTTP(S) upstream.url dan routing.socks5 saling eksklusif.

Shim asli menyelesaikan nama host melalui SOCKS dan tidak memiliki fallback langsung yang senyap. Tanpa rute upstream/SOCKS yang dikonfigurasi secara eksplisit, tujuan bawang langsung ditolak sebelum DNS target. URL SOCKS juga dapat merujuk ke terowongan SSH resmi atau layanan SOCKS5 lainnya; ini secara intrinsik bukanlah bukti perutean Tor.

Berbagi cookie tidak membuat IP keluar rute asli atau sidik jari TLS/browser identik dengan Firefox. Tantangan atau pengikatan sesi mungkin menolaknya. Periksa rute dan sesi yang diharapkan secara mandiri.

Nuclei asli terisolasi yang diluncurkan oleh Agent API berbeda: relai bawaannya tidak memiliki rute Tor/SOCKS dan memblokir target bawang sebelum DNS sistem. Gunakan pemeriksaan sisi browser yang memenuhi syarat di browser yang dimaksud, atau alat eksternal yang dikonfigurasi secara terpisah melalui proksi asli. Jangan menganggap kotak centang Nuclei mewarisi routing.socks5 dari Jembatan Peramban.

Agen API, MCP, dan klien model lokal

Daftarkan dan sambungkan host asli

Dari yang ditahan sumber direktori yang berisi manifest.json dan bridge/:

node bridge/bin/longshot-bridge install

Ini mendaftar longshot.bridge dan peluncur yang mereferensikan folder sumber dan Node yang dapat dieksekusi. Simpan keduanya di tempatnya. Jika salah satu pindah, daftar lagi.

Buka Pengaturan → Koneksi & pengaturan → Hubungkan jembatan asli dan memberikan izin perpesanan asli Firefox. Host dapat memulai daemonnya secara otomatis. Jika sengaja menjalankan daemon secara manual:

Hindari daemon kedua pada port/direktori data yang sama. Putuskan sambungan menutup koneksi asli ekstensi; itu tidak serta merta menghentikan daemon yang dimulai secara independen.

Node.js 20+ diperlukan. MCP perpesanan asli tidak memerlukan instalasi Python/mitmproxy proxy. Linux adalah pengaturan yang dilakukan. dukungan pendaftaran macOS disediakan tetapi tidak diverifikasi waktu proses di sini; rilis ini tidak memiliki penginstal host asli Windows Firefox. Mendaftar di WSL tidak mendaftarkan host untuk Windows Firefox. Isolasi Nuclei asli hanya untuk Linux.

Layanan bawaan: http://127.0.0.1:8765. Alamat localhost ini adalah API kontrol, bukan target yang dipindai. Token/soket defaultnya adalah $XDG_DATA_HOME/longshot atau ~/.local/share/longshot. Adat --port dan --data-dir harus cocok di seluruh instalasi, servis, dan mcp. Gunakan jalur data Unix yang pendek karena jalur soketnya memiliki batas 100 byte.

Contoh REST

Dari folder sumber yang sama:

longshot_token_file="$(node bridge/bin/longshot-bridge token-path)"
longshot_api_token="$(cat "$longshot_token_file")"

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/health

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/targets

Itu token-path perintah mencetak nama file, bukan token. API menggunakan autentikasi pembawa, tidak seperti autentikasi nama pengguna/kata sandi proxy. Ini menolak klien non-loopback dan permintaan Asal browser dan tidak mengekspos API CORS umum. Jangan mempublikasikannya melalui proxy terbalik publik.

Mulai pemindaian kecil hanya setelah menghubungkan/mengaktifkan target yang dituju dan memeriksa opsi yang disimpan:

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  -H 'Content-Type: application/json' \
  --data '{"target_id":"PROFILE_ID","mode":"safe","budget":150}' \
  http://127.0.0.1:8765/v1/scans

Ganti PROFILE_ID dengan ID profil yang dipilih. safe memetakan ke Spider saja; itu tidak mengatur ulang setiap opsi lanjutan yang disimpan atau bertindak sebagai penggantian universal. Permulaannya tidak sinkron. Baca ID proses yang dikembalikan, lalu pantau /v1/scans/RUN_ID, /eta, /findings atau /report?format=html. POST /pause, /resume dan /stop mengendalikan lari. Konsultasikan diautentikasi /openapi.json untuk skema yang tepat.

Profil dukungan REST/JSON-RPC, pemindaian, temuan/laporan, templat, OAST, dan operasi sesi. /rpc membawa JSON-RPC; /mcp menawarkan MCP HTTP, dengan opsi stdio dan SSE. String versi protokol/API layanan mungkin mempertahankan versi skema yang lebih lama; gunakan manifes ekstensi untuk versi rilis UI yang diinstal.

Untuk pekerjaan asli yang diluncurkan oleh Longshot:

  1. Instal biner Nuclei resmi secara terpisah dan ekspos di PATH atau set LONGSHOT_NUCLEI sebelum memulai API Agen.
  2. Menyediakan bubblewrap Linux dengan namespace pengguna/jaringan yang tidak memiliki hak istimewa.
  3. Untuk templat tanpa kepala, sediakan browser yang diperlukan, opsional melalui LONGSHOT_CHROME.
  4. Daftarkan/hubungkan API Agen dan periksa kemampuan asli yang dilaporkan.
  5. Impor templat yang telah ditinjau dan file pembantu relatif apa pun yang diperlukan.
  6. Aktifkan Eksekusi Nuclei penuh asli dan hanya diperlukan kemampuan Kode/JavaScript, Tanpa Kepala, atau File tambahan.
  7. Untuk templat file, atur LONGSHOT_FILE_ROOT ke daftar izin baca-saja yang eksplisit sebelum memulai host.
  8. Simpan, tinjau, dan setujui proses tersebut; periksa alasan Siap/Diblokir dan keluaran yang diberi tag pelaksana.

Pekerja memiliki sistem file/namespace jaringan yang terisolasi, penyimpanan sementara pribadi, dan eksekusi terbatas melalui relai target. Mereka tidak secara otomatis menerima cookie Firefox, penyimpanan lokal browser, atau rute Tor Firefox. Sesi tanpa kepala diisolasi. Templat asli yang diblokir tidak berarti dampak kerentanan negatif.

Templat kode/JavaScript asli memerlukan tanda tangan yang dipercaya oleh mesin resmi. LONGSHOT_NUCLEI_CERT dapat menunjuk ke sertifikat penulis publik yang ditinjau; tuan rumah tidak menandatangani impor secara otomatis atau memasang kunci penandatanganan pribadi. Templat file asli tidak dapat dengan bebas membaca direktori home host. Sakelar file/kode/tanpa kepala tambahan tetap terpisah dari impor templat umum.

Relai asli mendukung koneksi target/penyedia yang dibatasi, bukan akses jaringan sembarangan. Target bawang, isolasi/runtime yang tidak tersedia, pengalamatan target yang tidak didukung, atau cakupan jalur yang tidak kompatibel dapat memblokir eksekusi. Pendaftaran Interactsh asli adalah milik Nuclei, terpisah dari klien OAST browser Longshot. Gunakan bukti hasil aktual dan laporan kemampuan platform, bukan label “mesin penuh”, untuk memutuskan apa yang dijalankan.

Penjelajah API

Hubungkan dan jelajahi terlebih dahulu, lalu pilih Periksa halaman saat ini. Impor yang disediakan pengembang OpenAPI JSON deskripsi bila tersedia, hingga 2 MB. Bunyinya JSON lokal, bukan halaman jarak jauh atau file YAML sembarangan. Referensi spesifikasi lokal dan contoh/default permintaan yang tersedia dapat memberikan masukan yang didukung secara konkret; nilai/tubuh yang hilang dan konstruksi yang tidak didukung meninggalkan kesenjangan.

Titik akhir adalah sebuah alamat; operasi adalah alamat plus metode. Input kueri muncul setelahnya ?, masukan jalur di jalur alamat, dan masukan isi dalam konten yang dikirimkan. Operasi yang terdaftar adalah inventaris, bukan bukti bahwa akun saat ini dapat mengakses setiap objek yang dialamatkannya.

Gunakan Pengulang di samping operasi GET/HEAD yang didukung untuk menyiapkan permintaan tanpa harus mengirimkannya. Tinjau URL/metode/masukan, lalu kirimkan dengan sengaja. Operasi penulisan khusus inventaris masih mengharuskan Anda menyiapkan permintaan yang sesuai dan mendapatkan persetujuan menulis.

Repeater dan Bandingkan

Repeater membuat permintaan cakupan baru menggunakan sesi browser terikat. GET/HEAD/OPTIONS menggunakan rute biasa. Metode penulisan, perubahan isi, dan kemampuan destruktif/unggah tetap tunduk pada kebijakan dan persetujuan. Nilai Cookie/Otorisasi/Host yang dikelola tidak dapat diganti secara bebas melalui editor headernya; gunakan rute alat eksternal asli untuk pengujian header/cookie yang dikonfigurasi secara eksplisit.

Ikuti pengalihan asal yang sama mengontrol apakah Anda memeriksa pengalihan itu sendiri atau respons akhir yang diizinkan. Pengalihan di luar cakupan bukanlah otorisasi menyeluruh. Simpan isi tanggapan bila diperlukan untuk ditinjau, lalu pilih dua tanggapan yang disimpan Bandingkan. Bandingkan tidak mengirimkan permintaan; konten dinamis, status login, pembatasan, atau halaman WAF dapat menjelaskan perbedaannya.

Header yang diizinkan menggunakan array pasangan nama/nilai JSON; bidang sensitif/dikelola browser/pembingkaian dilindungi. Penulisan ulang metode/isi/status dari permintaan jaringan yang ditahan tidak tersedia. Hanya lalu lintas HTTP tab target terpilih yang memenuhi syarat. Transportasi pemindai melewati intersepsi untuk menghindari kebuntuan. Lalu lintas proksi asli eksternal berada di luar pencegat browser ini. Pesan WebSocket setelah pemutakhiran memerlukan meja kerja saluran terpisah.

WebSocket, SSE dan utilitas

Pilih saluran dalam cakupan yang ditemukan atau masukkan URL persisnya. Mendengarkan dan mengirim bingkai khusus adalah operasi terbatas yang disetujui, bukan pemindai protokol umum. Teks kesalahan yang diambil adalah petunjuk; itu tidak menetapkan otorisasi pesan atau cacat ras/logika.

Utilitas menyandikan/mendekode nilai, menghitung SHA-256, memformat JSON, dan memeriksa klaim JWT secara lokal. Penguraian kode JWT bukanlah verifikasi tanda tangan dan tidak menetapkan bahwa server menerima token palsu. Input yang diubah tidak secara otomatis dijalankan atau dikirimkan.

Cakupan 10 Teratas OWASP

Buka Opsi pemindaian → Informasi untuk tabel implementasi 44 entri yang dapat dicari/difilter, juga dapat dijangkau melalui tombol Informasi halaman. Ini menggunakan OWASP Teratas 10:2025 dengan referensi tahun 2021 yang lebih lama untuk orientasi. SSRF sekarang dikelompokkan dalam Kontrol Akses Rusak. Contoh dapat tumpang tindih dengan kategori; daftar tersebut bukanlah katalog CWE yang lengkap.

Label dukungan:

  • Pemeriksaan aktif: aturan implementasi khusus ada saat diaktifkan, untuk input yang didukung.
  • Verifikasi opsional: opsi tambahan, izin, penyedia, atau prasyarat eksekusi berlaku.
  • Hanya indikator: sinyal/perbandingan pasif yang memerlukan interpretasi manual.
  • Bergantung pada template: templat dan pelaksana yang diimpor menentukan kondisi yang diuji.
  • Tidak tercakup: tidak ada pemverifikasi bawaan khusus untuk kelas itu; muatan khusus generik tidak menetapkan cakupan secara otomatis.

Ini adalah audit kemampuan berbasis sumber, bukan persentase deteksi yang diukur. Ini menjelaskan pemindai internal Longshot dan fase opsionalnya, bukan seluruh rangkaian aturan ZAP eksternal.

Validator sesi memeriksa apakah login yang dikonfigurasi masih tampak valid. Tidak ada serangan kredensial umum, pengujian alur kerja MFA/reset, audit lockout, atau verifikasi pengambilalihan akun.
A07 Kelemahan verifikasi JWT, OAuth, OIDC dan SAML Tidak tercakup Utilitas dapat memecahkan kode JWT secara lokal untuk pemeriksaan manual. Decoding bukan verifikasi tanda tangan. Tidak ada uji kebingungan algoritma, pemalsuan token, aliran pengalihan, atau federasi secara umum.
A08 Jalur panggilan balik Log4Shell Verifikasi opsional Aktifkan Log4Shell dan OAST dengan persetujuan. Canary panggilan balik JNDI ditempatkan di input pertama yang tersedia dan Versi X-Api. Interaksi yang cocok memerlukan atribusi dan peninjauan; itu tidak membuktikan eksekusi kode. Titik penyisipan yang terbatas dan target jalan keluar dapat melewatkan jalur yang rentan.
A08 Deserialisasi yang tidak aman Bergantung pada template Opsi deserialisasi memilih templat impor yang memenuhi syarat yang diberi tag untuk deserialisasi. Tinjau pelaksana dan prasyaratnya. Tidak ada penemuan format objek umum, generator rantai gadget, atau pemverifikasi deserialisasi universal.
A08 Pembaruan yang tidak ditandatangani, data aplikasi palsu, dan kontrol integritas Tidak tercakup Respons yang diambil dan data yang diterjemahkan dapat membantu analisis manual. Tidak ada model kepercayaan aplikasi, validasi tanda tangan pembaruan, audit tanda tangan data, atau verifikasi penugasan massal secara umum.
A09 Log keamanan, peringatan, integritas log, dan deteksi insiden tidak ada Tidak tercakup Longshot mencatat bukti pemindaiannya sendiri dan jurnal permintaan lokal. Log pemindai tidak mengungkapkan apakah aplikasi mencatat atau memberi peringatan dengan benar; memeriksa bukti server/SIEM dan menjalankan skenario yang dipantau.
A10 Kebocoran informasi dari tanggapan yang luar biasa Hanya indikator Pengungkapan kesalahan pasif dan kontrol injeksi aktif dapat melihat jejak tumpukan yang dipilih dan kesalahan database yang baru diperkenalkan. Hanya mengembalikan bukti. Kesalahan umum atau HTTP 500 saja bukanlah kerentanan yang terverifikasi.
A10 Perilaku buka-gagal, kegagalan rollback, dan pemulihan pengecualian yang tidak aman Tidak tercakup Perbedaan status/tubuh dapat memandu penyelidikan manual. Tidak ada injeksi kesalahan umum, pernyataan rollback transaksi, pemulihan kerusakan, atau model kontrol akses jalur pengecualian.
Lainnya Penyelundupan permintaan HTTP, format framing yang salah, keracunan cache, dan serangan Host Tidak tercakup Pemindai internal menggunakan jaringan browser dan melindungi header terkelola. Alat eksternal melalui proxy asli terpisah. Transportasi HTTP yang diurai juga bukan merupakan penyelundupan byte-transparan atau mesin TLS khusus.
Lainnya Kerentanan aplikasi WebSocket / SSE Hanya indikator Tes saluran terbatas opsional menangkap pertukaran dan melaporkan teks kesalahan yang dipilih. Tidak ada otorisasi yang sadar protokol, pengaburan skema pesan, pembajakan WebSocket lintas situs, atau pemverifikasi logika bisnis.
Lainnya Unggahan file, logika GraphQL/SOAP, dan protokol biner tidak didukung Tidak tercakup Permintaan HTTP yang ditemukan dapat mengekspos input skalar yang didukung untuk pemeriksaan umum. Tidak ada eksekusi unggahan khusus, otorisasi/kompleksitas GraphQL, SOAP komprehensif, atau pemindai protokol biner.

Menafsirkan cakupan proses yang sebenarnya

Peta referensi WSTG yang lengkap mencakup subset otomatis, pekerjaan berbantuan, dan penilaian manual. Di Cakupan masukan aktual:

  • Selesai berarti aturan yang diterapkan selesai pada masukan itu, bukan masukan tersebut aman.
  • Sebagian berarti beberapa pekerjaan dijalankan tetapi ada batasan, gangguan, atau kondisi lain yang menghalangi penyelesaian.
  • Dilewati berarti rule/inputnya tidak berjalan; periksa alasannya.

WAF, peran yang hilang, sesi yang tidak valid, alur kerja yang tersembunyi/belum dikunjungi, isi permintaan yang tidak tersedia, CSP, atau anggaran yang habis dapat membuat masukan yang rentan belum teruji. Pemasangan proxy asli tidak menghilangkan batasan tersebut dari pemindai internal. Versi CVE yang diamati, header yang hilang, atau respons berbeda tidak secara otomatis merupakan eksploitasi.

Rilis 2.18.1 lulus 192 pengujian unit/regresi otomatis, delapan pemeriksaan Chrome nyata dan delapan pemeriksaan Firefox nyata, termasuk verifikasi ZIP/YAML CSP dan lalu lintas ZAP asli terhadap perlengkapan SQLite yang dimiliki. Pustaka peramban resminya diverifikasi byte demi byte dan pembangunan kembali sumber bersih mereproduksi Firefox XPI dengan tepat. Tes tersebut memvalidasi perilaku implementasi yang disebutkan; mereka tidak menunjukkan deteksi setiap tantangan Toko Jus, WebGoat, bWAPP, atau NodeGoat. Hasil ZAP SQLi eksternal memverifikasi jalur proksi, bukan penarikan kembali Longshot di semua kerentanan.

Penyimpanan browser dan file sesi opsional

Penyimpanan browser tetap aktif secara independen dari jembatan lokal mana pun. Itu menyimpan riwayat, temuan, ulasan, inventaris, dan opsi per profil. Badan-badan tanggap dapat dipertahankan dengan upaya redaksi terbaik; lalu lintas yang diamati browser sering kali memiliki metadata tanpa isi yang diambil.

Untuk pos pemeriksaan file otomatis:

  1. Daftar/sambungkan API Agen, bukan hanya Jembatan Peramban.
  2. Buka Pengaturan → Sesi penilaian → Instruksi.
  3. Masukkan yang absolut Folder sesi di komputer Agen API.
  4. Aktifkan Secara otomatis menyimpan file sesi dan pilih Simpan pengaturan sesi.
  5. Gunakan Simpan sesi sekarang untuk pos pemeriksaan segera; perubahan normal juga memicu penyimpanan.
  6. Gunakan Ekspor sesi saat ini / Impor file sesi untuk transfer manual; impor manual tidak memerlukan host asli.

File menggunakan ID profil stabil dengan .longshot.json, mengizinkan profil eksplisit untuk satu asal. Mereka adalah arsip penilaian yang dapat dibaca dan tidak terenkripsi dan dapat berisi data aplikasi, templat yang dibuat, dan isi yang disimpan. Cookie yang dikelola browser, token penyedia, dan izin eksekusi tidak termasuk.

Penulisan adalah pos pemeriksaan file pribadi atom. Penghentian mendadak hanya dapat memulihkan penyimpanan terakhir yang telah selesai. Pemindaian berjalan yang dipulihkan menjadi terganggu. Jika jembatan terputus, penyimpanan browser dilanjutkan dan penyimpanan file menunggu; pos pemeriksaan yang diaktifkan yang belum terselesaikan mungkin memerlukan penyambungan kembali atau penonaktifan penyimpanan file sebelum berpindah target. Ukuran file sesi maksimum adalah 256 MB dengan kesalahan eksplisit.

Penilaian ekspor arsip berbeda dengan Unduh konfigurasi di Jembatan Peramban. Yang pertama menyimpan bukti/pilihan penilaian; yang terakhir menyimpan pengaturan proxy asli.
