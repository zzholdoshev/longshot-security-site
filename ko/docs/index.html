Longshot 2.18.1 — 사용 안내 및 기능 설명

Longshot에 대해 2026년 11월 10일에 업데이트됨 2.18.1 (Firefox 및 Chrome 버전) 및 해당 버전 기본 HTTP/HTTPS 도구 프록시. 이는 일반적인 2.11.1 튜토리얼을 대체합니다. 아래 지침에서는 제한 사항을 포함하여 출시된 구현에 대해 설명합니다. 이전 브리지 예제는 이번 릴리스와 호환되지 않습니다.

Longshot은 승인된 웹 애플리케이션 평가를 위한 브라우저 세션 워크벤치입니다. 이는 검색, 자체 JavaScript 활성 스캐너, 수동 HTTP 도구, 가져온 템플릿, 결과 검토 및 보고서를 결합합니다. 선택적 브라우저 브리지를 사용하면 외부 도구가 자체 기본 HTTP 요청을 보내는 동안 선택된 Firefox 세션 값을 사용할 수 있습니다.

유용한 첫 번째 단계는 다음과 같습니다. 애플리케이션 열기 → 로그인 → 해당 탭에서 Longshot 실행 → 연결 → 세션 유효성 검사 → 입력 검색 → 선택한 검사 실행 → 증거 검토.

앱이 금전이나 민감한 사용자 정보를 다룬다면 전문 사이버보안팀에 평가를 의뢰하세요. AI로 개발한 앱도 마찬가지입니다. 확장 프로그램 스캔은 권한 검증, 비즈니스 로직 검토, 독립적인 보안 평가를 대신하지 못합니다. 발견 사항이 없다고 해서 안전이 입증된 것은 아닙니다.

이 문서에서는 명령에 대해 설명합니다. 업데이트해도 소프트웨어 설치, 호스트 등록, 브라우저 설정 변경 또는 검사 실행은 이루어지지 않습니다. 승인된 평가 대상에 대해서만 예제를 실행하세요. 샘플 http://localhost:8080 내장된 Longshot 서비스가 아닌 로컬 대상 예시입니다.

AI로 만든 앱, 그대로 출시해도 될까요?

이것을 상상해 보세요: 앱이 가동되고 공격자가 결함을 발견하면 사용자는 계정 잔액이 0이 되도록 개설합니다. 모든 돈이 사라졌습니다.

코드는 설득력이 있어 보였습니다. AI는 안전해 보인다고 말했습니다. 그것만으로는 충분하지 않았습니다.

언어 모델의 답변은 달라질 수 있습니다. 취약점을 놓치고도 확신에 찬 답을 내놓을 수 있죠. Longshot으로 한 번 더 검증하세요.

Longshot은 Firefox를 귀하가 구축하는 웹 앱을 위한 보안 워크벤치로 바꿔줍니다. 실제로 실행 중인 애플리케이션에 대해 반복 가능한 검사를 실행하고, HTTP 증거를 검사하고, 사용자가 비용을 지불하기 전에 약점을 조사하십시오.

수표 커버 지원 SQL/NoSQL 주입, 서버 측 코드 및 템플릿 주입, 반영된 XSS 후보, 경로 탐색/파일 포함, 오픈 리디렉션 및 CRLF/헤더 주입, 선택적 라이브 DOM XSS 검증이 포함됩니다. 검토 취약한 보안 헤더, 쿠키 및 CORS 정책, 노출된 구성 및 오류 공개, 추가 공격 클래스에 대한 선택적인 검사가 포함됩니다.

이미 사용하고 있는 브라우저 탭에서 시작하세요. 라이브 쿠키를 유지하고, 세션 유효성 검사를 구성하고, 세션 손실 후 복구하고, 각 대상의 설정, 기록 및 결과를 체계적으로 유지합니다.

AI에게 맡기되, 결과는 확인하세요. MCP를 통해 에이전트를 연결하여 승인된 검사를 실행하고 결과를 검사합니다. 기본 브라우저 브리지를 사용하면 쿠키 값을 수동으로 복사하지 않고도 ZAP, sqlmap, 컬, ffuf 또는 wget을 연결된 브라우저 세션으로 가져올 수 있습니다. 도구는 자체 HTTP 요청과 페이로드를 보냅니다. 브라우저 쿠키 재정의는 기본적으로 켜져 있으며 끌 수 있습니다.

고급 사용자는 호환되는 항목을 가져올 수 있습니다. CVE 템플릿 그리고 상관관계 OAST 콜백 그 원인이 된 프로브로. 평결을 검토하고 기록한 후 풍부한 증거를 내보냅니다. HTML, JSON, CSV 또는 SARIF 보고서, 인쇄/PDF 출력 포함. 결과를 다음과 같이 설명합니다. 시네마틱 뷰어, 라이브 CSS/JavaScript 페이지 컨텍스트, 애니메이션 3D 요소, 일시 중지 및 전체 화면 컨트롤을 포함합니다. 선명한 테마를 선택하고 작업 공간에 맞게 모션과 사운드를 맞춤설정하세요.

안전하다는 확신 전에, 먼저 확인하세요. Longshot.

출판 노트

계정 손실 이야기는 실제 고객에 대한 주장이나 Longshot이 금전적 손실을 방지한다는 보장이 아니라 가설입니다. 확장 프로그램은 지속적인 공격 차단이 아닌 평가를 수행합니다. 조사 결과에는 검토가 필요합니다. 적용 범위 표에는 제한된 지원과 수동 전용 격차가 설명되어 있습니다. DOM 분석에는 범용 DOM 공격 범위가 아닌 지표 및 지원되는 실행 카나리아가 포함됩니다. 영화 시퀀스는 증거를 설명합니다. 착취 증거를 추가하지 않습니다.

MCP 및 브라우저 브리지에는 로컬 설정이 필요합니다. 기본 도구 프록시는 별도의 Node/Python/mitmproxy 프로세스를 사용하며 HTTPS 차단에는 어댑터 CA에 대한 도구의 신뢰 구성이 필요합니다. 바이트 투명 원시 TCP가 아닌 구문 분석된 HTTP 전송입니다. 쿠키 재정의를 비활성화할 수 있습니다. 브라우저 쿠키나 User-Agent는 브라우저와 동일한 네트워킹이나 WAF 수용을 보장하지 않습니다. 외부 ZAP는 별도로 설치된 상태로 유지됩니다. 템플릿 실행은 호환성/런타임에 따라 다릅니다. OAST에는 구성된 공급자가 필요합니다. 인증 검증에는 의미 있는 보호 엔드포인트/마커가 필요합니다. 대상 프로필은 별도의 평가 데이터를 제공합니다. 탭/컨테이너는 쿠키 세션을 제공합니다.

민감한 데이터나 돈을 처리하는 애플리케이션의 경우 사이버 보안 팀을 고용하고 평가의 일부로 Longshot을 사용하세요. 귀하가 소유하고 있거나 테스트 권한이 있는 응용 프로그램에만 사용하십시오.

이전에 생성된 캠페인 이미지를 재사용하는 경우 해당 이미지에 컴포지션으로 라벨을 지정하고 정확한 픽셀 UI가 필요한 경우 실제 현재 스크린샷을 사용하세요. 이 튜토리얼에서는 모양 섹션의 실제 2.18.1 유효성 검사 스크린샷을 연결합니다. 새로운 8개의 이미지로 구성된 캠페인 팩이 포함되어 있지 않으며 제3자 보증을 주장하지도 않습니다.

비공개 브라우징 권한 및 설정에 따라 선택된 컨텍스트 이번 릴리스에서는 비활성화되었습니다.

Chrome 버전 설치

  1. 다운로드 크롬 ZIP 위/아래의 릴리스 링크에서 복사하여 보관하는 폴더에 추출합니다.
  2. 열기 chrome://extensions, 활성화 개발자 모드, 선택 포장을 푼 짐을 선택한 다음 다음이 포함된 추출된 폴더를 선택합니다. manifest.json.
  3. 승인된 애플리케이션을 열고 로그인한 후 해당 탭에서 Longshot을 실행하고 연결하세요.
  4. 스캔 및 기본 페어링 중에 워크벤치 탭을 열어두세요. 닫으면 실제 엔진 작업이 종료됩니다. 저장된 증거는 불확실한 요청을 다시 하지 않고 그대로 남아 복원됩니다.
  5. 기본 도구 프록시 시작의 경우 Chrome에서 표시하는 정확한 출처를 사용하세요. chrome-extension://YOUR_INSTALLED_ID, Firefox가 아닌 moz-extension:// 원산지. 프록시는 실제 대상 URL을 사용합니다. 호스트 파일 항목이 필요하지 않습니다.

Chrome 에이전트 API/MCP 등록

고정된 도우미 종속성을 설치한 후 유지된 전체 소스 체크아웃에서 다음을 수행합니다.

npm --prefix native-bridge ci --omit=dev
node bridge/bin/longshot-bridge install --browser chrome \
  --extension-id YOUR_INSTALLED_32_LETTER_ID \
  --port 8775 --data-dir /absolute/private/longshot-chrome
node bridge/bin/longshot-bridge mcp \
  --port 8775 --data-dir /absolute/private/longshot-chrome

크롬용 --browser chromium. 실제 ID를 사용하세요. chrome://extensions; 스토어 에디션을 설치하면 다른 ID가 제공되는 경우 다시 등록하세요. 별도의 포트/데이터 디렉토리는 Firefox 호스트와의 충돌을 방지합니다. 이 에이전트 API는 HTTP 도구 프록시(기본 포트 8900/8901)와 다릅니다. Linux는 테스트된 기본 호스트 플랫폼입니다. macOS 등록은 구현되었지만 여기에서는 테스트되지 않았으며 Windows 기본 호스트 설치 프로그램이 제공되지 않습니다.

자세한 브라우저 브리지 구성은 확장 프로그램에서도 사용할 수 있습니다. 브라우저 브릿지 → 정보 대화. 긴 형식의 README와 새로운 플랫폼/개인정보 보호 문서는 영어로 제공됩니다. 번들 UI 언어 선택은 대상 증거, 페이로드 또는 실행 가능한 예제를 번역하지 않습니다.

무엇이 어디에서 실행되는가

"브리지"라는 단어는 다양한 구성 요소를 나타냅니다. 작업에 필요한 구성요소를 선택하세요.

구성요소 실행 위치 기능 기본 연결
내장 스캐너, 리피터, 퍼저 Firefox 확장 및 바인딩된 대상 탭 Longshot의 JavaScript 규칙을 사용한 브라우저 세션 HTTP 검사 외부 프록시 프로세스가 필요하지 않습니다.
브라우저 브리지/네이티브 도구 프록시 로컬 노드 코디네이터와 별도로 설치된 mitmproxy 외부 도구의 자체 HTTP/HTTPS 요청을 전달합니다. 선택적으로 Firefox에서 쿠키와 선택한 헤더를 재정의합니다. HTTP 프록시 127.0.0.1:8900; 확장 제어 127.0.0.1:8901
에이전트 API/기본 메시징 브리지 Firefox에 등록된 로컬 노드 서비스 REST/MCP/UI 자동화, 평가 파일 및 선택적 기본 Nuclei 실행 API http://127.0.0.1:8765
외부 ZAP, 컬, ffuf, sqlmap 또는 Nuclei CLI 귀하가 설치한 별도의 프로세스 선택적으로 기본 도구 프록시를 통해 자체 트래픽 및 결과 생성 각 도구의 발신 HTTP 프록시 구성
Longshot이 발사한 고립된 네이티브 핵 에이전트 API 호스트 및 Linux 샌드박스 공식 Nuclei 엔진으로 적합한 가져온 템플릿을 실행합니다. 별도의 격리된 실행 경로; 자동 Firefox 쿠키 내보내기가 없습니다. 
Built-in scan / Repeater / Fuzzer
        → Firefox networking + target tab's session → target

External ZAP / curl / another HTTP tool
        → authenticated native proxy :8900 → mitmproxy → target
                        ↑
             selected cookie/header values
                        ↑
              paired Firefox tab via :8901

MCP or REST client → Agent API :8765 → Longshot commands / UI
                                      └→ separately enabled native jobs

검사 시작은 ZAP를 실행하지 않습니다. ZAP를 브라우저 브리지와 페어링해도 Longshot의 JavaScript 스캐너를 대체하거나 모든 ZAP 경고를 Longshot으로 가져오지는 않습니다. 해당 도구에서 외부 도구의 결과를 검토합니다. 네이티브 브리지 트래픽 표시는 완전한 취약점 결과 가져오기 도구가 아닌 메타데이터입니다.

Firefox Nightly에서 설치 또는 업데이트

사용 2.18.1 XPI, 추가 기능으로 이름이 변경된 이전 어댑터 ZIP이 아닙니다. 다음과 같이 표시된 폴더에 일치하는 소스 아카이브를 추출합니다. /path/to/longshot 예에서. 등록된 기본 호스트를 다시 등록하지 않고 이동하지 마세요.

릴리스 파일은 다음과 같습니다.

  • 파이어폭스 XPI
  • 크롬 ZIP
  • 일치하는 확장 프로그램 소스 ZIP
  • 릴리스 노트 및 체크섬
  • 기본 어댑터 ZIP: 브라우저 브리지 내에서 다운로드하세요. 각 확장 패키지에 포함되어 있습니다.

이는 개발/제출 빌드입니다. Firefox 스토어 서명과 두 마켓플레이스의 승인이 보류 중입니다. 서명되지 않은 XPI가 Firefox 릴리스에서 정상적으로 설치되기를 기대하는 대신 적용 가능한 개발 로딩 절차를 따르십시오.

매니페스트에는 Firefox 140 이상이 필요합니다. 릴리스 통합 검사는 Linux에서 데스크톱 Firefox 159를 사용했는지 확인합니다. 선택적 도우미에 대한 플랫폼/런타임 지원은 기본 확장 지원과 별개입니다.

서명되지 않은 임시 설치의 경우:

  1. 열기 about:debugging#/runtime/this-firefox.
  2. 선택 임시 추가 기능 로드 그리고 XPI를 선택하세요.
  3. Longshot의 표시된 버전을 확인한 다음 대상을 열고 도구 모음 버튼을 실행하세요.
  4. 압축이 풀린 개발 빌드를 교체한 후 확장을 다시 로드하세요.

Firefox가 다시 시작되면 임시 추가 기능이 사라집니다. 그것은 예상됩니다. 확장을 삭제하는 것은 어댑터가 아닙니다. 지속적인 공개 배포에는 Mozilla 서명이 필요합니다. Nightly에는 다음에 설명된 추가 서명되지 않은 개발 옵션이 있습니다. Mozilla 서명 가이드; 임시 로딩에는 해당 설정을 변경할 필요가 없습니다. 참조 임시 설치.

XPI는 기본 어댑터를 다운로드 가능한 아카이브로 번들로 제공합니다. Firefox 추가 기능을 통해서만 임의의 Node/Python 프로세스를 시작하거나 기본 호스트를 설치할 수 없습니다. 프록시 시작과 에이전트 API 등록은 별개의 선택적 로컬 설정 단계입니다.

시작하기 및 대상 세션

오른쪽 탭을 연결하세요

  1. 예를 들어 Firefox에서 승인된 대상을 엽니다. http://localhost:8080.
  2. 원하는 테스트 계정으로 로그인하고 브라우저 챌린지를 완료하세요.
  3. 롱샷 발사 해당 대상 탭에서. 애플리케이션 탭을 열어두세요.
  4. 대상 주소를 확인하고 선택하세요 연결하다.
  5. 사용 시작하기 8단계로 강조 표시된 연습의 헤더에 있습니다. 재생할 수 있습니다. 스캔을 시작하거나 설정 자체를 변경하지 않습니다.
  6. Longshot이 유용한 경로와 입력을 관찰할 수 있도록 대표적인 애플리케이션 페이지를 탐색합니다.

대상 원본은 구성표, 호스트 이름 및 포트로 구성됩니다. http://localhost:8080, http://127.0.0.1:8080 그리고 https://localhost:8080 궁극적으로 동일한 서비스에 도달하더라도 출처가 다릅니다. 평가를 위해 의도된 정확한 주소를 연결하고 사용하십시오. 호스트 이름 뒤에서 관찰되는 IP 주소는 자동으로 추가 인증 대상이 되지 않습니다.

프로필 및 계정

대상 기록, 결과, 요청 저널, 검색된 엔드포인트, 검토 및 스캔 구성을 분리합니다. 프로필로 돌아가면 이전에 인증된 브라우저 세션이 아닌 평가 데이터가 복원됩니다. 명시적 프로필은 원본을 공유할 수 있습니다.

두 개의 일반 Firefox 탭은 일반적으로 쿠키를 공유합니다. 완전히 다른 테스트 ID를 위해 독립 컨테이너나 별도의 개인 쿠키 저장소를 사용하십시오. 프로필을 전환해도 두 번째 계정 세션이 생성되지 않습니다. 세션 B 비교에는 동일한 대상 원본과 별도의 저장소가 필요합니다.

  5. 선택 거미만 그리고 시작하세요.
  6. 검사 사이트 맵, HTTP 기록, API 탐색기, 서버 스택 그리고 조사 결과.

Spider는 양식 작성을 제출하지 않고 발견된 범위 내 링크/양식을 따릅니다. 숨겨진 모든 끝점을 아는 것은 아닙니다. GET 요청에는 여전히 애플리케이션별 부작용이 있을 수 있습니다. "읽기 방법"은 부작용이 없는 목표를 설정하지 않습니다.

두 번째 패스: 제한된 활성 평가

  1. 유지하다 자동 퍼지 → 꺼짐 내장된 활성 규칙을 개별적으로 더 쉽게 검토할 수 있습니다.
  2. SQL 삽입 및 Reflected XSS와 같은 관련 개요 활성 검사를 선택합니다.
  3. 예를 들어 활성 요청 150개, 활성 URL 10개, 활성 매개변수 5개 등 작은 제한을 사용합니다.
  4. 선택 활성 수표만 현재 페이지와 저장된 인벤토리를 재사용하거나 스파이더 + 액티브 체크 먼저 발견합니다.
  5. 시작하고, 필요한 승인을 검토하고, 활동 및 요청 수를 확인하세요.
  6. 각 결과의 요청, 기준, 반복된 조사/통제 증거, 판정 및 신뢰도를 검사합니다.
  7. 열기 WSTG 확인 → 실제 입력 범위 완료된 작업, 부분 작업, 건너뛴 작업을 확인하세요.

Auto-fuzz Off는 활성 검사를 끄지 않습니다. SQLi/XSS/SSTI 및 기타 전용 규칙은 자체 프로브를 생성합니다. 반대로, 활성 규칙을 선택해도 누락된 입력이 제공되지 않거나 스파이더 전용 실행이 일반 활성 단계를 실행하도록 만들지 않습니다.

수동 쿼리 퍼저

  1. 대상을 연결하고 범위가 지정된 URL을 선택합니다. 다음과 같은 상대 URL /search?q=apple 연결된 원본에 대해 허용됩니다.
  2. 기존 쿼리 매개변수 이름을 입력하거나 사용 검색된 입력 옆에 있습니다.
  3. 페이로드 클래스와 값 변형을 선택합니다.
  4. 에 대한 사용자가 업로드한 커스텀 페이로드, 먼저 적절한 사용자 정의 팩을 활성화하십시오.
  5. 선택 퍼저 실행그런 다음 기준선, 요청, 상태, 기간/타이밍 및 증거를 검사합니다.

누락된 URL, 매개변수 또는 빈 사용자 정의 세트는 특정 확인 메시지를 생성합니다. 응답을 변경하는 것만으로는 주입 결함이 발생하지 않습니다. 서버 조절은 기준선에서 발생하더라도 매개변수를 중지할 수 있습니다.

자동 퍼지 검색된 입력

사용 검색된 입력 미리보기 먼저. 저장된 인벤토리를 읽고 프로브를 보내지 않고 적격/건너뛴 요청을 보고합니다. 자동 퍼즈에는 수동 퍼저의 URL/매개변수 필드가 필요하지 않습니다. 인벤토리가 비어 있으면 탐색이나 스파이더를 먼저 실행하세요.

페이로드 클래스를 선택하고 별도의 클래스를 선택하십시오. 자동 퍼지 버튼. 검색된 요청 본문 포함 시작하고 공격적인 승인과 다음 실행 승인이 필요합니다. 이 자동 입력 선택기는 토큰 바인딩 양식, 지원되지 않는 방법, 사용할 수 없는 본문 및 XML을 건너뜁니다. 기존 제외, 요청 제한 및 제한 동작은 계속 적용됩니다.

사용 가능한 클래스 확인란은 SQLI, NOSQLI, CODE, XSS, SSTI, TRAVERSAL, COMMAND, SSRF, REDIRECT, CRLF 및 CUSTOM입니다. 새로운 기본값은 SQLI, SSTI, TRAVERSAL, REDIRECT 및 CRLF를 활성화합니다. 일반 루프는 SSRF를 건너뜁니다. 사용하다 SSRF 카나리아/콜백 구현된 검증을 위해. CUSTOM은 입력/활성화된 사용자 정의 값을 사용하고 전용 일치자가 더 많은 것을 설정하지 않는 한 신뢰도가 낮은 응답 차이를 보고합니다.

프로브 라이브러리가 여기에 속하는 이유

도서관 용품 페이로드 값 및 검토된 템플릿; 퍼저 컨트롤 선택 어디로, 어떻게 보내야 할까?. 수동 URL/매개변수를 대체하지 않습니다. 공유 라이브러리 옵션은 저장 후 활성 스캔 및 자동 단계에도 영향을 미칩니다.

GitHub 목록 업데이트 임의의 실행 가능한 스캐너가 아닌 고정 소스를 새로 고칩니다.

업데이트는 HTTPS를 사용하고 쿠키를 생략하며 실패 시 이전 스냅샷을 보존합니다. 소스 해시, 새로 고침 시간 및 지원되는 개수가 표시됩니다. 전체 입력 파일의 해시가 해당 파일의 모든 값이 사용된다는 의미는 아닙니다. 다운로드된 SQL 목록에는 파괴적/데이터 추출/지연/코드/콜백 구성이 제외됩니다. 기본 제공 규칙에는 별도로 구현된 카나리아가 있습니다.

업데이트하기 전에 검사를 중지하십시오. 업데이트해도 프로브 시작, 승인 부여, OAST 활성화 또는 대상 데이터/사용자 지정 팩을 GitHub에 업로드하지 않습니다. 지원되지 않는/원시/코드/헤드리스 형식으로 변경되는 다운로드된 템플릿은 자동으로 새 실행 기능으로 승격되지 않고 거부됩니다.

페이로드 및 가져온 템플릿

리터럴 목록 업로드

아래 스캔 옵션 또는 Fuzzer → 프로브 라이브러리 → 페이로드 및 CVE 템플릿, 카테고리를 선택한 다음 맞춤 파일 업로드.

허용되는 목록 양식:

  • .txt: 한 줄에 하나의 리터럴 비어 있지 않은 값; 공백과 대소문자는 그대로 유지됩니다.
  • .json: 문자열의 배열 또는 다음을 포함하는 객체 name, category 그리고 payloads.
  • 카테고리: custom, waf, sqli, nosqli, code, xss, ssti, traversal, crlf, redirect, command.
{
  "name": "My SQL review probes",
  "category": "sqli",
  "payloads": ["'", "\"", "' AND 1=1 -- "]
}

팩은 대상별로 다르며 처음에는 장애인. 미리보기를 검사하고 의도한 팩을 명시적으로 활성화합니다. 활성화된 업로드 팩에는 적극적인 승인이 필요합니다. 업로드만으로는 아무것도 실행되지 않습니다.

제한: 페이로드 파일당 256KB, 팩당 문자열 200개, 값당 2,000자, 대상당 최대 10팩/500값/512KB 팩 구성. 팩 내의 중복 문자열이 제거됩니다. 기존 방법, 범위, 예산 및 파괴적인 SQL 보호 조치가 계속 적용됩니다.

분류된 팩은 내장된 클래스 값을 보완합니다. WAF 팩에는 스마트 변형과 적합한 필터링 증거가 추가로 필요합니다. 리터럴 사용자 정의 페이로드는 예상되는 출력 일치자 또는 실행 가능한 확장 코드가 아닙니다. CVE 번호 업로드만으로는 해당 CVE를 확인할 수 없습니다.

요청/매처 템플릿 가져오기

YAML/YML/JSON을 업로드하기 전에 CVE/Nuclei 템플릿 카테고리를 선택하세요. 템플릿 파일 한도는 2MB입니다. 검토해 보세요 템플릿, 실행자 및 구체적인 준비/차단 이유를 포함합니다. 가져온 템플릿은 공유 라이브러리를 사용합니다. 페이로드 팩은 목표와 함께 유지됩니다.

  • 실행이 선택됨 선택한 템플릿을 직접 실행하며 CVE 자동 단계가 필요하지 않습니다.
  • CVE 자동 단계 구성된 스캔 중에 적격한 CVE 태그 지정/식별 가져오기를 고려합니다.
  • 자동 퍼지 일반적인 값을 생성합니다. 작성된 CVE 페이로드나 일치자를 다시 작성하지 않습니다.
  • 자문 전용 JSON은 제품/버전 증거를 상호 연관시킵니다. 작동하는 익스플로잇 요청을 생성하지 않습니다.
  • 원시, 복잡한 코드, 헤드리스, 파일 또는 비 HTTP 템플릿에는 별도의 공식 엔진과 추가 승인이 필요하거나 차단된 상태로 유지될 수 있습니다.

검토된 상대 도우미 번들을 필요한 템플릿과 함께 가져옵니다. 사용할 수 없는 기본 런타임, 범위를 벗어난 요청, 승인 누락 또는 지원되지 않는 기능은 성공적인 음성 테스트가 아니라 검사 이유입니다.

서버 스택 및 스마트 분석기

사용 소프트웨어 감지 지원되는 범위 관찰을 수집합니다. 시체 증거가 필요할 때 대표 페이지를 탐색하고 적절한 답변을 유지하세요. 그런 다음 선택 녹음된 증거 분석 최대 200개의 최근 저장된 응답에 대한 로컬 수동 상관 관계를 확인합니다. 분석기 자체는 대상 요청을 추가하지 않습니다.

이 보기는 브라우저 구성 요소, WAF/CDN/에지, 웹 서버/역방향 프록시 및 애플리케이션/런타임 신호를 구분합니다. 제품별 헤더, 쿠키 이름, 자산/부트스트랩 구조 및 오류 텍스트는 신뢰도를 높일 수 있습니다. 챌린지 페이지 본문은 애플리케이션 지문 채취에서 제외됩니다. 일반 403, nginx 배너 또는 CDN 에지는 특정 WAF 규칙이 활성화되도록 설정하지 않습니다.

가능한 구성 카드는 증거와 제안된 검증을 설명합니다. 이는 가설입니다. 브라우저 응답은 원본 IP, 개인 서브넷, 백엔드 데이터베이스 설정, TLS 종료, 방화벽 규칙 또는 프록시 신뢰 목록을 정확하게 설정할 수 없습니다. 여러 업스트림 및 재작성된 배너는 레이어를 숨기거나 잘못 식별할 수 있습니다.

WAF 권장 사항 및 속도 처리

보수적인 스캔 권장 사항 적용 커뮤니티 SQL 프로브, 스마트 변형 및 적응 속도를 명시적으로 활성화하고 구성된 속도를 최대 0.5 요청/초로 낮춥니다. 스캔을 시작하거나 고급 기능을 부여하지 않습니다.

적격 조사에서는 기존 예산 내에서 최대 3개의 대체 표현을 고려합니다. 차단된 기준선을 건너뜁니다. 브라우저 문제에는 일반적인 브라우저 해상도가 필요합니다. 일반적인 ACL 거부는 끝없는 우회 시도를 정당화하지 않습니다. 차단-허용 변경은 취약성 증명이 아니라 도달 가능성 증거입니다.

명시적 챌린지를 반복하면 메모리 내 속도가 절반으로 줄어들고 최소 10초의 대기 시간이 발생할 수 있습니다. Retry-After가 포함된 HTTP 429 또는 503은 예약된 추가 프로브를 중지합니다. 더 긴 Retry-After 간격이 존중됩니다. 비율은 자동으로 다시 증가하지 않습니다. 새로운 실행은 구성된 속도로 시작됩니다.

CVE 조회

온라인 CVE 검색 허가 후 지원되는 제품/패키지 좌표에 대해 NVD/OSV를 쿼리합니다. 요청은 대상 URL, 쿠키 또는 페이지 콘텐츠가 아닌 좌표를 보냅니다. 알 수 없는 버전, 공급업체 백포트 및 확인되지 않은 패키지 존재로 인해 결론이 제한됩니다. 수동 npm/PyPI 항목은 설치를 증명하지 않습니다.

일치하는 항목이 없다고 해서 CVE가 없다는 의미는 아닙니다. 일치는 자문 후보입니다. 전제 조건을 검사하고 사용 확인 템플릿 찾기 적합한 수입 수표를 찾으려면 해당 버튼은 템플릿을 실행하는 대신 템플릿을 필터링합니다.

OAST 설정 및 해석

OAST 정상적인 응답이 동작을 드러내지 않을 때 프로브로 인해 발생하는 DNS/HTTP 상호 작용을 관찰합니다. Longshot은 등록/상관 키를 소유합니다. 다른 클라이언트에서 미리 생성된 무작위 콜백은 상호 교환이 불가능합니다.

  1. 귀하가 제어하거나 사용이 허용된 Interactsh 호환 서비스를 선택하세요.
  2. 입력 제공업체 URL: 공급자의 전체 API 기본 주소(일반적으로 HTTPS)입니다. HTTP는 루프백 공급자에만 허용됩니다.
  3. 일치하는 항목을 입력하세요. 콜백 도메인 없이 http://, 포트 또는 경로.
  4. 입력 공급자 토큰 해당 공급자가 요구하는 경우에만.
  5. TTL 및 폴링 간격을 설정합니다. OAST와 관련 SSRF/XXE/Log4Shell/명령 옵션을 활성화합니다.
  6. 사용 OAST 연결 테스트 등록/폴링을 확인합니다.
  7. 사용 OAST 콜백 테스트 이 브라우저에서 별도의 상관 카나리아를 보냅니다.
  8. 실제 스캔을 저장, 검토 및 승인합니다. OAST 상호작용의 정확한 상관관계와 프로토콜을 검사합니다.

예를 들어, 다음에서 일치하는 공공 서비스를 사용하는 경우 https://oast.pro, 콜백 베이스는 다음과 같습니다. oast.pro. 이는 가용성 보장이나 해당 공급자를 사용하기 위한 요구 사항이 아니라 하나의 예입니다. 자체 호스팅 공급자에는 적절하게 위임된 연결 가능한 도메인, DNS/리스너 및 TLS가 필요합니다. 랩톱 HTTP 수신기만으로는 공개 콜백 서비스가 아닙니다. 팔로우 공식 Interactsh 설정.

관찰 그것이 확립하는 것
연결 테스트 통과 등록 및 폴링은 브라우저의 경로를 통해 이루어졌습니다.
브라우저 콜백 테스트 통과 이 브라우저는 상호 연관된 자체 상호 작용을 트리거하고 검색할 수 있습니다.
대상 프로브가 일치하는 상호 작용을 생성합니다. 상관된 상호작용이 발생했습니다. 출처를 밝히고 그 의미를 평가하세요.
콜백 없음 결론이 나지 않음: 대상 송신, 공급자 도달 가능성, 만료, 필터링 또는 지원되지 않는 컨텍스트로 인해 설명될 수 있음

DNS 확인은 중개자/보안 서비스를 통해 이루어질 수 있습니다. 콜백만으로는 임의의 내부 액세스, 데이터 도난 또는 코드 실행을 증명할 수 없습니다. 별도의 격리된 Nuclei 엔진은 자체 기본 Interactsh 등록을 소유합니다. 해당 이벤트는 브라우저 클라이언트의 등록이 아닙니다.

브라우저 측 OAST 클라이언트에는 Go, Node 또는 Agent API가 필요하지 않습니다. 릴리스 테스트에서는 공식 서버 등록, 암호화된 HTTP 콜백 검색 및 루프백 상관 관계를 실행했습니다. 공용 공급자 가용성이나 대상 서버의 송신을 설정하지 않았습니다. 호스트 파일 편집은 정상적으로 올바르게 위임된 OAST 설정의 일부가 아닙니다.

브라우저 브리지: 기본 도구 프록시

보내는 내용

외부 도구는 공격 페이로드, 방법, 본문 및 쿼리를 포함하여 요청을 생성합니다. 기본 어댑터는 구성된 쿠키/헤더 변경 사항만 적용하여 mitmproxy를 통해 이를 전달합니다. 그렇습니다 아니 ZAP 또는 다른 도구를 대신하여 가져오기를 수행하도록 Firefox에 요청하세요.

이는 기본 HTTP 의미 체계와 도구의 페이로드 생성을 유지하지만 임의의 원본 와이어 바이트는 유지하지 않습니다. mitmproxy는 HTTP를 구문 분석/직렬화하고 자체 아웃바운드 TLS 연결을 설정합니다. 브라우저 사용자 에이전트 문자열은 기본 TLS/네트워크 지문을 Firefox와 동일하게 만들지 않습니다.

다운로드한 어댑터 설치

  1. 열기 브라우저 브리지. 만 기본 도구 프록시 2.18.1에서 사용할 수 있습니다.
  2. 선택 기본 어댑터 다운로드 그리고 그것을 추출하십시오.
  3. 추출된 내용을 입력하세요. native-bridge 디렉토리. 그것은 포함 cli.js, bootstrap.py, config.json 그리고 번들 노드 ws 의존성.
  4. 아직 사용할 수 없는 경우 Node.js 20+ 및 Python 3.12+를 설치합니다.
  5. 일회성 Python 설정을 실행합니다.

sh cd /absolute/path/to/native-bridge python3 bootstrap.py

이렇게 하면 로컬이 생성됩니다. .venv 고정된 mitmproxy 12.2.3을 설치합니다. 설치에는 인터넷 액세스가 필요합니다. 정상 시작에서는 스캐너 코드나 페이로드 목록을 다운로드하지 않습니다.

  1. 표시된 명령을 사용하십시오. 너의 확장 페이지:

sh node cli.js --config config.json \ --extension-origin moz-extension://YOUR-LONGSHOT-UUID

자리 표시자를 현재 확장 원점 전체로 바꿉니다. 대상 웹사이트, 추가 기능 ID 또는 다른 Firefox 프로필에서 복사한 원본이 아닙니다.

  1. 터미널을 계속 실행하세요. 프록시 리스너가 준비되면 프록시 주소, 제어 포트, 새 페어링/프록시 토큰 및 CA 인증서 경로를 인쇄합니다.

번들 어댑터 아카이브를 사용하지 않고 소스 ZIP에서 개발할 때 고정된 노드 종속성이 없는 경우 먼저 설치하십시오.

cd /absolute/path/to/longshot-source
npm --prefix native-bridge ci --omit=dev
cd native-bridge
python3 bootstrap.py

--mitmdump /absolute/path/to/mitmdump 또는 LONGSHOT_MITMDUMP 기존 런타임을 선택합니다. --data-dir /absolute/private/run-directory CA/audit 디렉터리를 선택합니다. 기본값은 run 기본 어댑터 내부. Ctrl+C는 어댑터를 중지합니다.

수동 기본 프록시는 에이전트 API 호스트 등록과 별개입니다. 그것은 필요하지 않습니다 node bridge/bin/longshot-bridge install 단지 컬/ZAP를 프록시하기 위한 것입니다. Linux/Firefox는 릴리스 통합 테스트에서 실행되었습니다. 이 수동 Node/Python 시작 경로에서 다른 플랫폼의 기본 메시징 설치 프로그램 지원을 추론하지 마십시오.

선택한 탭 페어링

  1. 승인된 것을 선택하세요. 타겟 탭 브라우저 브리지에서.
  2. 표시된 원본과 쿠키 저장소를 확인하세요. 사용 탭 새로 고침 필요한 경우.
  3. 입력 제어 포트 8901, 어댑터 구성에서 변경되지 않는 한.
  4. 현재 붙여넣기 페어링/프록시 토큰 실행 중인 어댑터에서.
  5. 선택 페어 네이티브 브리지 준비 상태를 확인합니다.
  6. 도구 트래픽을 라우팅하기 전에 쿠키/헤더 스위치를 검토하세요.

이 필드는 성공적인 페어링 후 토큰을 지웁니다. 다시 시작하면 새 토큰이 생성됩니다. 다시 페어링하고 모든 외부 도구에서 프록시 자격 증명을 업데이트하세요. 프록시 포트 8900 도구용입니다. 제어 포트 8901 파이어폭스용입니다. 둘 다 포트 8765의 에이전트 API 전달자 토큰을 사용하지 않습니다.

실제 대상 URL 및 bridge.invalid

실제 주소를 사용하세요. http://localhost:8080/search?q=apple, 도구에서. HTTPS를 테스트하는 경우 실제 https://... 주소. 프록시 자체 주소는 그대로 유지됩니다. http://127.0.0.1:8900 이는 HTTPS CONNECT를 포함하여 로컬 HTTP 프록시 수신기이기 때문입니다.

아니요 /etc/hosts 진입이 필요합니다. 오래된 bridge.invalid 주소는 유틸리티의 HTTP URL을 선택한 브라우저 가져오기 대상에 매핑하기 위한 어댑터별 별칭이었습니다. 현재 기본 프록시는 실제 대상 URL과 HTTPS CONNECT를 지원하므로 매핑이 필요하지 않습니다.

localhost 모든 대상에 대해 상호 교환 가능한 별칭은 아닙니다. 관련 프로세스의 네트워크 환경에서 로컬 시스템의 이름을 지정합니다. 대상이 실제로 해당 원점에 로컬인 경우에만 정확합니다. 두 이름이 모두 동일한 IP로 확인되더라도 다른 호스트 이름은 다른 가상 호스트, 쿠키 정책 또는 원본을 선택할 수 있습니다.

기존의 사용되지 않는 호스트 항목은 새 작업 흐름과 관련이 없습니다. 도구 URL에는 사용하지 마세요. 이 튜토리얼을 준비하는 동안 호스트 파일을 수정하지 않았습니다.

HTTPS 신뢰

어댑터는 일반적으로 선택한 데이터 디렉터리 아래에 자체 로컬 CA를 생성합니다.

run/ca/mitmproxy-ca-cert.pem       public CA certificate for tool trust
run/ca/mitmproxy-ca.pem            sensitive CA material/private key

구성 외부 도구의 평가 신뢰 구성 시작 시 공개 인증서 경로가 인쇄됩니다. 개인 키를 공유하거나 시스템/Firefox 신뢰 저장소가 변경되었다고 가정하지 마십시오. 어댑터는 해당 CA를 신뢰 저장소에 설치하지 않습니다.

컬의 경우:

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  --cacert /absolute/path/to/native-bridge/run/ca/mitmproxy-ca-cert.pem \
  'https://actual-target.example/search?q=apple'

바꾸기 CURRENT_TOKEN 및 대상/인증서 경로. HTTP 전용 로컬 대상의 경우 --cacert 불필요합니다. --noproxy '' 컬이 루프백 대상에 대한 프록시를 자동으로 우회하지 않도록 합니다.

TLS 검사에는 두 가지가 있습니다.

  • 클라이언트는 어댑터가 제공한 인증서를 확인합니다. 어댑터 CA를 사용하여 클라이언트의 신뢰를 구성합니다.
  • 어댑터는 실제 업스트림 서버를 확인합니다. tls.verifyUpstream 기본값은 true입니다. 클라이언트 --cacert 개인 원본 CA를 어댑터에 제공하지 않습니다.

확인 비활성화를 인증서 오류에 대한 일반적인 수정으로 간주하지 마십시오. 소유한 자체 서명 설비의 경우, tls.verifyUpstream:false 어댑터 구성의 명시적인 평가 예외이고 그 뒤에 다시 시작됩니다. 이는 별도의 업스트림 확인을 약화시킵니다. 참조 mitmproxy 인증서 동작.

기본 쿠키 동작

브라우저 쿠키 사용 그리고 응답 Set-Cookie 업데이트 저장 기본적으로 켜져 있습니다. User-Agent, Accept-Language 및 Authorization은 기본적으로 도구에 의해 제어됩니다.

기본 요청의 경우 Firefox는 쌍을 이루는 탭의 쿠키 저장소와 일치하는 파티션에서 URL에 적용 가능한 쿠키를 선택합니다. 다른 컨테이너/개인 저장소는 병합되지 않습니다. 도메인/경로/보안/만료 규칙 및 동일한 이름 경로 순서는 여전히 관련성이 있습니다. 나가는 쿠키 헤더를 구성할 수 있도록 값이 기본 프록시에 제공됩니다. 제거된 브라우저 가져오기 경로와 달리 기본 도우미는 메모리에서 세션 비밀을 처리합니다.

와 cookies.mode:"replace", 브라우저 jar는 비어 있는 경우를 포함하여 신뢰할 수 있습니다. jar에서 삭제된 브라우저 쿠키는 나중에 관리되는 요청에서 제거됩니다. 명시적으로 보호된 이름과 감지된 도구 변경 사항이 우선적으로 적용됩니다. 와 mode:"merge", 브라우저 관리 이름이 업데이트되는 동안 관련 없는 도구 쿠키가 남아 있을 수 있습니다.

응답 세트-쿠키 필드는 지원되는 Domain/path/Secure/HttpOnly/SameSite/expiry/deletion/partition 속성을 포함하여 Firefox의 쿠키 API를 사용하여 선택한 동일한 저장소에 개별적으로 적용됩니다. 유효하지 않은 쿠키는 거부될 수 있습니다. 보고된 오류를 검사합니다. 추가로 구성된 원본은 브라우저 쿠키 또는 브라우저 파생 헤더를 수신하지 않습니다.

브라우저 인증 및 기타 헤더

브라우저 인증은 JSON 구성을 통해 선택됩니다. 브라우저 소싱을 활성화한 후에만 페어링된 대상 탭의 실제 요청에서 캡처됩니다. localStorage 또는 애플리케이션 메모리의 모든 토큰에 대한 자동 판독기가 아닙니다. 관찰된 값이 존재하기 전에 이후 브라우저 요청이 필요할 수 있습니다. 브라우저 인증을 끄면 도우미가 캡처한 값을 제공하는 것이 중지됩니다.

브라우저 User-Agent 또는 Accept-Language를 선택하면 해당 HTTP 필드만 변경됩니다. 대상 JavaScript를 실행하거나, 본문 CSRF 토큰을 새로 고치거나, 브라우저 TLS를 재생하거나, WAF 승인을 보장하지 않습니다. IP/장치 바인딩 인증 및 OAuth 새로 고침에는 여전히 애플리케이션 워크플로가 필요합니다.

VHOST / 호스트 처리

기본 도우미는 내부 브리지 별칭을 도구의 호스트 필드로 대체하지 않습니다. 도구가 인증된 가상 호스트 테스트에 필요한 호스트 값을 보내도록 합니다. HTTPS의 경우 CONNECT 대상은 인증된 대상으로 유지되는 반면 도구의 호스트 헤더는 보존될 수 있습니다.

호스트 헤더를 변경해도 다른 네트워크 대상에 대한 액세스 권한은 부여되지 않습니다. 역방향 프록시는 이를 다른 애플리케이션으로 라우팅할 수 있습니다. 평가 승인에 해당 가상 호스트 동작을 포함합니다. 정확한 잘못된 헤더 바이트와 충돌하는 프레이밍이 이 구문 분석된 프록시 외부에 있습니다.

감사 및 개인정보 보호

기본 트래픽 요청 메타데이터와 변경/보호된 필드 이름을 표시합니다. 감사에서는 쿠키/헤더 비밀 값, 쿼리 값 및 본문을 생략합니다. 이는 프록시가 비밀을 처리하지 않는다는 의미는 아닙니다. 인증된 트래픽을 보내려면 비밀을 처리해야 합니다. 외부 도구는 해당 값을 포함할 수 있는 자체 기록/결과를 유지합니다.

보고서/소스 아카이브에서 개인 구성 토큰, CA 키 및 데이터 디렉터리를 유지하세요. 사용자 정의 인증 값이 포함된 구성을 다운로드하면 해당 값이 포함된 파일이 생성될 수 있습니다.

외부 도구 및 실제 ZAP 스캐닝

하나의 요청으로 시작하세요

브리지를 페어링한 다음 실제 로컬 대상을 테스트합니다.

curl --noproxy '' \
  --proxy http://127.0.0.1:8900 \
  --proxy-user 'bridge:CURRENT_TOKEN' \
  'http://localhost:8080/'

알려진 인증된 읽기 경로를 사용하여 세션 동작을 확인하세요. 공개 홈페이지의 200만으로는 충분하지 않습니다. 요청이 기본 트래픽에 나타났는지, 선택한 쿠키 저장소가 올바른지, 도구가 예상한 콘텐츠를 수신했는지 확인하세요. 이번 요청이 그랬다는 이유만으로 이후의 모든 요청이 프록시를 사용한다고 추론하지 마세요.

ZAP 발신 프록시

  1. ZAP를 별도로 설치/시작하고 평가별 ZAP 세션을 사용하세요.
  2. ZAP에서는 옵션 → 네트워크 → 연결, 활성화 나가는 HTTP 프록시.
  3. 호스트 설정 127.0.0.1, 포트 8900 (또는 현재 구성된 프록시 포트).
  4. 프록시 인증 활성화: 사용자 이름 bridge, 현재 어댑터 토큰에 비밀번호를 입력합니다.
  5. 이 체인에 대해 ZAP의 자체 SOCKS 프록시를 비활성화합니다. ZAP의 SOCKS 설정은 HTTP 프록시보다 우선합니다.
  6. 특히 로컬 서비스의 경우 의도한 대상이 우회되지 않도록 HTTP 프록시 제외를 확인하세요.
  7. 필요한 경우 도구의 적용 가능한 TLS 신뢰/확인 설정에서 어댑터 CA를 구성합니다. 해당 위치는 어댑터 시작 시 인쇄됩니다.
  8. 액세스 실제 타겟 URL ZAP에서 기록과 브리지 메타데이터를 확인합니다.
  9. ZAP의 자체 대상/컨텍스트, 스캔 정책, 제외, 인증 확인 및 적당한 요청 속도를 정의합니다. 승인된 대로 실제 스파이더/액티브 스캔을 실행합니다.
  10. ZAP의 조사 결과 및 적용 범위를 검토하세요. 의도적으로 쿠키/헤더 인증 필드를 퍼징하는 경우 위의 보호/우회 메커니즘을 사용하세요.

이 설정은 ZAP의 것입니다. 나가는 연결, 로컬 수신 브라우저 프록시 수신기가 아닙니다. 선택한 탭의 쿠키를 이 체인에 제공하기 위해 ZAP를 사용하도록 Firefox를 재구성할 필요는 없습니다.

ZAP는 실제 활성 규칙 페이로드를 생성합니다. mitmproxy는 결과 기본 요청을 보냅니다. Longshot은 선택한 요청 필드만 변경합니다. 이는 외부 도구의 사용 가능한 세션 컨텍스트를 늘리지만 두 도구의 검색을 포괄적으로 만들지는 않습니다. 참조 ZAP 연결 설정.

컬 --proxy, --proxy-user; --cacert HTTPS 신뢰의 경우; 필요한 경우 프록시 우회 지우기 다양한 호출/연결로 휴리스틱 프로브 기준선을 재설정할 수 있습니다.

sqlmap 현재 자격 증명을 사용한 HTTP 프록시 옵션입니다. 인증된 URL/매개변수를 선택하고 테스트 중인 필드를 보호하세요. 별도의 SQLi 엔진/설정; 쿠키 교체는 구성되지 않은 한 쿠키 프로브를 지울 수 있습니다.

Python urllib/요청 명시적으로 인증된 프록시 처리기/구성 및 HTTPS용 어댑터 CA 라이브러리는 환경 변수 및 우회 처리가 다릅니다.
핵 CLI 지원되는 HTTP 템플릿 트래픽에 대한 HTTP 프록시/신뢰 구성 비HTTP/코드/헤드리스 템플릿 트래픽은 하나의 HTTP 프록시 옵션으로 보편적으로 처리되지 않습니다.

자격 증명이 포함된 프록시 URL은 중요합니다. 가능한 경우 도구의 비공개 평가 구성을 사용하세요. 현재 토큰을 공유 보고서에 붙여넣지 마십시오. 각 도구에 대해 모든 프로토콜이나 하위 프로세스가 HTTP 프록시 설정을 따른다고 가정하기보다는 라우팅된 트래픽을 확인하세요.

읽기 전용 로컬 대상에 대한 Linux Python 표준 라이브러리 예. 하드코딩하는 대신 토큰을 묻는 메시지를 표시하고 이 프로세스에 대한 환경 프록시 우회를 지웁니다.

import os
from getpass import getpass
from urllib.request import (
    HTTPPasswordMgrWithDefaultRealm,
    ProxyBasicAuthHandler, ProxyHandler, build_opener,
)

os.environ["no_proxy"] = ""
os.environ["NO_PROXY"] = ""
proxy = "http://127.0.0.1:8900"
credentials = HTTPPasswordMgrWithDefaultRealm()
credentials.add_password(None, proxy, "bridge", getpass("Bridge token: "))
opener = build_opener(
    ProxyHandler({"http": proxy, "https": proxy}),
    ProxyBasicAuthHandler(credentials),
)
with opener.open("http://localhost:8080/", timeout=20) as response:
    print(response.status)
    print(response.read(200).decode("utf-8", errors="replace"))

기본 트래픽에서 요청을 확인합니다. 다른 플랫폼에는 추가 시스템 프록시 우회 규칙이 있을 수 있습니다. 명시적인 컬 예제 --noproxy '' 더 간단한 루프백 경로 유효성 검사입니다. HTTPS Python 클라이언트에는 어댑터 인증서를 신뢰하는 SSL 컨텍스트/CA 번들이 추가로 필요합니다.

일시중지 및 오류

기본 요청 일시중지 새로운 기본 송신을 차단합니다. 인증 상태 401/419/440, HTTP 429, 탭 폐쇄/원본 외 변경 또는 예산 제한으로 인해 작업이 일시 중지될 수도 있습니다. 탭 확인 후 재개 페어링 상태를 검토한 후에만 재개됩니다.

중지하고 연결을 끊습니다. 브라우저 페어링을 종료합니다. 별도로 시작된 Node 프로세스를 종료하지 않습니다. 해당 프로세스를 중지하려면 터미널에서 Ctrl+C를 사용하세요.

기내 요청이 완료될 수 있습니다. 프록시 클라이언트는 차단된 작업에 대해 오류를 수신합니다. 어댑터는 임의의 도구 프로세스를 일시 중단하거나 해당 요청을 재생하지 않습니다. 어떤 요청이 성공했는지 검사하고 도구의 자체 재시도/재개 컨트롤을 사용하세요. 다시 시작/재페어링하면 토큰이 변경되며 업데이트 도구 인증이 필요합니다.

고의적인 부정 인증 테스트에서는 401/419/440이 예상될 수 있습니다. 필요한 경우 조정하세요. session.pauseStatuses 검토된 실행 및 다시 시작을 위해; 어댑터는 모든 인증 실패가 의도된 프로브인지 여부를 추론하지 않습니다.

토르와 양파 라우팅

브라우저 기반 Longshot 요청은 선택한 브라우저의 네트워킹을 따릅니다. 기본 어댑터는 다른 프로세스이며 Firefox/Tor 브라우저 프록시 설정을 상속하지 않습니다.

SOCKS/토르는 기본적으로 꺼짐 기본 구성에서. 승인된 양파 평가의 경우 원격 호스트 이름 확인을 통해 명시적으로 구성된 기존 SOCKS 서비스를 사용합니다. 예를 들어 실제로 로컬 Tor 수신기인 경우 다음을 재정의합니다.

{
  "routing": {
    "socks5": "socks5h://127.0.0.1:9050"
  }
}

이 예에서는 Tor를 시작하거나 포트 9050이 존재하는지 확인하지 않습니다. 실제 구성된 서비스를 선택하십시오. Tor 브라우저 인스턴스는 다른 리스너를 사용할 수 있습니다. 어댑터를 다시 시작하고 다시 페어링하세요. HTTP(S) upstream.url 그리고 routing.socks5 상호 배타적입니다.

기본 심은 SOCKS를 통해 호스트 이름을 확인하며 자동 직접 대체 기능이 없습니다. 명시적으로 구성된 업스트림/SOCKS 경로가 없으면 직접 양파 대상이 대상 DNS보다 먼저 거부됩니다. SOCKS URL은 인증된 SSH 터널이나 기타 SOCKS5 서비스를 참조할 수도 있습니다. Tor 라우팅에 대한 본질적인 증거는 아닙니다.

쿠키 공유는 기본 경로의 종료 IP 또는 TLS/브라우저 지문을 Firefox와 동일하게 만들지 않습니다. 챌린지 또는 세션 바인딩에서 이를 거부할 수 있습니다. 경로와 예상 세션을 독립적으로 확인하세요.

Agent API에 의해 시작된 격리된 기본 Nuclei는 다릅니다. 내장된 릴레이에는 Tor/SOCKS 경로가 없으며 시스템 DNS 이전에 양파 대상을 차단합니다. 의도한 브라우저에서 적합한 브라우저 측 검사를 사용하거나 기본 프록시를 통해 별도로 구성된 외부 도구를 사용하십시오. Nuclei 확인란이 상속된다고 가정하지 마세요. routing.socks5 브라우저 브리지에서.

에이전트 API, MCP 및 로컬 모델 클라이언트

에이전트/스크립트가 Longshot을 작동하거나 증거를 검색하거나 평가 파일을 저장해야 하는 경우 이 기능을 사용하세요. :8900 트래픽 프록시가 아닙니다.

네이티브 호스트 등록 및 연결

보관된 것 중에서 출처 다음을 포함하는 디렉토리 manifest.json 그리고 bridge/:

cd /absolute/path/to/longshot-source
node bridge/bin/longshot-bridge install

이 레지스터 longshot.bridge 소스 폴더와 노드 실행 파일을 참조하는 실행 프로그램입니다. 둘 다 제자리에 유지하십시오. 둘 중 하나라도 이동하면 다시 등록하세요.

열기 설정 → 연결 및 설정 → 네이티브 브리지 연결 Firefox의 기본 메시징 권한을 부여합니다. 호스트는 데몬을 자동으로 시작할 수 있습니다. 의도적으로 데몬을 수동으로 실행하는 경우:

node bridge/bin/longshot-bridge serve

동일한 포트/데이터 디렉터리에 두 번째 데몬을 두지 마십시오. 연결 끊기는 확장 프로그램의 기본 연결을 닫습니다. 독립적으로 시작된 데몬을 반드시 중지할 필요는 없습니다.

Node.js 20 이상이 필요합니다. 기본 메시징 MCP에는 프록시의 Python/mitmproxy 설치가 필요하지 않습니다. Linux는 연습된 설정입니다. macOS 등록 지원은 제공되지만 여기에서는 런타임이 확인되지 않습니다. 이 릴리스에는 Windows Firefox 기본 호스트 설치 프로그램이 없습니다. WSL에 등록해도 Windows Firefox용 호스트는 등록되지 않습니다. 기본 Nuclei 격리는 Linux 전용입니다.

기본 서비스: http://127.0.0.1:8765. 이 localhost 주소는 제어 API이며, 스캔한 대상이 아님. 토큰/소켓의 기본값은 다음과 같습니다. $XDG_DATA_HOME/longshot 또는 ~/.local/share/longshot. 맞춤 --port 그리고 --data-dir 설치, 제공 및 mcp에서 일치해야 합니다. 소켓 경로는 100바이트로 제한되므로 짧은 Unix 데이터 경로를 사용하세요.

REST 예

동일한 소스 폴더에서:

longshot_token_file="$(node bridge/bin/longshot-bridge token-path)"
longshot_api_token="$(cat "$longshot_token_file")"

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/health

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  http://127.0.0.1:8765/v1/targets

는 token-path 명령은 토큰이 아닌 파일 이름을 인쇄합니다. API는 프록시 사용자 이름/비밀번호 인증과 달리 베어러 인증을 사용합니다. 루프백이 아닌 클라이언트 및 브라우저 Origin 요청을 거부하고 일반 CORS API를 노출하지 않습니다. 공개 역방향 프록시를 통해 게시하지 마십시오.

원하는 대상을 연결/활성화하고 저장된 옵션을 확인한 후에만 소규모 스캔을 시작하십시오.

curl --fail-with-body \
  -H "Authorization: Bearer $longshot_api_token" \
  -H 'Content-Type: application/json' \
  --data '{"target_id":"PROFILE_ID","mode":"safe","budget":150}' \
  http://127.0.0.1:8765/v1/scans

PROFILE_ID를 선택한 프로필 ID로 바꿉니다. safe Spider에만 매핑됩니다. 저장된 모든 고급 옵션을 재설정하거나 보편적인 재정의로 작동하지 않습니다. 시작은 비동기식입니다. 반환된 실행 ID를 읽은 다음 모니터링합니다. /v1/scans/RUN_ID, /eta, /findings 또는 /report?format=html. POST /pause, /resume 그리고 /stop 실행을 제어합니다. 컨설트 인증됨 /openapi.json 정확한 스키마를 위해.

REST/JSON-RPC는 프로필, 스캔, 결과/보고서, 템플릿, OAST 및 세션 작업을 지원합니다. /rpc JSON-RPC를 전달합니다. /mcp stdio 및 SSE 옵션과 함께 MCP HTTP를 제공합니다. 서비스의 프로토콜/API 버전 문자열은 이전 스키마 버전을 유지할 수 있습니다. 설치된 UI 릴리스 버전에 대한 확장 매니페스트를 사용합니다.

승인 범위: 직접적인 의미론적 동의 명령은 공격적인 실행 권한을 부여할 수 없습니다. 인증된 전체 UI 자동화는 승인 버튼을 포함하여 바인딩된 대시보드의 승인 대화 상자를 작동할 수 있습니다. 따라서 에이전트 UI 제어를 제공하면 해당 UI 기능이 제공됩니다. 승인을 클릭할 수 없는 액세스 권한을 설명하지 마십시오. 일회용 대상/구성/만료 확인은 계속 적용됩니다.

Hermes/Ollama 또는 기타 현지 모델 에이전트

Longshot은 임의의 LLM 채팅 스트림을 허용하거나 모델을 선택하지 않습니다. 는 에이전트 신청 모델 연결 및 도구 호출 루프를 제공합니다. 에이전트가 MCP를 지원하는 경우 해당 에이전트에서 위의 MCP 서버를 구성하십시오. 에이전트는 지원되는 도구 호출을 보내고 도구 결과를 받습니다. 노출된 UI 도구를 통해 확장 프로그램을 검사/탐색/채울 수 있을 뿐만 아니라 스캔 명령을 호출할 수도 있습니다.

Hermes/에이전트 자체 구성에서 Ollama 모델 및 서버를 선택합니다. 에이전트의 도구 호출 형식을 지원하는 모델/클라이언트 조합을 사용하고 에이전트가 실제로 MCP 도구를 호출할 수 있는지 확인하십시오. Longshot의 구성에는 model, ollama 또는 공급자 API 키 설정. 모델 액세스, 셸 액세스 및 관련 없는 파일 시스템 제어는 이 확장을 설치해도 부여되지 않는 에이전트 호스트의 기능입니다.

상담원 작업에서 범위, 예산, 계정 및 의도한 작업을 명시적으로 유지하세요. 기록된 증거에 대해 생성된 결과를 검증합니다. 모델 텍스트는 스캐너 결과나 권한 부여가 아닙니다.

API 탐색기

먼저 연결하고 찾아본 다음 선택하세요. 현재 페이지 검사. 개발자 제공 가져오기 오픈API JSON 설명은 가능한 경우 최대 2MB입니다. 임의의 원격 페이지나 YAML 파일이 아닌 로컬 JSON을 읽습니다. 로컬 사양 참조 및 사용 가능한 요청 예제/기본값은 지원되는 구체적인 입력을 제공할 수 있습니다. 누락된 값/본문 및 지원되지 않는 구성으로 인해 공백이 남습니다.

엔드포인트는 주소입니다. 작업은 주소와 방법을 더한 것입니다. 쿼리 입력은 다음에 나타납니다. ?, 주소 경로의 경로 입력 및 제출된 콘텐츠의 본문 입력입니다. 나열된 작업은 인벤토리이며 현재 계정이 해당 계정이 다루는 모든 개체에 액세스할 수 있다는 증거는 아닙니다.

사용 중계기 아직 보내지 않고 요청을 준비하기 위해 지원되는 GET/HEAD 작업 옆에 있습니다. URL/메서드/입력을 검토한 다음 의도적으로 보냅니다. 인벤토리 전용 쓰기 작업을 수행하려면 적절한 요청을 준비하고 쓰기 승인을 받아야 합니다.

WebSocket, SSE 및 유틸리티

검색된 범위 내 채널을 선택하거나 정확한 URL을 입력하세요. 청취 및 사용자 정의 프레임 전송은 일반 프로토콜 스캐너가 아닌 제한적으로 승인된 작업입니다. 캡처된 오류 텍스트는 단서입니다. 메시지 인증이나 경쟁/논리적 결함을 설정하지 않습니다.

유틸리티는 값을 인코딩/디코딩하고, SHA-256을 계산하고, JSON 형식을 지정하고, JWT 클레임을 로컬에서 검사합니다. JWT 디코딩은 서명 확인이 아니며 서버가 위조된 토큰을 수락하는지 확인하지 않습니다. 변환된 입력은 자동으로 실행되거나 제출되지 않습니다.

A01 IDOR / 깨진 개체 또는 기능 승인 지표만 별도의 Firefox 컨테이너/개인 쿠키 저장소를 사용하여 세션 B와 비교를 활성화합니다. 최대 10개의 읽기 요청이 상태 및 본문 해시를 비교합니다. 객체 소유권이나 기대되는 역할 모델이 없습니다. 동일한 공개 페이지는 합법적일 수 있습니다. 일반 권한 상승 증거가 없습니다.
A01 사이트 간 요청 위조(CSRF) 지표만 양식 검토에서는 인식된 토큰 필드가 없는 POST 양식을 보고하고 표시되는 쿠키 속성을 확인합니다. 교차 사이트 익스플로잇 제출 또는 서버 토큰 유효성 검사 테스트가 없습니다. SameSite, 사용자 정의 헤더 및 워크플로 컨트롤은 수동 검토가 필요합니다.
A01 CORS(교차 원본 리소스 공유) 악용 지표만 CORS 검토에서는 관찰된 허용 원본 및 자격 증명 헤더를 검사합니다. 임의의 원본 반영 테스트나 공격자 원본 데이터 읽기 확인이 없습니다. 자격 증명이 포함된 와일드카드는 브라우저에서 거부됩니다.
A01 리디렉션 열기 액티브 체크 열기 리디렉션을 활성화합니다. Location 헤더에 생성된 .invalid 대상이 반복되어야 합니다. 외부 대상은 추적되지 않습니다. JavaScript 리디렉션, 다단계 로그인 리디렉션 및 모든 URL 정규화 우회는 다루지 않습니다.
A01 테넌트 격리, 역할 에스컬레이션 및 워크플로 권한 부여 보장되지 않음 세션 비교 및 가져온 요청은 분석가에게 증거를 제공할 수 있습니다. 테넌트 소유권, 역할, 상태 전환 또는 허용된 비즈니스 조치에 대한 이해가 없습니다.
A02 보안 헤더 누락, 취약한 CSP 및 클릭재킹 방어 지표만 스캔 중 패시브 헤더 검토는 CSP, 안전하지 않은 평가, 프레이밍 정책 및 관찰된 응답에 대한 nosniff를 확인합니다. 누락된 방어는 신호를 강화합니다. 악용 가능성, 정책 완전성 및 UI 교정 영향이 확립되지 않았습니다.
A02 디렉토리 목록, 소스/구성 노출 및 디버그 추적 지표만 수동적 검토는 반환된 콘텐츠에서 목록 마크업, PHP 소스, 구성 키 할당 및 선택된 스택 추적을 인식합니다. 관찰된 내용과 서명만; 포괄적인 백업 파일, 비밀 또는 숨겨진 관리자 검색이 없습니다.
A02 XML 외부 엔터티 삽입(XXE) 선택적 검증 적극적인 승인을 통해 XXE 및 수신 OAST 공급자를 활성화합니다. XML 요청 본문은 외부 엔터티 콜백 카나리아로 대체됩니다. 인벤토리에 포함된 XML 요청이 필요합니다. 포괄적인 파서, SOAP, 파일 읽기, 매개변수 엔터티 또는 블라인드 추출 범위가 없습니다.
A02 위험한 HTTP 메소드 지표만 광고된 HTTP 메서드를 활성화합니다. OPTIONS는 Allow 응답 헤더를 기록합니다. 승인되지 않은 PUT/DELETE 쓰기를 시도하지 않으며 광고된 방법이 악용될 수 있음을 증명하지 않습니다.
A02 중복 쿼리 매개변수 처리 지표만 반복되는 첫 번째/마지막 순서 응답 비교를 위해 중복 쿼리 매개변수 처리를 활성화합니다. 구문 분석 차이는 WAF 우회, 액세스 제어 실패 또는 프록시/백엔드 불일치를 입증하지 않습니다.
A02 클라우드 권한, 숨겨진 관리 서비스 및 백엔드 구성 보장되지 않음 스택 지문과 토폴로지 보기는 브라우저에 표시되는 가설을 제공합니다. 클라우드 계정 액세스, 인프라 감사, 서버 구성 검사 또는 철저한 내부 네트워크 검색이 없습니다.
A03 알려진 취약한 브라우저 JavaScript 종속성 선택적 검증 클라이언트 라이브러리 SCA를 활성화하여 관찰된 자산 버전을 소규모 번들 자문 데이터베이스와 비교할 수 있습니다. 버전/서명 상관 관계만; 백포트, 연결 가능한 취약한 코드, 전체 종속성 트리 및 보이지 않는 자산은 확인되지 않습니다.
A03 서버 종속성 CVE 및 제품 취약점 템플릿에 따라 다름 CVE 자동 단계에는 적합한 가져온 템플릿이 필요합니다. 작성된 요청과 일치자만 실행됩니다. Native Nuclei는 별도의 엔진과 승인이 필요합니다. 지문/자문 일치만으로도 후보가 됩니다. 두 개의 번들로 제공되는 커뮤니티 스타터는 범용 CVE 적용 범위를 제공하지 않습니다.
A03 손상된 패키지, CI/CD 및 악성 공급망 업데이트 보장되지 않음 종속성 이름 또는 버전은 별도의 코드 및 빌드 검토를 지원할 수 있습니다. SBOM 완전성, 저장소/빌드 감사, 패키지 신뢰성 또는 서명 체인 확인이 없습니다.
A04 HTTP 비밀번호 형식, HSTS 및 안전하지 않은 리소스 참조 지표만 수동 검사는 HSTS가 없는 HTTP/GET 및 HTTPS 마크업에서 참조하는 선택된 HTTP 리소스를 사용하여 비밀번호 형식을 인식합니다. 포괄적인 민감한 데이터 검색이 아닙니다. 미사용 데이터 노출을 증명하거나 모든 전송 동작을 평가하지 않습니다.
A04 약한 TLS 프로토콜/암호, 키 관리 및 저장 암호화 보장되지 않음 브라우저는 일반 TLS 연결을 제공합니다. 암호/프로토콜 열거, 인증서 목록, 암호화 설계 검토, 암호 해시 감사 또는 서버 측 키 액세스가 없습니다.
A06 비즈니스 로직, 결제/가격 조작 및 워크플로 남용 보장되지 않음 관찰된 요청과 반복기는 수동 테스트를 지원합니다. 정확한 가격, 계정 잔액, 비즈니스 규칙, 거래 순서 또는 의도된 응용 프로그램 동작에 대한 모델이 없습니다.
A06 경쟁 조건 및 자원 고갈 설계 결함 보장되지 않음 요청 제한 및 속도 제어 바운드 스캔; 속도 제한 응답은 작동 신호입니다. 동기화된 레이스 하네스나 고의적인 서비스 거부 확인이 없습니다.
A07 약한 쿠키/세션 속성 지표만 쿠키 검토에서는 Secure, HttpOnly 또는 명시적인 SameSite 및 Secure가 없는 SameSite=None이 누락되었다고 보고합니다. 쿠키 목적과 브라우저 기본값이 중요합니다. 세션 하이재킹, 고정, 로그아웃 무효화 또는 토큰 엔트로피를 설정하지 않습니다.
A07 로그인 우회, MFA, 비밀번호 재설정, 무차별 대입 및 계정 탈취 보장되지 않음 주입 검사를 통해 로그인 결함의 한 가지 원인이 드러날 수 있습니다. 세션 유효성 검사기는 구성된 로그인이 여전히 유효한지 확인합니다. 일반 자격 증명 공격, MFA/재설정 워크플로 테스트, 잠금 감사 또는 계정 탈취 확인이 없습니다.
A07 JWT, OAuth, OIDC 및 SAML 확인 결함 보장되지 않음 유틸리티는 수동 검사를 위해 JWT를 로컬로 디코딩할 수 있습니다. 디코딩은 서명 확인이 아닙니다. 일반적인 알고리즘 혼동, 토큰 위조, 리디렉션 흐름 또는 연합 테스트가 없습니다.
A08 Log4Shell 콜백 경로 선택적 검증 승인을 통해 Log4Shell 및 OAST를 활성화합니다. JNDI 콜백 카나리아는 사용 가능한 첫 번째 입력 및 X-Api-Version에 배치됩니다. 일치하는 상호작용에는 귀속 및 검토가 필요합니다. 코드 실행을 증명하지는 않습니다. 제한된 삽입 지점과 대상 출구로 인해 취약한 경로가 누락될 수 있습니다.
A08 안전하지 않은 역직렬화 템플릿에 따라 다름 역직렬화 옵션은 역직렬화 태그가 지정된 적합한 가져온 템플릿을 선택합니다. 실행자와 필수 구성 요소를 검토합니다. 일반 개체 형식 검색, 가젯 체인 생성기 또는 범용 역직렬화 검증 도구가 없습니다.
A08 서명되지 않은 업데이트, 위조된 애플리케이션 데이터 및 무결성 제어 보장되지 않음 캡처된 응답과 디코딩된 데이터는 수동 분석에 도움이 될 수 있습니다. 응용 프로그램 신뢰 모델, 업데이트 서명 확인, 데이터 서명 감사 또는 일반 대량 할당 확인이 없습니다.
A09 누락된 보안 로그, 경고, 로그 무결성 및 사고 감지 보장되지 않음 Longshot은 자체 스캔 증거와 로컬 요청 저널을 기록합니다. 스캐너 로그는 애플리케이션이 올바르게 기록하거나 경고하는지 여부를 나타내지 않습니다. 서버/SIEM 증거를 검사하고 모니터링된 시나리오를 실행합니다.
A10 예외적인 응답으로 인한 정보 유출 지표만 수동적 오류 공개 및 능동적 주입 제어는 선택된 스택 추적과 새로 발생한 데이터베이스 오류를 확인할 수 있습니다. 증거만 반환했습니다. 일반 오류 또는 HTTP 500만으로는 확인된 취약점이 아닙니다.
A10 페일오픈 동작, 롤백 실패 및 안전하지 않은 예외 복구 보장되지 않음 상태/신체 차이로 인해 수동 조사가 이루어질 수 있습니다. 일반 오류 주입, 트랜잭션 롤백 어설션, 충돌 복구 또는 예외 경로 액세스 제어 모델이 없습니다.
기타 HTTP 요청 밀수, 잘못된 프레이밍, 캐시 중독 및 호스트 공격 보장되지 않음 내장된 스캐너는 브라우저 네트워킹을 사용하고 관리되는 헤더를 보호합니다. 기본 프록시를 통한 외부 도구는 별개입니다. 구문 분석된 HTTP 전송은 바이트 투명 밀수 또는 사용자 정의 TLS 엔진도 아닙니다.
기타 WebSocket/SSE 애플리케이션 취약점 지표만 선택적 제한된 채널 테스트는 교환을 캡처하고 선택한 오류 텍스트를 보고합니다. 프로토콜 인식 인증, 메시지 스키마 퍼징, 사이트 간 WebSocket 하이재킹 또는 비즈니스 로직 검증 기능이 없습니다.
기타 파일 업로드, GraphQL/SOAP 로직 및 지원되지 않는 바이너리 프로토콜 보장되지 않음 검색된 HTTP 요청은 일반 검사를 위해 지원되는 스칼라 입력을 노출할 수 있습니다. 전용 업로드 실행, GraphQL 인증/복잡성, 포괄적인 SOAP 또는 바이너리 프로토콜 스캐너가 없습니다.

실제 실행 범위 해석

전체 WSTG 참조 맵에는 자동화된 하위 집합, 지원 작업 및 수동 평가가 포함됩니다. 에서 실제 입력 범위:

  • 완료됨 입력이 안전하다는 의미가 아니라 해당 입력에 대해 구현된 규칙이 완료되었음을 의미합니다.
  • 부분 일부 작업이 실행되었지만 제한, 중단 또는 기타 조건으로 인해 완료되지 않았음을 의미합니다.
  • 건너뛰었습니다. 규칙/입력이 실행되지 않았음을 의미합니다. 이유를 조사해보세요.
