Longshot privacy and data handling

Publisher display name: Longshot Security. Applies to the Firefox and Chrome editions of Longshot. Longshot is a workbench for authorized web security assessment. It does not contain developer analytics, advertising or a developer-operated scan upload service. No developer account is required by the extension.

Data used

After you connect a target, Longshot processes its address, page content, discovered endpoints, HTTP metadata, supported scanner request/response bodies, findings and review notes. The connected browser tab supplies the assessment's session. Browser Bridge can additionally read applicable cookie values, including HttpOnly cookies, and explicitly selected observed authentication/header values from the paired tab's cookie store. These values enable authenticated requests by your local tools.

Assessment evidence, target profiles and preferences are stored locally in extension storage/IndexedDB. Optional retained responses can contain application information despite best-effort redaction. Optional exported reports/session files are written or downloaded where you choose and are not encrypted by Longshot. The local browser cookie jar is separate from an assessment export.

Where data goes

  • Browser scanning sends your selected test requests to the connected target under the configured scope and limits. Opening live target pages loads their normal resources through the browser.
  • Browser Bridge is optional. Pairing explicitly connects a separately started local native adapter. Applicable cookies and opted-in headers are sent to that authenticated loopback helper to form outgoing tool requests. Response cookie synchronization is enabled by default and can be independently disabled. Target traffic then follows the adapter's configured direct/upstream/SOCKS route. External tools can keep their own histories; inspect their settings before use.
  • Agent API/native messaging is optional and requires separate native-host installation and connection. It allows authenticated local clients, including your agents, to operate the workbench, receive results and use explicitly configured session-file/native-template features. Full UI automation can operate the approval dialog. Treat access to those local interfaces as privileged.
  • OAST is optional and contacts the provider you configure. Registration/polling, callback correlation and target-triggered interactions can disclose connection/IP and probe metadata to that provider. The provider has its own policy. A callback domain or provider token is not sent to a Longshot developer service.
  • Update GitHub lists is an explicit action fetching the fixed public payload/template sources with cookies omitted. Target URLs, response bodies, cookies and uploaded custom packs are not sent to GitHub by that action.
  • Online CVE lookup is an explicit action querying NVD/OSV with supported product/package coordinates. It does not send target URLs, pages or session cookies; the provider receives the software coordinates and ordinary connection metadata.
  • Report/session/theme exports occur only through the corresponding user or authenticated automation action. Sharing those files is your decision.

Browser data is used/transferred solely for the disclosed security-assessment features, under the Chrome Web Store User Data Policy including Limited Use requirements. There is no sale of assessment data or use for advertising, credit, unrelated profiling or developer model training. Bundled UI translations do not call an online translator at runtime. Optional local-model/MCP clients are configured independently and have their own data handling.

Control and retention

Use Settings → Clear scan data to clear the active profile's scan evidence. Manage profiles and imported material through the workbench; removing the extension removes its browser-owned extension storage. Delete exported reports, native audit directories, CA keys and optional session files separately where they were saved. No developer retention period exists because Longshot does not operate an assessment upload backend.

The proxy request-cookie override, response-cookie synchronization and header sourcing are separate controls. Disabling one is not a promise that another integration stops. Stop/disconnect the relevant local helper and remove its native registration if you no longer want it available. Revoking browser permissions can disable dependent features.

Chrome scans/native pairing run while the user-visible workbench remains open. Closing it ends live engine work; persisted evidence remains. Firefox uses its declared persistent background page. The Chrome edition does not permit incognito operation in this release; Firefox private/container contexts are used only when selected and browser access permits them.

Permissions

Host access, tabs and script injection support connecting an arbitrary authorized target and inspecting/testing its pages. webRequest observes the scoped tab's HTTP metadata; it is not used for developer browsing-history analytics. Cookies support the paired native session feature. Storage retains local evidence/preferences. Notifications report assessment attention. Native messaging is optional for the separately installed Agent API host. Firefox's optional blocking permission supports its explicit interceptor/live-DOM guards; it is not requested by Chrome.

Local helpers use authentication/origin checks and loopback listeners, but can process session secrets in memory. Cookie sharing does not guarantee browser-identical TLS/IP routing, WAF acceptance or automatically safe imported programs. Review integrations, authored payloads/templates and intended targets before enabling them.
